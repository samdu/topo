# The guest

Claude Code on the phone: the Alpine userland iSH runs inside the app, the loopback proxy that is its only way out, the one resident process, and the bridge that makes it the chat's brain. What the guest may reach is decided at its holes (`docs/design.md`); the invariants are in CLAUDE.md's *Where the risk lives* (the resident process, the bridge, the holes, the token and the proxy).

## The userland

The guest is an arm64 Alpine userland run inside the app's own process by iSH's kernel: `Packages/TopoUserland`, linked into the iOS target alone. Its C side is `TopoIsh.xcframework` (iOS device and arm64 simulator slices, gitignored under `Packages/TopoUserland/Frameworks/`), which `scripts/build-ish.sh` builds from `OpenMinis/ish-arm64` at its pin with meson `guest_arch=arm64`, `kernel=ish`, `engine=asbestos` and exactly the patches in `patches/ish/` — the memory brake's refresh hook (`ish_mem_refresh_hook`, `kernel/mmap.c`: on a sample older than two seconds the kernel asks the app for a fresh one before it fails closed), `pidfd_open` on a child that has exited and not been reaped (`kernel/pidfd.c`: it opens and reads as exited, as on Linux, rather than failing `ESRCH`; Claude Code's runtime opens a pidfd on every child it spawns, and its `ESRCH` path registers fd 0 with its own epoll, so its stdin reader's registration fails and it exits 0 having read nothing), the guest's own `mount(2)` refused `EPERM` for `real` (`fs/mount.c`: the guest runs as root, and a realfs mount made from inside is a bind mount of any path the app's sandbox can open, so what the guest reaches is what the app mounts — `topo_ish_mount` calls `do_mount` and is not this path — while `proc`, `devpts` and `tmpfs` stay mountable), and the `offsets` source meson leaves out of the fork's own executable — linking the fork's libraries, its fakefs importer and `deps/libarchive` (built with no crypto library and no XML reader); `deps/linux` is never fetched and `deps/libapps` never linked. The script refuses a checkout that is not the pin, a patch that does not apply cleanly (`git apply --check`), a populated `deps/linux`, and a meson configuration read back that is not those three options, and skips when the framework's inputs stamp matches the pin, the options, the patches, the glue and the script itself; `scripts/tests/build-ish-test.sh` holds each refusal red, and the PR check builds the framework before any `xcodebuild` and asserts both slices export `ish_mem_refresh_hook`.

The glue is `Packages/TopoUserland/Guest/topo_ish.c` behind `topo_ish.h`: import, combining the rootfs and Alpine packages into one archive for it, boot, spawn (stdin from `/dev/null`, or a pipe whose write end the app keeps, `F_SETNOSIGPIPE`, so a write to a program that has gone is `EPIPE` and never a signal), wait, signalling every guest task but init under the pid table's lock, counting what of a list of pids still runs (reaping, as init, those orphaned to it, which init never reaps), a line about one task for a log (its name, thread and parent, whether it is running, exiting or a zombie, the last syscall it entered, a pending `SIGKILL`), a realfs bind mount of a host directory, a mount of the memory's folder through the vault's own filesystem, the unmount of either, a link in the fakefs, and the brake's feed, compiled into the framework. The vault's filesystem is `Guest/topo_vaultfs.m`, the fork's realfs with the file coordination the fork's `app/iOSFS.m` puts around it (that file is the fork's app, which its meson build does not make): an open of a regular file for reading is a coordinated read, released once the file is open, so it waits for any writer and has iCloud Drive bring an evicted file down first; an open for writing is a coordinated write held until the file closes, so the mirror never reads half a note the guest is writing; a rename, removal or creation is a coordinated write; stat, readdir, readlink and utime are realfs's own, since a coordinated stat of an evicted file is a download of every file a listing touches. Each wait is on a queue of its own, holds no lock of the kernel's, is bounded at `TOPO_ISH_VAULT_WAIT_SECONDS` (20 s, the mirror's own bound on a download; then `EIO`) and is looked at every 100 ms for a SIGKILL to the waiting task (then `EINTR`), since a host semaphore is nothing the kernel's signal wakes. `.topo` at the mount's root, the mirror's baseline, is refused `EACCES` to every operation. Unlike realfs, its unmount closes the folder's descriptor.

A task is started with `SIGUSR1` unblocked on the starting thread: every task thread, and every thread it forks, inherits that thread's mask, a GCD worker blocks `SIGUSR1`, and `SIGUSR1` is how iSH interrupts a task parked in a host call, so with it blocked no signal, `SIGKILL` included, reaches a `sleep` or a blocked read. A second `SIGKILL` to a task that already has one pending wakes its thread again, since iSH queues a pending signal without waking and its one wake is lost if it lands between the syscall's check and a host `nanosleep`.

`Guest` boots one kernel per process on a fakefs — init never runs a program, since init exiting halts the process — refuses every boot after the first whatever it answered, names the guest `topo` rather than letting the kernel copy the host's name into its 65-byte field, and runs a program as init's child over host pipes, returning its output and its exit status (128 plus the signal for a signal), in `Guest.environment` unless it is handed another: root's home, the usual path, `SHELL=/bin/bash` (what Claude Code's Bash tool runs in, inherited by the resident and everything it starts) and `DISABLE_AUTOUPDATER=1`. The app's side of the brake is `MemorySampler`, started by the boot: `os_proc_available_memory` every 250 ms and on memory pressure, and the refresh hook.

The root is Alpine's `alpine-minirootfs-3.22.6-aarch64.tar.gz`, one more entry of the model manifest with its own source URL (`url` beside the path, where the Hugging Face entries carry `repo` and `revision`), fetched by `ModelDownloads` on every foreground until it is imported (`Apps/Topo/Userland.swift`, through `DownloadSource`, which settles once with the entry's files and their pins or the fetch's failure: a failure is `Userland`'s `failed` and what `ready()` throws, and the next `prepare` fetches afresh) and never in the bundle. bash is laid in beside it from Alpine's own packages for v3.22 aarch64, pinned the same way as the entry `alpine-bash` (`url` is the branch's `main` repository, and the files are `bash`, `readline`, `libncursesw` and `ncurses-terminfo-base`, which is what `apk add bash` pulls on top of the minirootfs; `scripts/model-manifest.sh` checks each against the repository's APKINDEX, its version and size, and the set closed over its dependencies at the versions they require, which `scripts/tests/model-manifest-test.sh` holds; the PR check runs `--check`, so a manifest that is not the script's output fails), fetched on the same cue, and no `apk` runs in the guest.

`RootfsInstaller` checks the tarball and every package against the manifest's size and sha256 before the importer is called, and imports them together into `Userland/alpine.importing` under Application Support with the fork's own importer (`fakefs_import`, which keeps modes, owners and device nodes in `meta.db`): since it makes a fakefs from one archive, `topo_ish_combine` first writes one uncompressed tarball beside the staging directory — every entry of the rootfs, then each package's entries in the manifest's order, headers as the archives carry them, less each package's control entries (the dot-names at its root: `.PKGINFO`, `.SIGN.*`, the install scripts, `.trigger`), so no package script runs — and that archive is what is imported, and removed. Once the import has finished a completion marker, `topo-userland`, listing each layer's digest and name, is written inside the staging directory (beside `meta.db`, outside the guest's `data/`), and the directory is renamed to `Userland/alpine` with it — beside `Models/`, never in it, since `ModelStore.sweep` removes what under `Models/` is not a manifest home, while the tarball's and the packages' own homes, `Models/alpine-minirootfs` and `Models/alpine-bash`, are — so the marker being in `Userland/alpine` is the fakefs being whole. A staging directory or combined archive found at the start is an import a killed process left, and is discarded; a `Userland/alpine` without the marker is imported afresh and replaced once the new one is whole, never patched in place. A fakefs with the marker is kept, so a bump of the rootfs or a package reaches a phone that already has one only when that fakefs is taken away.

Claude Code is a third kind of entry, pinned by `version` beside its `url`: Anthropic's `linux-arm64-musl` build from the release distribution the official installer reads (`downloads.claude.ai/claude-code-releases/<version>/`, its size and checksum from that release's `manifest.json`, which `scripts/model-manifest.sh` checks), fetched into `Models/claude-code` on the same foreground cue and never in the bundle. It is never copied: `ClaudeCodeInstaller` (`Packages/TopoUserland`) checks the binary against the pin's size and sha256 on every install — the digest of 227 MB is what a launch pays in place of a copy, and the debug launch prints how long it took — and only then makes it executable (the guest sees the host's mode bits, and its kernel refuses to exec a file nobody may execute), bind-mounts its home at `/opt/claude-code` and links `/usr/local/bin/claude` to the file there; a binary that fails the check is mounted by nothing and made not executable, so no mount already standing can run it. A bump is a new pin: the downloader replaces the file in its home, and the next install checks, mounts and runs the new one. Its own updater stays off (`DISABLE_AUTOUPDATER=1`), since the updater speaks TLS through a library whose handshake never completes under the emulator; nothing in a user build starts it. The diagnostics `userland` row has a clause for each download — the rootfs's and bash's downloader states, then the two importing together, then ready; Claude Code's downloader state, then downloaded at its version — so it says which of the three a guest is waiting on.

The fork is GPL-3.0 under its holders' App Store waiver, which stands while the app meets the GPL otherwise, so the iOS bundle carries the licence's text (the repository's `LICENSE`) and the About screen shows it beside where the corresponding source is (`Licence` in `Apps/Client/AboutView.swift`): this repository at the commit `scripts/archive-upload.sh` writes into the Info.plist as `TopoSourceCommit` — refusing a tree with uncommitted changes or a commit on no remote branch — and the fork at its pin; `scripts/check-built-plist.sh` fails a product with no `LICENSE`.

The guest is booted once per process (`Userland.bootGuest`) by the chat's brain, once both downloads are resident (`ResidentConversation`, below), or by a debug launch with `TOPO_DEBUG_USERLAND=<command>` or `TOPO_DEBUG_GUEST_TURN`. The first (`DebugRun.userland`) waits for both downloads, mounts Claude Code, starts the API proxy and runs the command under `/bin/sh -c` with `ANTHROPIC_BASE_URL` and `CLAUDE_CODE_OAUTH_TOKEN` in its environment (`DebugRun.handOver`), and printing `[topo-debug] guest: <line>` and `[topo-debug] guest exit: <status>`, which `scripts/simulator-run.sh --userland` asserts on (`docs/simulator.md`).

Its suites are two unhosted bundles in the `Topo` scheme's test action, both given the tarball in `TEST_RUNNER_TOPO_USERLAND_ROOTFS`, a directory of the bash packages in `TEST_RUNNER_TOPO_USERLAND_SHELL` and Claude Code in `TEST_RUNNER_TOPO_USERLAND_CLAUDE` (`scripts/fetch-pinned.sh <id> <directory>`), a missing one being a `missing coverage` skip that `scripts/ci-require-tests.sh` fails: `TopoUserlandTests` (the installer against a counting importer — a package off its pin never imported, a staging directory discarded even with its marker, a fakefs with no marker imported afresh — the real combined import, boot, run, `/bin/bash` running in the guest and reached through `$SHELL`, exit status, the refused second boot, Claude Code's installer against a counting guest and in the real one — a wrong digest that cannot run, a bump, a relaunch that copies nothing, the updater off — and the pinned binary's own `claude --version`; the guest's own mount of a host directory refused; the memory's folder (`GuestVaultMountTests`: a read and a write through it, an open waiting for a coordinated writer, a guest write holding its coordination until it closes, an open failing at the bound and printing nothing, a task parked in a coordination ended and confirmed inside the teardown's bound, a parked open stalling no other guest task, `.topo` refused and left byte-identical by an emptying of the vault, a mount made again reaching the new folder, an unmount refused while a guest file holds it, and a write through the home's link landing in the vault); a spawned `cat` echoing each line while it runs, a write to a program that has gone refused, and a tree of four ended and confirmed; `pidfd_open` on a zombie, a reaped and a live child, from a static program built from `Tests/Programs/pidfd.c`; the stream-json parser over the recorded fixtures in `Tests/StreamJSON/`; and `GuestSession` and `GuestLifecycle` over a scripted process and a manual clock) and `TopoUserlandBrakeTests`, a process of its own because a feed puts the kernel in footprint mode for the life of the process and a simulator has no jetsam line for the production sampler to renew from.

## The API proxy

The guest reaches the API through `Packages/TopoProxy`, linked into the iOS target alone, since TLS under the emulator does not work: `APIProxy`, an `NWListener` bound to `127.0.0.1` at a port picked at start (`requiredLocalEndpoint`, so no other interface and no LAN peer reaches it), plain HTTP/1.1 in and every path and query forwarded to the one upstream, `URLSessionUpstream` — `https://api.anthropic.com` over TLS, redirects refused by the session delegate so the 3xx itself goes back, no cookies, no cache, and a target that would name any other scheme, host or port refused. The guest holds its own credential (`CLAUDE_CODE_OAUTH_TOKEN`, handed over only in the environment of the process the app starts) and the proxy passes `Authorization` through unchanged, adds none, and logs method, path, status and time and never a header value.

Inbound it keeps the connection alive across requests, reads bodies framed by `Content-Length` or chunked (both at once, or any other transfer coding, is refused), answers `Expect: 100-continue`, and parses each head with CFNetwork's `CFHTTPMessage` (the target taken from the request line as written, since `CFHTTPMessage` resolves its URL against `Host`); the chunked decoder and the reader over `NWConnection` are its own. The request body is read whole; the response is streamed back chunked as the data delegate hands each piece over, hop-by-hop headers and the `Content-Encoding` URLSession has already undone taken out. An upstream failure before the response head is an Anthropic-shaped 502; one after it cannot change the status, so the response ends incomplete: no terminating chunk, and the connection closed. A target carrying a fragment is not origin-form and is refused. The connection is read continuously, so a client that goes away mid-response cancels its task, and that ends the upstream request through the body stream's termination.

In a debug build the `model` of every `POST /v1/messages` body is rewritten to `APIProxy.pinnedModel` (Haiku 4.5) before it is forwarded, and a body it cannot read as a JSON object is refused rather than sent unpinned. `swift test` in the package runs its suite offline: a scripted `Upstream` for the proxy, and local stub origins over loopback for `URLSessionUpstream`. `GuestResident` starts it with the guest.

## The resident process

Claude Code runs in the guest as one resident process, and it is what answers the chat. `GuestProcess` (`Packages/TopoUserland/Sources/TopoUserland/GuestProcess.swift`, from `Guest.spawn`) is a guest program with stdin a pipe, stdout an `AsyncStream` of lines as they arrive, a 16 KB tail of stderr, and `terminate(within:)`, which `SIGKILL`s every guest task but init — the guest runs the one program and what it starts, and a descendant orphaned to init mid-teardown is reached by no parent link — kills again whatever of it is still running (and anything started since), and answers once the process is reaped, no descendant is running, both pipes are closed and every walk of the tree was made whole — or at the bound, saying which did not happen, how long it took and one line about each task still there; every blocking read, write and wait is on a queue of its own, never the cooperative pool.

`StreamJSON` is the parser, a pure function from one stdout line to typed events (the session and model from each `system/init`, text, a tool call by name, with the file for a tool that writes one (Write, Edit, MultiEdit, NotebookEdit: `StreamJSON.fileTools`), a tool's result with its text and whether it was an error, a thinking block, usage with the context as input plus both cache counts, the result, anything else named `type/subtype`, and a line that is not an event kept as malformed), and the writer of a turn as one line.

`GuestSession` is the actor that owns the resident `claude -p --input-format stream-json --output-format stream-json --verbose` (`ClaudeLauncher`: `sh -c` moves into the home and `exec`s Claude Code, so the pid held is Claude Code's; permissions bypassed, `--dangerously-skip-permissions` with `IS_SANDBOX=1`, which Claude Code needs to bypass as root and the guest runs everything as root, because the guest is the sandbox and what the mind can reach is the holes poked in it — the mounts, the proxy — never a prompt inside it (`docs/design.md`); the environment is the guest's with `HOME` at `/home/topo`, a bind mount of `Documents/home`, and the proxy's base URL and the guest's token read at each launch; the memory told to it with `--append-system-prompt` (`ClaudeLauncher.memoryPrompt`: where the vault is and how to write in it when it is mounted, that nothing written there is kept when it is not — an argument, so nothing the resident starts inherits it); and `--model` the session's current model, which `use(model:)` replaces by ending an idle process and starting one on the new model, resuming, and by doing that once the turn in flight ends when one is).

One turn at a time — a second send is refused, and so is a send with nothing resident; a send to a process started on a model or conversation the session no longer says replaces it first, and one to a process being replaced waits for the replacement, so no turn rides the old model — and its updates are the events then how it ended: answered, failed (an error result, which keeps the process; the process exiting, with its stderr; silence past the turn's bound, 180 s from the last line; a write that failed) or abandoned. Every failure but an error result ends the process and starts another, resuming, and nothing the old one says afterwards reaches anybody; a turn is never sent twice. A turn is sent with a uuid (`send(_:id:)`, the stream-json line's `uuid`), which Claude Code keeps as its transcript entry's.

The session to resume is the one the last `system/init` named, kept in `Documents/.guest-session`; a resume that exits before it begins anything clears it and starts a fresh session, and says so in the log; `forgetSession()` (sign-out) clears it, makes the next process fresh and ends the resident process at once, abandoning a turn in flight rather than waiting for it as a change of model does, since the process holds the login that went (its token in its environment) and a turn left running would run its tools and write that session's transcript for nobody; a process started before it never writes the session it names back (`keep` is gated on the conversation the process was started under).

`GuestLifecycle` carries the app's lifecycle to it, each foreground and background a generation the session admits only if it is the newest, so a start or a teardown still pending never acts on the wrong process: the foreground starts the process (or keeps it, when the app is back before the teardown began); `DidEnterBackground` begins a background task, reads `backgroundTimeRemaining` a second later (it is infinite inside the notification), and gives a turn in flight the grant less the 5 s the expiration handler fires with and the 8 s kept for the teardown (`GraceBudget`; 28 s is assumed when the reading is not a grant), then ends the process — at once when no turn is in flight, abandoning a turn still running at that point — with 7 s for the termination to be confirmed, and ends the task when the termination answers: confirmed, or at that bound unconfirmed, logged as `NOT confirmed` with each task still there. The task is not held past the bound, since holding it past the grace gets the app killed. The expiration handler does not end the task itself: it asks the session to expire — a teardown waiting on a turn stops waiting and ends the process, and a termination begun from then on has 4 s — and holds the task, which is ended when the teardown answers, or 4.5 s after the handler with the teardown still running and `background: background time ran out…` logged.

The memory's folder is mounted at `/memory` (`ClaudeLauncher.vault`) and linked from the home as `/home/topo/memory` (`ClaudeLauncher.memory`), so it is `memory/` from the resident's working directory. Beside the home rather than inside it, because the fork's mount lookup keeps the last mount it found per thread and answers a path under a mount nested in that one with the outer mount, which would put a note in the home's own folder under the link's name. `VaultMount` (`Apps/Client/VaultMount.swift`) keeps it in line with the home `Memory` names (`GuestResident.memory`, set by `TopoApp`): `reconcile` is asked at every launch of the resident (its answer is what the launch tells the resident) and before every turn (`ResidentConversation.ready`), and compares the folder by its device and inode, not its path, since a folder removed and made again at the same path is another folder and a mount's descriptor is on the old one. The local home's folder is made when it is not there yet; an iCloud Drive home is mounted from the vault folder, with access started on the URL the grant is on and held for as long as the mount stands; a lost home, or a vault folder that is not there, mounts nothing. A mount that has to go and cannot, because something in the guest holds it, refuses the turn as not ready with that reason, before the guest receives anything. Sign-out, after the resident has been ended, takes the mount away and then stops the access; a mount a teardown that did not confirm still holds is marked stale, its access stopped, and taken away at the next reconcile.

`GuestResident` (`Apps/Topo/GuestResident.swift`) puts these together over the app's notifications; a start of it that fails (the proxy not binding, a mount refused) is not kept (`StartOnce`), so the next turn's start tries again from the step that failed, while the kernel's own boot stays once per process.

A debug launch with `TOPO_DEBUG_GUEST_TURN=<turn> || <turn>` (`DebugRun.guestTurn`, refused beside `TOPO_DEBUG_USERLAND`, since the resident's end ends every guest task) sends the turns one after another to the one resident process and prints each turn's model, session, the resident process's guest pid, tool calls and each one's result (`tool result: <tool>: ok|error: <text>`, paired with the calls in the order they were made, on one line, cut at 300 characters, any `sk-ant-` key, `Bearer` value or token variable redacted), each pose Topo takes on the glass, reply and wall time as `[topo-debug] guest turn N …`, the session's log (the start, a resume, each teardown and its termination) as `[topo-debug] guest: …`, and `guest turn done`; `scripts/simulator-run.sh --guest-turn` asserts on those (`docs/simulator.md`).

## The bridge

The chat's brain is `GuestBridge` (`Apps/Client/GuestBridge.swift`), a `Brain` over a `GuestConversation`: in the app `ResidentConversation` (`Apps/Topo/GuestResident.swift`), the one `GuestSession` that `GuestResident` starts, and in the suites `ScriptedGuest` (`Tests/Client/ScriptedGuest.swift`), which writes Claude Code's own transcript format. Until the rootfs and Claude Code are both on the phone nothing starts, and a turn is refused as not ready with the userland's status line: the person's turn stands in the log, the chat shows the line, and the answering loop, which warms the guest on each pass, answers it once the guest is ready.

The guest keeps its own conversation, so it is told only what it has not seen: the person's words, after the turns of the log it was never given (a limb's turn, another primary's reply, a late branch whatever its timestamp) as a block of what happened meanwhile, or, for a session that has seen nothing (the first, or a fresh one after a resume failed), the last `contextLimit` (40) turns as the conversation so far (`GuestBridge.render`). The limit is a fresh session's alone, whose older turns are its history and are counted seen without being told; a session that has seen the log is told every turn it has not seen, however many, and an input covers exactly what it told, what an input the log moved past carried, and the turns it answers.

What it has seen is graph coverage — per-device runs of sequence numbers (`Coverage`), not a point in time — kept in the ledger, `Documents/.guest-bridge.json` (`GuestLedger`), beside the session it belongs to, and advanced only when the reply is in the log (`landed`), and then only over what the guest is known to have received — it answered the input, or read it and was cut off: a reply another device wrote under the nonce, for an input whose fate here is not known, settles the request and counts nothing seen, so those turns go with the next input rather than never; a different session id clears it. No ledger file is an empty ledger; one that cannot be read or decoded is not, since it may record an input the guest received: until it reads, every request is refused with that reason and nothing is sent, nothing is written over it, and each request reads it again, so a ledger unreadable at launch — before the first unlock, say — is read as soon as it can be. Sign-out removes it with the rest.

Before an input is sent the ledger records it (`Pending`: the uuid it carries, the reply's nonce and parents, the turns it answers and covers, the session, the time, and whether it is sent, answered by the guest, or unresolved); an input whose turn ended in an error result is unresolved without reading anything, since Claude Code said it received it and the process, still running, may still be writing its transcript; an answer that stops listening (its task cancelled) with the turn still the guest's concludes nothing and leaves the record as sent; after any other end but an answer, and before any later request, the bridge waits until nothing the guest is doing can still write about an input — no turn in flight, one nobody listens to any more included, and no process being ended (`GuestSession.settle`) — and, when the last process ended was confirmed gone, reads the guest's session transcript under the home for that uuid (`GuestTranscript`, `Packages/TopoUserland`: the input's entry, then the messages up to the next prompt; answered when the last message ended with `end_turn`, `stop_sequence` or `max_tokens`, an error Claude Code wrote in the model's place being no reply), and one pure function decides (`Reconciliation.of`): never received, the record goes and the input is sent; answered, the reply is written under its nonce without asking again — before anything else when the log has moved on from its request (`owed`), and caught up with nothing sent when CloudKit already holds it under that nonce; received with no reply, the turn is unresolved, and a record already known received is never cleared by a later read that does not find the input (a transcript not written yet, or cleared away since); a process not confirmed gone, a transcript that could not be read, or a folder of them under `.claude/projects` that could not be listed (`unreadable`), is no answer at all, so the record stays, nothing is sent and the next request reads again; only no `.claude/projects` at all, or every folder listed and every file that could hold the input read, is not received.

An unresolved turn is never sent again by itself, since it may have run tools: `answerPending` skips it, the chat shows it with an ask-again control under the transcript (`Harness.unfinished`, `Harness.askAgain`), and the person saying something new moves past it: the guest is not told the cut-off turn again, and what it carried counts as seen once the new turn's reply is in the log, with the rest of that input's coverage.

Requests go to the guest one at a time, and a request waiting behind the one that answered its nonce is handed the same words. The bridge reports each turn's start (with the resident's pid), updates and end to `Harness.onGuest` (`GuestActivity`), which is what moves Topo on the glass; a reply is read aloud through `Harness.onReply` as any reply is. The diagnostics screen's `Brain` row says where the guest stands (the userland, the process, its pid and model, how many turns it has seen of which session, a turn with it or cut off) and `Unfinished turn` names the one waiting to be asked again. A failure before the guest received the input is a failed turn the answering loop retries; one after is unresolved; the guest is the only brain, so neither is answered any other way.

Sign-out (`Harness.forget`), and the far end of a takeover (`Harness.demote`, since a viewer holds no login), cancels the turn in flight and the answering pass in flight — each pass is a task of its own for this — ends the answering loop, and forgets the ledger and the guest's session with the login. An answer begun before it — waiting for the guest to be ready, or with its input already with the guest — records nothing, sends nothing and hands no reply to the runner once its wait ends: the bridge checks the login after every wait, before it records an input, before it sends it, once the guest's turn has ended however it ended, and after the transcript is read, and `owed` checks it after its read; and the runner checks its task immediately before the person's turn and each reply it appends, so words from before a sign-out are not written after it either.
