# The log, the lease and the packages

The records every bundle shares and the Swift packages that hold them. The rule over all of it, *CloudKit is truth, sockets are speed*, is in CLAUDE.md; the design behind the log and the memory is `docs/design.md`.

## The records

The transcript is an append-only log: one record per turn, per-device sequence numbers, never overwrite. The role record (`role/<device>`, `DeviceRole`) is how one device changes another's role, written by the taker in the make-primary control; a device reads its own at launch and on each answering pass. The primary lease is the one mutable record: atomic claim, 10s expiry judged on `mach_continuous_time` (`PrimaryLease.continuousUptime`) as well as the wall clock — not `CLOCK_MONOTONIC`, which on Darwin is time-daemon-disciplined and can follow a backward system-time step, the case the fence exists for — 5s heartbeat the holder runs itself, probe-driven handover, a displaced holder yields rather than reclaims, and only the hub takes the lease from a live holder. A turn written as primary rides in one atomic batch with a heartbeat of the lease (`TurnWriter.append(…, renewing:)`), so a displaced device writes nothing; the phone's reply uses it and the hub's turns will. A `Surface` record (`surface-<slot>`) is a phone widget slot's document for the watch, written only by a compare-and-set on the change tag of the read it was made from, in which the later revision of the same `runner` wins and another runner's record is replaced; it is never deleted, since a delete carries no tag, but cleared with a tombstone (`cleared`, no document, no images) when the slot is cleared, the phone that saved it signs out, or the primary sweeps a record another runner saved (`docs/widgets.md`, *The record*); its `updated` field needs to be marked queryable in the development schema for the watch's subscription.

## The packages and their tests

Core logic ships as Swift packages whose tests run against an in-memory database behind the package's own CloudKit protocol; no test needs a signed-in device. `Packages/TopoCore` is the log, the lease, the device directory and the memory (`MemoryStore`, one create-only record per revision; `MemoryVault`, which reads those revisions as files, with the newer head of a forked path the file and every other head a conflict copy under Obsidian Sync's name; and `VaultMirror`, the actor that keeps a directory on disk in step with them both ways): `RecordDatabase` is the protocol over the CloudKit calls used (compare-and-set save, fetch, query, and the whole of a type from the zone's change feed, which is how the log and the device directory are read: a match-all query needs a queryable index on the record name that the development schema never builds), `ZoneDatabase` adds a delete (a record already gone is not an error) and a type's changes from a change token, deletions included, with an expired token answered `tokenExpired` so a reader starts again from the beginning; a field may hold assets (`FieldValue.assets`, a `CKAsset` per file). `CloudKitRecordDatabase` is the adapter to both, and `TopoCoreTesting` holds the in-memory database with CloudKit's conflict semantics.

A read of a whole type (`RecordDatabase.records(ofType:)`) is the zone's change feed, and over CloudKit it is answered from `ZoneMirror` (`Packages/TopoCore/Sources/TopoCore/ZoneMirror.swift`): the process's copy of the zone, every type, with the feed's token after the last page it took. The first read of a launch walks the feed from the beginning; every read after, by whichever object over that zone, asks only from the token and answers from the copy, which is what a walk from the beginning would return at that moment. Reads go one at a time and each asks the feed, so one begun after a save returns it. An expired token is a walk from the beginning. The copy is in memory only. `ZoneMirrorTests` holds it against a feed in memory.

A container nothing has written to answers two more ways, both absorbed by the adapter and both invisible until a fresh account takes its first turn: a query on a record type the development schema has never seen fails `unknownItem` rather than returning nothing (answered `[]`), and an empty string list on a first save makes the server refuse the whole atomic batch with "Syntax error in request" (left off the wire, since a list with no elements has no type the schema can be grown from).

`Packages/TopoLink` is the socket layer: the lease probe over TCP (one line each way), the listener that answers it and advertises the device as `_topo._tcp`, and the browse that says who is on the LAN; its tests run on loopback.

`swift test` from a package directory runs its suite. `TopoTests` drives the phone's `Harness` itself over the in-memory log, with the guest behind a scripted `GuestConversation` (the unsettled line on disk and its relaunch, a failed model call, not-primary and displaced turns, the role-record handover, the answering loop). No automated suite reaches the CloudKit service: `CloudKitMappingTests` covers the adapter's record and error mapping offline, so the account, the schema, partial failures and the zone change feed are exercised only by Womble's manual self-test (`CloudKitSelfTest`) on a signed-in device.
