# Tests and the PR check

Every suite's own description sits with the code it holds (the guest's in `docs/guest.md`, the mascot's in `docs/mascot.md`, the packages' in `docs/cloudkit.md`). Running the app signed in, the microphone press, the audio lane and the talk lane are `docs/simulator.md`.

## The debug launch environment

A simulator is signed in from its launch environment, not by hand: `Apps/Client/DebugRun.swift` (all of it behind `#if DEBUG`) takes a Claude Code setup token from `TOPO_CLAUDE_SETUP_TOKEN` and writes it to the store as a finished sign-in, puts a turn on the harness's line from `TOPO_DEBUG_OUTBOX` (empty clears it) so a launch can be the relaunch that finds one owed, and takes one turn from `TOPO_DEBUG_SEND` through the ordinary harness, waiting first for the guest to be ready (`guest: waiting: …`, then `guest: ready`), printing each step prefixed `[topo-debug]`, each pose Topo takes from the guest's turn (`mascot: turn began for <turn>, process P, …`, `mascot: …`, `mascot: turn gone for <turn>, …`, naming the turns the guest turn answers), and the reply as `reply to <nonce> in run <run> from session <id>, process <pid>: <text>`.

## The PR check

The PR check itself is three macOS jobs at once — the Topo scheme's test action split by test selection into the UI tests (`topo_ui`) and everything else (`topo_unit`), and the scripts' tests, the packages, Womble, the watch's suite (`TopoWatchTests` on a watch simulator from the pinned watchOS runtime, booted and waited on with `simctl bootstatus -b` before the run, its own step bounded at 15 minutes) and the watch, TV, Release and hub builds (`others`; the watch build is read for its widget extension, background mode and URL scheme by `scripts/check-built-plist.sh --watch`) — behind one gate job on ubuntu, `test`, which the merge waits on; the reviewer waits on `topo_unit` and `others` alone and runs beside `topo_ui`. Three of the free plan's five concurrent macOS jobs, so a second PR validating at once queues one job rather than all of it.

A PR runs only the jobs its paths need. The `select` job reads the paths the PR changes against main and matches each against `SUITE_RULES` in the workflow (`scripts/ci-select-suites.sh`, first rule wins): documentation, root markdown, the other workflows, `.claude/`, `.gitignore`, and the TestFlight and plan-review tooling run none of the three; the hub, watch and TV targets, the watch's widget extension and suite, Womble and `TopoLink`, which the app does not compile, and the janitor, whose test runs there, run `others` alone; the app's sources, every package the app links, the tests, the project, the guest patches, the workflow and its scripts, and any path no rule names run all three, as does a diff that cannot be read. The nightly and a dispatched run take all three. A job left out is skipped, and `test` and the reviewer read that skip as a pass only because `select` said `false` for it; the choice and its reason are in `select`'s log and summary. `scripts/tests/ci-select-suites-test.sh` pins the rules and their cases.

Each macOS job restores its build from the last run that saved one (`.github/actions/prepare`, `build-cache`): DerivedData's build products and package checkouts and SwiftPM's cache, keyed on the Xcode build and `Package.resolved`, with `topo_unit` and `topo_ui` sharing one since they build the same products. A PR restores what runs on main saved and its own earlier runs'. Test results are never cached, and whether a restored product is current is Xcode's call: a file the checkout has just written reads as changed and compiles again, so what the cache saves is mostly FluidAudio, the one remote package, fetched and built.
