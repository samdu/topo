# The memory on the phone

The Obsidian vault as a folder on the phone: its two homes, the mirror that keeps it in step with the store, `look.json`, and moving between homes. The store itself (`MemoryStore`, `MemoryVault`, `VaultMirror`) is in `Packages/TopoCore` (`docs/cloudkit.md`); the invariants are in CLAUDE.md's *Where the risk lives* (the mirror, the migration, the look as a document).

The memory is an Obsidian vault, and on the phone it is a folder of markdown with two homes, which `Apps/Client/VaultHome.swift` decides. `<Documents>/Vault` is the one every phone has from the first launch: Files shows it under On My iPhone › Topo and any editor that opens documents in place reads and writes it — Files' own, iA Writer, Textastic; not Obsidian, whose iOS app keeps its vaults in its own folder or in iCloud Drive (`UIFileSharingEnabled` and `LSSupportsOpeningDocumentsInPlace`, declared in `Apps/Topo/Info.plist` through `project.yml`'s `info:` block, because Xcode generates neither from a build setting; `scripts/check-built-plist.sh` reads both off the product).

The other is a folder in iCloud Drive the person picks from the Memory screen (`Apps/Client/MemoryView.swift`, the settings sheet's Memory section, and what the offer card above the composer opens), which Obsidian opens on the phone and iCloud Drive carries to their Macs.

`Apps/Client/Memory.swift` is the app's one `VaultMirror` over the same CloudKit database and device identity the harness uses, and one sync at a time: a request arriving during a pass asks for one more pass after it, however many arrive, since two syncs over one folder would each read what the other was halfway through writing. It runs only while this device holds a login, the condition the harness answers under: a cue reaching a signed-out phone — a foreground after a sign-out, a launch as a viewer — takes away any folder it finds rather than filling one, so a sign-out the app did not live to finish settles at the next cue.

It syncs on every foreground (`TopoApp`, where the models are prepared), at the top of every pass of the answering loop before it looks for a turn to answer and again once a reply is in the log, whoever's turn it answered — a limb's, or one typed here (`Harness.onPass`, installed by the chat) — and on a silent push saying a revision was created (`NotePush`, `TurnPush`'s twin under the id `note-created`, routed by `TopoAppDelegate` to `MemoryWake.handler` by the subscription id it carries; the handler follows the login rather than the chat screen, put up and taken down by `TopoApp` as the login comes and goes, so a signed-in phone that never reached the chat still answers a push). The loop is what makes the folder current with no push and no turn, so a dropped push costs latency and not currency. A failed sync is recorded, retried on the next cue, and touches no disk: the mirror refuses to act on a partial read.

Nothing in the folder is read or written uncoordinated, the mirror's own `.topo/mirror.json` baseline included, and that baseline is written last and only by a pass that got to the end of itself. Every fact about the folder is read where it is acted on, inside the same coordinated write: what is at a name, whether it is a file or a folder, whether a folder is still empty (`rmdir`, which refuses one that is not), and what text a file holds. All of it goes through a descriptor for the folder the file sits in, opened from the vault root with `O_NOFOLLOW_ANY` so no link anywhere on the way down is followed and nothing is resolved again between the look and the write, and the way down is made one name at a time through that descriptor rather than by a path. So an editor's save landing in that window is found and made a revision of rather than flattened, and a file this pass cannot read is neither written over nor read as a deletion. A path only counts as shown the store's heads when its text reached the disk, since a push names as its parent what this folder was actually given. Cancellation is checked before every mutation, the folder's own making included, which is what makes a sign-out mid-sync safe, and it is carried into the coordination by hand because none of it runs on a cooperative thread: `NSFileCoordinator` blocks until every other accessor lets go, and the threads tasks run on are a handful the process shares, so the wait is spent on a queue of the mirror's own with the actor suspended. The package suites run with `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1`, which pins that pool to one thread, so anything that blocks one hangs there rather than on a runner.

Sign-out takes the folder away — the memory is the person's and lives in their iCloud, and a phone that is signed out keeps no copy — and a sync in flight at that moment is cancelled, writes nothing, and the folder goes once it has stopped, so a half-finished pass cannot put a file back.

The diagnostics screen's `memory` row says where the home is, when the folder was last in step and what the last sync did, and names the first few files a pass skipped with the reason it skipped each — a count alone is a device run that has to be repeated to learn anything.

`look.json` in the root is a file of the vault like any other, and the one the app reads for itself: after each pass that reached the end of itself, from the folder the home names, through the mirror's own coordinated read (`VaultMirror.contents(at:)`) and never by opening the folder — after the sync and not during it, since a second coordinated access of one folder held from inside the first is two accessors from one process. It is decoded field by field (`Apps/Shared/LookDocument.swift`): a field absent, misspelt, of the wrong kind or outside the range its field is read in falls back to the compiled default for that field alone, every other override stands, and the reason is on the diagnostics `look` row along with the file's state — no file, the count of fields it set, or why nothing could be read from it. Colours are hex pairs, light then dark, as `Theme` writes them (`Theme.colour(light:dark:)`); materials are named; numbers are points, degrees or seconds, each in a range named where it is read, and what has to be pressed or read is bounded below as well as above. The environment is set from it on every sync, so a document the mind wrote is worn from the next one with no relaunch; a sign-out takes it away with the folder. The watch and the television draw the same transcript from the same look and have no composer, badge, sheet or row, so the transcript's and the bubble's fields are all of it that reaches them.

An empty file is a note with no text in it, not a file that could not be read: `FileHandle.readToEnd` answers nil at the end of a file, which an empty one is from the start, and every note Obsidian has just made is empty.

A debug build launched with `TOPO_DEBUG_LOOP_SECONDS` waits that long between passes instead of five seconds, which is how a device test tells a revision that arrived by push from one the loop would have fetched anyway.

The home is the bookmark, one keychain item beside the tokens, because a bookmark is a capability to the person's files and not a setting: no bookmark is the local home, one that resolves is iCloud Drive, one that does not is `lost` and stops every pass until the person picks again or comes back to the phone. The picker's grant is the whole of the permission story — no entitlement of ours reaches iCloud Drive or Obsidian's container — and what it hands over is judged against this device's own ubiquity root, `<user>/Library/Mobile Documents` read off `NSHomeDirectory()`, rather than against a path component of that name: a vault one level under `iCloud~md~obsidian/Documents` is the pick Obsidian opens, iCloud Drive's own root is a vault made at `Obsidian/<the mind's name>` under it, and anything else is refused with the reason and the home unchanged. The bookmark kept is to what was picked, so a root pick keeps root access, and the vault folder under it is derived by the same rule at every launch. Every access is started and stopped on that URL and never on a child of it, and it is held for the whole pass.

The move (`Apps/Client/VaultMigration.swift` over `VaultTransfer` in TopoCore) is one coordinated write over both folders with one commit point: every file and the `.topo/mirror.json` baseline are copied and read back by digest, the write of the home to the keychain is the commit, and the source is emptied of what was carried only after it — name by name, then the folders left empty, and the folder itself only when it is this app's own, since a folder in the person's iCloud Drive is theirs. What counts as left behind is a file the move carried and could not take away, never a name it skipped on purpose — `.obsidian` was the person's and is not the memory's to account for, still less to remove. A removal that will not finish is said in the Memory screen and the `memory` row, with a control to try again that runs that same cleanup against the same names, under the grant the stranded folder carries rather than the home's (by then the home is the other folder), and is never a rollback. The screen's controls are read against all three homes: picking while the memory already lives in a picked folder moves it out of that one, picking while the home is lost is refused because there is nothing to carry out of a folder that cannot be reached, and a lost home comes back by dropping the bookmark alone — there is nothing to carry, and the folder fills from the store. A sign-out during a move waits the move out before it clears the bookmark and takes the folder away. A file already in the destination keeps its name and the carried one lands beside it under a conflict copy's name (`ConflictCopy`, the rule `MemoryVault` reads a fork with).

An iCloud Drive home has files whose bytes are not on the phone, so each pass asks for what is not downloaded and waits with a bound (`Apps/Client/VaultDownloads.swift`, a regular file whose status is `.notDownloaded` and nothing else: a folder has a downloading status of its own, a file with no status is not a ubiquitous item and asking for one throws, and `.downloaded` is a local copy that is merely out of date); what has not arrived is a file the mirror reports as unreadable and acts on in neither direction.

Sign-out drops the bookmark and takes away the folder in this app's container; a vault the person keeps in their own iCloud Drive is theirs and is left where it is.

The chat shows one card above the composer offering the move, once, when the vault holds more than a handful and the home is still local; Not now is for good, in defaults.
