# Timing a launch and a turn

Where the time goes is read off marks the app writes itself. `Perf.mark(_:)` (`Packages/TopoCore/Sources/TopoCore/Perf.swift`) logs one `notice` line per named moment under subsystem `zone.hexagon.topo`, category `perf`: `mark t=<epoch ms> <name> [detail]`. A mark carries a name and nothing of the person's: no words, no tokens, a request's method, route and byte count at most. The route is the path with every segment that is not one of `Forwarder.routeSegments` replaced by `*`, and no query (`Forwarder.routeForMark`). `turn.reply.shown` is the reply handed to the view, a frame before it is drawn; `resident.spawned` is a launch that succeeded, and one that failed is `resident.launch.failed`.

## The marks

| Path | Marks, in order |
| ---- | ---- |
| Launch | `app.init.begin sinceProcessStart=<ms>`, `app.housekeeping.begin`/`.end`, `app.init.end`, `chat.appear`, `scene.active`, `chat.log.read`, `ear.load.begin`/`.end`, `voice.load.begin`/`.end` |
| Guest start | `guest.boot.begin`, `guest.downloads.present`, `guest.kernel.booted`, `guest.dns.up`, `guest.tmp.zone.done`, `guest.claude.verified`, `guest.tools.ready`, `guest.proxy.up`, `resident.launch.begin fresh\|resume`, `resident.spawned` |
| Turn | `turn.send`, `turn.runner.made`, `turn.begin`, `turn.lease.acquired` and `turn.log.read` (the long way only: the read runs while the lease is taken, so the second is whichever ended later), `log.append.checked`, `lease.batch.lapsed` (a batch found the lease lapsed and reads the record to claim afresh: before a reply's save, or before `turn.lease.fresh` when the lease lapsed while the person's batch waited), `lease.batch.refused <notHeld\|taken>` (why a batch was refused: a reply's as displaced, the person's before the turn goes the long way), `turn.lease.fresh` (the fresh path only, after its save: the person's turn saved in one batch with the lease's renewal or that fresh claim, or on a retry found in the log and the lease heartbeated; no lease taken first), `turn.person.saved`, `lease.heartbeat <held\|lost\|failed> ms=<n>` (the lease's own loop, at any point), `turn.bridge.begin`, `turn.bridge.guestReady`, `turn.guest.write`, `turn.guest.firstLine`, `turn.guest.init`, `turn.text.first` (the first words drawn), `turn.guest.text`, `turn.guest.toolUse`, `turn.guest.result` (each of the turn's own, from its input's echo on; a result of a turn Claude Code ran of its own is `turn.guest.result.other`), `turn.brain.answered`, `turn.reply.saved` (or `turn.reply.failed <kind>`), `turn.reply.shown`, and for a spoken turn `speak.begin`, `speak.firstFrame`, and for each sentence the voice makes `speak.sentence synth=<s> first=<s> audio=<s> words=<n>` (the seconds it took to synthesise, to its first frame, and of audio made, so `synth` over `audio` is the share of the audio's own length the voice took to make it; a sentence that made no audio says `first=-1.00 audio=0.00`; never the sentence's words) |
| Downloads and setup | for each manifest entry a pass enqueues: `download.begin <id> files=<n> resumed=<n> running=<n> bytes=<n>` (tasks made, how many of them from resume data, tasks the session already held, and the size of the entry's files not yet verified; it repeats on a later pass that finds tasks, so the first is the start), `download.firstByte <id>`, `download.verified <id> bytes=<n> ms=<n>` a file (the digest and the move, on the session's one delegate queue, so every other arrival waits behind it), `download.present <id>` or `download.failed <id>`; `guest.import.begin` and `.end` or `.failed` (the rootfs and bash made into the fakefs, off the main thread); and in a timed first run `perf.setup.done s=<n> thermal=<0–3>` or `perf.setup.unfinished <lines>` |
| The guest's requests | `proxy.request <METHOD> <path> bytes=<n>`, `proxy.head … <status>`, `proxy.firstByte`, `proxy.done` |

## A run with nobody at the phone

`scripts/perf-run.sh --device <id> [--build | --app <Topo.app>] "question" ["question" …]` installs a build, launches it cold with `TOPO_PERF_SEND` in its environment, and copies the marks off when the run is done. `PerfRun` (`Apps/Topo/PerfRun.swift`) is what reads the variable: it starts `tmp/topo-perf.log` in the app's container empty, has every mark written there as well as to the log, sends the first question as soon as the scene is up and each next `TOPO_PERF_GAP` seconds (5) after the reply to the last, through the harness's own line (`willSend`, `retry`) as the composer does, and marks `perf.run.done answered=<n>/<m>`. Each `perf.question <i>/<m>` carries `thermal=<0–3>` (`ProcessInfo.thermalState`: nominal, fair, serious, critical), since a phone warmed by earlier runs interprets the guest slower and a run is only comparable with one at the same state. A question counts as answered when its reply is in the transcript, which is waited for up to a minute after its turn ends (a turn saved as a limb's is answered by another device); the run ends at the first question that gets none, and, after the log has been read and any words the launch before left on the line have been sent (`perf.line.waiting`), sends nothing if words are still waiting. A proxy mark names a request by the path segments in `Forwarder.routeSegments` and writes `*` for any other. `TOPO_PERF_SEND` is a JSON array of strings, which the script makes from its arguments. One launch is one run, however many windows it restores. The script polls the file with `devicectl device copy from` until that mark is in it, taking only a file whose first mark is no older than its own launch (a copy can reach the phone before the new process has emptied the last run's file), and exits 4 when fewer questions were answered than asked. A blank question is refused before anything is installed (exit 2).

In a timed run the proxy also marks what each `/v1/messages` request is made of and what the API counted of it: `proxy.shape` (`system=<bytes>:<digest>` a block each, `tools=<count>:<bytes>:<digest>`, `messages=<count>:<bytes>`, `head=<digest>` of the first message, `marks=` each `cache_control` by place, `s`, `t` or `m` and an index, with its `ttl`), `proxy.usage in=… cacheRead=… cacheWrite=…` from the answer's `message_start`, and `proxy.usage.out <tokens>` at its end. A digest that differs between two requests is a part that changed, which is what stops a cached prefix being read. They are made only while a run is being timed, since they parse the request.

With `--spoken` (`TOPO_PERF_SPOKEN=1`) the questions are sent as spoken turns once the voice is resident, their replies are read aloud from the phone, and the next question waits for the reading to end. The run waits up to two minutes for the voice, since a fresh install compiles its model on the first load (`voice.load.begin` to `voice.load.end`, 35–44 s on an iPhone 15 Pro), and marks `perf.voice.unready` if it sends without it.

With `--fresh` (`TOPO_PERF_SETUP=1`) the run is a first run: the script deletes the app from the phone, which takes its container and every download and compiled model with it, then installs (so `--app` or `--build` is required, exit 2 without), and the app waits for every setup line to be done before its first question, up to 50 minutes, marking `perf.setup.done`, `perf.setup.failed <part>` as soon as a line fails (nothing retries it without a foreground), or `perf.setup.unfinished`. A reinstalled phone is a new device to the lease, so it usually opens as a viewer, its kept login dropped: whoever is at the phone makes it the primary ("Make this device the primary…", which demotes the device that was) and signs in if asked. The phone stays unlocked with Topo in front throughout, or the suspended time is inside the timings. The script deletes nothing unless `--app` (or `--build`'s product) is a bundle whose identifier is Topo's, asks the phone whether Topo is installed rather than reading an error's words, and stops when it cannot tell or the delete fails, since a container left behind would make a warm run read as a first one. The script's timeout is an hour unless `--timeout` says. The first-run account is then read off the marks: from `app.init.begin` to each entry's `download.present`, `guest.import.end`, `ear.load.end` and `voice.load.end`.

So one run times a cold launch, a question asked into a cold app, and as many warm turns as there are further questions. The questions are sent as the person and land in their transcript.

`PerfRun` is in a release build because a release build is what is timed. The variable reaches the process only from a launch by `devicectl` or Xcode, from a Mac the phone trusts; an ordinary launch has none.

The phone has to be unlocked: `devicectl` refuses to launch an app on a locked one, and the script exits 3 saying so.

## Without the script

The same marks are in the phone's unified log: `sudo log collect --device-udid <hardware udid> --last 15m --output run.logarchive`, then `log show run.logarchive --predicate 'subsystem == "zone.hexagon.topo" AND category == "perf"' --style compact`. The collect needs the phone awake, no `idevicesyslog` attached to it, and a cable: over Wi-Fi `sudo log collect --device-udid` fails with `Device not configured (6)`, so from buddybox, which has no cable to the phone, the only read is a file the app writes into its own container, copied out with `xcrun devicectl device copy from --domain-type appDataContainer` as `perf-run.sh` does with the marks file.
