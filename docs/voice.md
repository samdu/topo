# Voice

Push to talk, the on-device ear and voice, the audio session and the background hold, and how the models get onto the phone. The invariants a change here must keep are in CLAUDE.md's *Where the risk lives* (audio lifecycle, the press path).

## Push to talk, the ear and the voice

Voice on the phone is push to talk (`Apps/Client/VoiceInput.swift`): the microphone opens as the thumb comes down; hold it to talk and release to send, or tap to leave it open until the next press. Which a release is, is SwiftUI's word and not a clock's: the microphone carries a standard `LongPressGesture` of 0.4 s (`VoiceInput.tapLimit`, within the press's 60 points) beside its down/up gesture, and a release is a hold only when that long press fired before it (`Composer.micHeld`, `MicPress.hold`, handed to `VoiceInput.pressUp` as `held`), so the time the app takes to open the microphone is no part of the verdict. The verdict is only as good as the main thread at the press: a tap whose thumb-down is followed by a stall of the main thread past 0.4 s is a hold, because SwiftUI fires the overdue long press before the release that queued behind it (`MicrophonePressTests.testATapWhileTheMainThreadStallsIsJudgedByTheGesture`, which records it), so the open's engine work runs off the main thread and the `microphone open` line says what the session took on it (`session`). A press slid more than 60 points before the long press fires releases as a tap. A tap whose thumb lifts while the microphone is still opening (the open in flight) opens it hands-free once it is open; a hold lifted then cancels the press; and with the system's prompt up, any release cancels it, since the alert takes the touch. A press made while another's microphone is still opening opens nothing, and nor does its release; the chat still sounds the listening cue for it, beside the press that is opening. The first press asks for the microphone, which is the only permission a press asks for, and nothing is asked before it.

Recognition is on the device, and it is the phone's one ear: Parakeet-tdt-0.6b-v2 through FluidAudio (`Apps/Client/Ear.swift`, the iOS target only), the audio so far decoded bare every second for the caption and the whole utterance decoded and rescored at the release against the person's own vocabulary (`Apps/Client/Vocabulary.swift`: empty until they add to it, since none of anyone else's words are theirs; edited from the settings sheet; kept in this device's defaults rather than the vault, because a vocabulary is this device's ear and not the person's memory). An edit rebuilds the spotter's session live, so a word works from the next press; the gate is constant (no aliases, similarity 0.65, three characters minimum, and FluidAudio's confident-word bias gate off, since the sweep measured the rescorer without it: Daphne's measured config, and the reason additions are safe). The session is a layer over Parakeet, not a condition of the ear: an empty list builds none, and one that cannot be built leaves Parakeet recognising bare, with the reason in the diagnostics `speech` row.

The microphone is heard through Apple's voice processing — noise suppression, echo cancellation and gain control, one unit on the engine's input node — unless Noise suppression is off (`NoiseSuppression`, on for a phone never asked; a toggle in the settings sheet and the mind's own `topo voice noise-suppression on|off`, `docs/guest.md`; kept as the `noiseSuppression` default, this device's alone like the vocabulary). The setting is read at the press and nowhere else, so a change is the next press's: the unit can be changed only on an engine that is not running, which every press finds, and it changes the input node's formats, so the press sets it after the engine's input node is made and before the one read of the formats the guard judges and the tap carries (`VoiceInput.setVoiceProcessing`, called only when the node's own answer differs, since a change rebuilds the node's unit). The sink's converter follows whatever format the buffers arrive in. Off is the unit gone, not bypassed: the microphone as it comes. The voice unit ducks every other sound on the phone while it runs, a reply of Topo's among them, so its ducking is set to the least it allows (`voiceProcessingOtherAudioDuckingConfiguration`, advanced ducking off and the level at its minimum); some remains for as long as the microphone is open. With it on, a reply on the phone's own speaker is quieter than with it off, from the call volume `voiceChat` plays at and that ducking; with headphones it does not show. The echo cancellation is what lets a person talk over a reply, so the setting stays on by default and the quieter speaker is its stated cost: the settings footer says it, and so does the mind's line for `topo voice noise-suppression`, so it can answer a person who asks why its voice is quiet. A node that will not take the change refuses the press in words and drops the engine, the session left as it was. Every microphone that opens says which it is in the log (`microphone open: noise suppression on`, the `audio` category), after the engine has started.

The session's mode goes with the unit, and it is `AudioSession`'s to set: the record configuration is `voiceChat` with voice processing and `default` without (`AudioSession.wantVoiceProcessing`, told the setting when `VoiceInput` is made and again at each press, before `ensureActive`), the category and its options the same either way. A voice unit made on a session in no chat mode has the system set `voiceChat` by itself and leave it there when the unit goes, which would be a mode nobody here chose under a session counted as configured. A change of setting reconfigures like a claim does, so not while a hold stands or the microphone is open; the press hands the unit the state the session is actually in (`AudioSession.voiceProcessed`), so under a hold both stay as they were and change together at the first press after it.

The models are not in the bundle: about 540 MB of CoreML that `ModelDownloads` (`Apps/Client/ModelDownloads.swift`) fetches from the first foreground on (`VoiceInput.prepare`) into the app's Application Support, where FluidAudio loads them from, told to touch no network of its own (`ModelHub.offlineMode`). Until they are resident, or if they fail to load, a press is refused with the ear's own status line and nothing touches the audio session or the engine; the chat's microphone is dimmed whenever a press would not open one (`VoiceInput.canListen`, the microphone denied or the ear not resident, read from the state as it is, so the load finishing undims it with no press in between); the first-run line's copy about allowing it in Settings (`FirstRunLine`) stays tied to `denied` alone, since an ear that is still downloading is a wait rather than something to go and allow; a decode that throws at the release sends the caption the glances left, and nothing when there is none, with the error in the debug `Capture`. The diagnostics screen's `speech` row says which state the ear is in.

A spoken turn's reply is read aloud (`Speaker`; the mute in the chat's navigation bar turns it off, kept as the `readAloud` default, and muting stops what is being read, for good — what the guest writes while muted is not read, and the reply the mute stopped is not begun again when it is lifted — ends every wait, and leaves a reply that lands muted unread: `SpokenReply.wire` and `SpokenReply.read`'s `muted`, asked of the defaults as the reply comes), a typed one's is not; holding any of Topo's turns in the transcript opens a menu that says it again, which is how a typed turn's reply is heard (`Replay` in `Apps/Client/TranscriptView.swift`, threaded from the chat screen, so the watch, the television and a viewer offer nothing). The item reads Stop while the speaker is speaking, and is gone while the voice is not resident; the chat's microphone is a stop button for as long, too (`MicPress`, `docs/chat.md`). Nothing is read into an open microphone: a reply that lands while one is open — held, hands free, or opening, which a press marks before `VoiceInput` awaits the permission prompt (`Speaker.microphoneOpening`) — is taken and waits, with its turn's wait standing, and is read when the microphone closes (`Speaker.microphoneOpen`, asked at every `speak` and answered with `VoiceInput.busy`, open or opening, and `Speaker.microphoneClosed`, called when the press's call into `VoiceInput` returns and by `MicrophoneWatch` whenever `VoiceInput.busy` goes false — an observation the app starts, not a view, so it runs behind the lock); a newer reply replaces it and a stop drops it, each letting go of its turn's wait, and a press that opens the microphone again keeps it and its wait, to be read when that one closes. Its turn stays marked spoken until it is read or dropped (`Speaker.settled`, which the chat answers with `Harness.answeredAloud`), so a reply the session refuses at the close keeps waiting and is still owed.

The keeper has sounds (`KeeperSounds`, `Apps/Client/WorkingSounds.swift`): what a phone in a pocket hears of a spoken turn being worked on. The setting is While Topo works (`WorkingSounds`: `off`, `receipts`, `sounds`; `sounds` for a phone never asked, so a spoken turn's hold is heard as playback from the release to the reply rather than as silence (App Review's 2.5.4, `docs/testflight.md`); a picker in the settings sheet and the mind's own `topo voice working off|receipts|sounds`, `docs/guest.md`; kept as the `workingSounds` default, this device's alone, as the case's name, and anything kept that is not one of the cases — a Boolean included — reads as `sounds`), read at each sound. The sounds are Daphne's, as she plays them (Sam's own bloops, `THIRD-PARTY`; `bloop_<tone>.wav` at the bundle's root). The receipts are tool-class tones, each tool classed as her voice channel classes it (`KeeperSounds.tone(forTool:)`, buddy-channels `voice/classify.ts`; a table of its own, not the mascot's): `read` for `Read`, `Grep`, `Glob`, `LS`, `ToolSearch`, `WebFetch`, `WebSearch`, `NotebookRead`, `ListAgents` and `TaskOutput`, `write` for `Edit`, `Write`, `MultiEdit` and `NotebookEdit`, `delegate` for `Agent`, `Task` and `Workflow`, and `act` for everything else — a command, every MCP tool, anything new. A delegate's own result coming back sounds `return`, paired to its call by the call's id (`StreamEvent.toolUse`'s `id`, the result's `tool_use_id`), since calls made at once finish in any order and a sub-agent's own tools sound and answer between its delegate's call and its result; the delegates still owed a result go as a turn begins and goes; a result Claude Code marked an error sounds `error` (her channel's `SubagentStop`, and a `PostToolUse` that did not succeed); and `error` sounds too when the guest's turn fails with the earcons off (`GuestSession.TurnEnd.failed`; a failure the harness finds for itself sounds nothing here; with the earcons on their `failed` says it and the receipt gives way, Daphne's rule, so one failure is one tone). A receipt sounds over Topo's own voice, as Daphne's Keeper does: each is a fraction of a second and quieter than the voice. Two more are the open microphone's and the press's: `speak` (the go-ahead) as its microphone can take the next one (*The conversation*, below), and `queue`, a two-note bleep, for a press released with words while a turn is still on its way, in place of the earcons' `sent` (`Speaker.sounded(release:)`, which asks the harness — words on the line the log does not have, or a turn this device is running, `Harness.turnOnItsWay`; words the log has with no run open on them are not, a reply shown included though its words stay on the line through the memory's pass after it — and not the speaker's waits, which the press itself ends; with the sounds off, or nothing on its way, the earcons say it as ever). They follow the harness's guest activity beside Topo (`KeeperSounds.follow(harness)` wraps the handler `Mascot.follow` installed, after it). The receipts and the bleep are the keeper's, so they sound only while a hold that is not a sound's own stands (`AudioSession.heldForATurn`): a typed turn, which holds nothing, makes none; a typed turn sent while a spoken turn's wait stands receipts with it; and a tool reached for in the moment after a press ended the wait, with only the last receipt's hold standing, sounds nothing, so the receipts cannot keep the process alive by themselves. The conversation's go-ahead sounds under the conversation, which its own input or the front keeps running, and holds only beside a turn's hold. Under `sounds` the bed plays too: `thinking_bed.wav`, an 8 s loop under −20 dBFS at half volume, wherever a turn's own hold stands and Topo's voice is not heard, as Daphne's does (`ClaudeTurn.updateBed`): the speaker asks for it (`Speaker.askForBed`) while a release whose utterance has been taken, a turn's wait, or a gap of the voice in a spoken turn's reading stands, and the keeper's sounds judge the rest — the mode, the mute (`Mute`: muted, no bed at all), a turn's hold and the voice. It fades in over 1.5 s and out over 0.25 s, and is paused rather than stopped, so the next ask picks it up where the last left it. A release asks once `VoiceInput` has taken its utterance (`VoiceInput.onTaken`, told after `SampleSink.take`, with the tap off or the kept input's gate shut, so the bed's onset is never in the released utterance; a conversation's next microphone opens over the bed as it fades in, ducked), and so it is under the final transcription and the send; the release hands over to its turn's wait without the bed moving. A reply landing ends its wait and the bed plays on to the reading's first frame (`Speaker.voiceGap`, from `begin`); the voice's gap opens again when a reading of a spoken turn's reply has said everything it has with the guest still writing — the queue drained with nothing being made (`drained`), or the last sentence made with no frame after it and the queue already idle (`made`) — and the next frame closes it, so the guest's tools between two messages are under the bed and the pause between two sentences of one message is not. When a reading ends with another turn's wait still standing, the bed comes back for it (`Speaker.done`). A replay answers no turn and has no bed under it, and a wait taken while Topo is reading starts none, so the bed is never under a sentence. The lock screen's `.began` stops the bed with the engine, and it stays wanted; at the interruption's `.ended` the player made before the interruption is stopped and let go (`KeeperSounds.renew`), since what it says of itself is not to be trusted across the change, and the speaker asks for the bed again where it puts its own engine back, on a new player at the level the microphone asks for. The record configuration's category is not silenced by the ring/silent switch, so neither is the bed. A mode changed mid-wait applies at the next sound, and off goes through in every mode, so a bed begun under `sounds` is still faded out at its wait's end. Every sound is played by an `AVAudioPlayer` on the session as it stands, live (`AudioSession.ensureLive()`) and refused when it is not, so it configures and activates nothing, after an interruption behind the lock least of all; where a hold that is not a sound's own already stands it holds the process for its own length too (the `.sound` hold, below), taken before it starts, and with nothing held it holds nothing. Into an open microphone they sound as Daphne's do, and each tells the conversation its length as it starts (`KeeperSounds.toneSounded`), which shuts that microphone's gate under it (*The conversation*, below), so the ear does not take a tone for speech. The bed dips to a fifth of its level while one is open, set at each microphone moment: the press's, and `MicrophoneWatch` seeing `VoiceInput.listening` go either way (`Speaker.microphoneListening`, `microphoneClosed`). The players are handles into mediaserverd: at a media services reset the speaker has them dropped first, before its own queue, and nothing built, and the next sound makes its own. The session counts the reset and stops being live at the notification itself, before any handler runs (`AudioSession.resets`), and every player is checked against the count it was made under before anything touches it, so a sound after the session's handler has made it live again and before the speaker's has run drops the stale players rather than speaking to them. The lock screen's interruption stops the bed under a wait that still wants it, so the speaker asks for it again where it puts its own engine back (`resumeAudio`), through the same refusal path as its start; whether the bed is wanted is kept apart from whether it is playing, so a resume the session refuses leaves it wanted and the next end that succeeds brings it back. Letting another app's playback resume when the last hold goes is the session's hand-back, not these sounds': a sound's hold is taken only beside a turn's, and when it is the last to go its letting go is that hand-back, after its player has stopped.

The spoken exchange sounds four cues (`Earcons`, `Apps/Client/Earcons.swift`), each a UI SFX Zen sound (CC0, `THIRD-PARTY`) bundled as `earcon_<cue>.mp3` at the bundle's root: `listening` as the microphone opens at a press, once `VoiceInput.pressDown` has returned with the chat holding the microphone (`owner`, which every refusal that begins no session clears; a press over another press's start or end answers nil and leaves it, and the one over an end is a press on the open microphone's waveform, `drawn.open`); `sent` at a release that heard words, and at the press on the open microphone's waveform that sends them, unless a turn is still on its way, where the keeper's `queue` bleep is that release's sound; a release whose words are written into the row rather than sent (`Dictation`) sounds neither `sent` nor `failed`, since nothing went; `failed` at a release that heard nothing, and when a spoken turn fails for the person (`Harness.onTurnFailure`, told before what was drawn of the reply is dropped and before `onTurnFailed` at the sites that set a failure the person sees, and when the guest's turn ends with an error result under a reply being read — not a guest that exited or went silent, whose transcript may hold the reply; not for a turn another device answered or one the guest finished with iCloud behind, which end the same wait and are no failure): `Speaker.turnFailed` sounds it for a wait standing for that turn, once, so a typed turn is silent, and a reply being read as it was written when its turn fails ends with `failed` in place of `done`; and `done` as a reply read aloud comes to its end (`Speaker.finished`; a reply stopped sounds nothing, a reply said again sounds `done` as it ends, and one heard out in a conversation sounds none, the conversation's go-ahead being that moment's tone). A stop and its release sound nothing, a release during the permission prompt sounds nothing, and a press the microphone refuses sounds nothing: a cue follows `VoiceInput`'s decision and never makes one. The setting is `EarconsSetting` (on for a phone never asked; a toggle in the settings sheet and the mind's own `topo voice earcons on|off`, `docs/guest.md`; kept as the `earcons` default, this device's alone), read as each cue sounds. A cue is a moment, not a reply: it is played by an `AVAudioPlayer` on the session as it stands, live (`AudioSession.ensureLive()`) and refused when it is not, so it configures and activates nothing, after an interruption behind the lock least of all; where a hold that is not a cue's own already stands it holds the process for its own length too (the `.cue` hold, above), taken before the player starts, with nothing held it holds nothing, and under nothing but the cue before it it lets that one's hold go, so cues cannot keep the process alive by themselves; nothing but `listening` is played into an open microphone, since a second press while a turn is in flight is allowed and a cue is dropped rather than deferred, and a cue still sounding as a press opens the microphone is stopped there and its hold let go (`Earcons.microphoneOpening`, told by `Speaker.microphoneOpening`); the player's finish ends a play only if the player is silent when it arrives, so the finish of one play delivered after the same cue has begun again ends nothing; and the players are handles into mediaserverd, so at a media services reset the speaker, once its own queue is dropped, has them dropped too and nothing built, and the next cue makes its own. `listening` is heard by the microphone by design: with noise suppression on the echo canceller removes it, and with it off it is the first 300 ms of the utterance, which Parakeet has no word for. There is no armed cue: nothing is armed between turns.

The voice is on the device, and it is the phone's one voice: Gradium's Phonon 40m English through Gradium's own Swift runtime, ptts's `Phonon.swift` vendored as `Packages/PhononTTS` over its compiled core, `PhononCore.xcframework` (`Apps/Client/Voice.swift`, the iOS target only), speaking Friendly Octopus, the one voice its bundle carries (`PhononStore.voice`), at a temperature that is a setting (`VoiceTemperature`: 0.3 for a phone never asked, the bundle's own, which Gradium's exporter writes as the temperature its other frontends speak at; a slider in the settings sheet from 0 to 1 and the mind's own `topo voice temperature`, `docs/guest.md`; kept as the `voiceTemperature` default, this device's alone, and read as each sentence is asked for (`Voice.synthesise`, which hands it to the engine), which is ahead of its playing, so a change is heard from the next reply and, in a reply being read, only from the sentences not yet made; anything kept that is not a number in the range, a Boolean included, is read as 0.3). The runtime places the flow model on the Neural Engine (`.neuralEngine`) and decodes on the CPU. One engine for the process (`PhononVoiceEngine`, an actor) makes one sentence at a time: a sentence is begun only once the one before has stopped making samples, its own or a stopped one's (a busy flag, and a queue of waiters it is handed to in turn), so two never run at once and a sentence's wait is never another's tail. Phonon reads its temperature from the bundle's `bundle.json` as it loads, and its runtime has no setter, so a sentence asked for at a temperature other than the one loaded first writes that one key into the store's `bundle.json`, every other left as it was, and loads the bundle again: between sentences and never under one, the old instance let go before the new one opens, so two are never held; about a quarter of a second warm, once, after the setting moved. A reload that fails leaves the engine holding no bundle, and the sentence is refused before any frame; the voice is then failed (`Voice.synthesise`), its line says it could not be loaded again and why, replies are text, and the next foreground's `prepare` loads it again. Phonon makes no audio handle of its own: its samples, 80 ms frames of 1920 at 24 kHz, reach the speaker through `Speaker`'s play queue alone, which is why ptts's own player (`PhononPlayer.swift`, which builds an engine and a session of its own) and its model downloader (`PhononModels.swift`, which goes to the network) are left out of the vendored package, and `scripts/tests/fetch-phonon-test.sh` fails a tree whose app or packages name either. What the voice reads is the reply's words as the transcript draws them, not its source (`Speakable`, `Apps/Client/Speakable.swift`, applied in `Speaker.speak` and never to the transcript): cut by the transcript's own parse, so emphasis, heading marks and list markers are gone, a link whose words are not its address is its words, and a bare URL — a link whose words are its address — is "a link to" its host, each dot said ("a link to example dot com"); a code block is "See code block N.", N the number the transcript draws over it; a table is "A table with N rows.", not counting the header; an image is "An image: " and its alternative text, or "An image." with none, said after the block it was written in, as it is drawn — so of a reply still being written, a block is read no further than an image in it until a blank line ends the block (`Speaker.settled`); a rule is nothing; and in every other block a URL the parse did not link (one inside code, or with a scheme a tap does not follow) or an address is left exactly as written, inline code is a literal whose every `/`, `~` and `.` followed by something is said (`./look.json` "dot slash look dot json"), and outside backticks a file name or a path is read with its punctuation said — `look.json` "look dot json", `/home/topo` "slash home slash topo", `Apps/Client` "Apps slash Client" — while a decimal, a version, `e.g.`, `and/or` and a sentence's own full stop are left as written. Phonon then normalises what is left as English (`Language.english`): numbers, amounts, dates, emails and the symbols between them are said as words, and none of the rewriting above is done there. It is cut into sentences on sentence-final punctuation, each synthesised behind the one before as a stream of 80 ms frames pushed to one player node as they decode, so the wait is the first frame. A code block's line, "See code block N.", is always a sentence of its own, and it is a cue — the line carries its block from `Speakable.lines` (`Speakable.Line.codeBlock`), so prose that says the same words is never one — (`Speaker.cue`, a `CodeBlockCue` naming the reply's turn, the block and a serial): its first frame is marked on the play queue (`PlayQueue.play`'s `begins`), and the mark fires when every frame scheduled before it has been heard — with nothing scheduled before it, a lead-in of two milliseconds of silence, written as zeroes (`PlayQueue.leadIn`), is queued ahead of the frame to carry it — which is the moment the sentence starts, however far synthesis has run ahead. What counts as heard is `.dataPlayedBack`; a test's offline engine never plays back, so a test hands `Speaker` `.dataRendered` and renders. A reply stopped or replaced before the mark fires cues nothing, a reply said again cues its blocks afresh, and a reply not read aloud makes no cue at all; the debug report's `blocks` lists the blocks the reply reached, in order. What the cue does on the screen is `docs/chat.md`'s. Phonon's pace is fixed in its bundle at export, with no setter in its runtime, so how fast the voice is heard is the play queue's `AVAudioUnitTimePitch`, with the pitch untouched and the only thing between the voice's frames and the speaker, at a rate that is a setting (`VoiceSpeed`: 1.0, Friendly Octopus's own pace, for a phone never asked; a slider in the settings sheet from 0.8 to 1.5 in steps of 0.05 and the mind's own `topo voice speed`; kept as the `voiceSpeed` default, this device's alone, and read only where the queue already speaks to its nodes, as it builds the unit and at each frame it plays (`PlayQueue.build`, `PlayQueue.play`, after `ensureActive`), so a change is heard from the next frame queued; anything kept that is not a number in the range, a Boolean included, is read as 1.0). `Speaker` reads the clock through an injected `now` (the continuous clock in production), so the debug report's two measurements are arithmetic a unit test drives rather than a race it has to wait out. The voice's bundle is Phonon 40m English exported to Core ML with Friendly Octopus as its one voice (`phonon-40m-en`: a `bundle.json` naming every other file with its size and SHA-256, the flow models and Mimi as `.mlpackage`s, the host weights, the tokenizer and the voice; about 200 MB), and how it reaches the phone is the build's. A TestFlight or App Store build gets it as one essential Apple-hosted Background Assets pack, `phonon-40m-en`, which the system downloads with the app at its first install (`installationEventTypes` `firstInstallation` alone, `scripts/phonon-bundles.sh`) through Topo's downloader extension (`TopoAssets`, `Apps/Assets/TopoAssets.swift`: Background Assets' own `StoreDownloaderExtension`, embedded as `Extensions/TopoAssets.appex`) for the app group the Info.plist names (`BAAppGroupID` `group.zone.hexagon.topo`, beside `BAHasManagedAssetPacks` and `BAUsesAppleHosting`; `scripts/check-built-plist.sh` reads the three and the extension off the product); the archive never carries the weights (`docs/testflight.md`). A build from the install page carries the bundle in its own resources (`TOPO_EMBED_VOICES=YES`, `docs/install.md`), and a debug launch can name a folder (`TOPO_DEBUG_VOICE`). Whatever the source, one store holds the copy the engine loads (`PhononStore`, `Apps/Client/PhononStore.swift`): `Application Support/Voice/phonon-40m-en`, excluded from backup, because Core ML compiles a `.mlpackage` beside itself and neither the pack nor the app is writable. A copy is made into `phonon-40m-en.partial` beside it, every file checked against the size and SHA-256 the source's own `bundle.json` names, `bundle.json` and the `.installed` record (the bundle's `built` stamp and, from a pack, the pack's version) written last, and only then renamed into place: a copy that fails at any step, the swap into place included, takes its partial folder with it, and one cut short by the process ending leaves a partial folder the next launch removes before anything else, whether it takes the store as it stands, copies, or its source fails, never a store with a file missing. A store whose record matches the source's and whose every file is there at its size is taken as it stands — against a pack, by the pack's version, without making the pack local — and an older one is replaced through the same path; a source that cannot be read leaves a good older copy in use. Once a pack's files are copied and checked the pack is removed (`AssetPackManager.remove(assetPackWithID:)`), so the phone keeps one copy of the weights, and the record says so (`Installed.released`): a removal that fails, or a process that ends between the copy and the removal, is tried again at each launch that finds the store whole until it is done. A launch on which the pack's version cannot be read takes a whole store as it stands rather than fetching the pack to find out, and logs that it did. An update of the app fetches no weights: a new version of the pack published since is found at the first launch after it, by the version the store's record names not being the pack's, and fetched then through the same path, copied over the store and the pack removed again. The fetch asks for the latest version (`ensureLocalAvailability(of:requireLatestVersion:)` from iOS 26.4; before it, the older call and then the pack's status, a local version that is not `upToDate` being a refusal), and the version recorded is the one that call made local, never one read apart from it, so an older pack a failed removal left on the phone is recorded as itself and not as the version the manager advertises. Before 26.4 that refusal is all there is: with an older pack left local and a newer advertised, the store keeps its older copy and the pack beside it, and logs that at each launch, until the phone is on 26.4; until it is in, the voice is not loaded and replies are text. While the store waits on a pack's download the voice's line says how far it has come, `downloading Topo's voice (N%)` for a first download and `downloading Topo's new voice, replies written until it's in (N%)` for a new version over a copy already here (`Voice.renewingWords`), and `copying Topo's voice` while it copies. The store is asked from every foreground (`Voice.prepare`, which `Speaker.prepare` calls too), and Phonon loads from it (`Phonon.load(models:language:computeUnit:)` at `.english` and `.neuralEngine`, then `setVoice`); the first load after an install or a new bundle pays Core ML's compile. The ear comes first, because the first thing a person does is talk and a reply can be text until the voice is in: the voice's compile waits while the ear is still to be fetched or is compiling (`Voice.mayLoad`, over the ear `TopoApp` hands it), so the ear's compile is not shared with the voice's even when the voice's copy is already made: refused for an ear being fetched, the voice waits for the ear's download to settle (`whenSettled`), and the ear calls `Voice.earSettled` when its compile ends, resident or failed (`Ear.settled`). An ear whose download failed lets the voice compile, which is the one way the two still compile at once: a later foreground's retry can bring the ear in while that voice is compiling, and nothing holds the ear back for the voice. A debug stand-in ear holds nothing back. On every launch the voice's load follows the ear's cached one. A reply is not read aloud at all when the voice is not resident or fails to load — there is nothing to fall back to — and the diagnostics screen's `voice` row says which state it is in; a debug build launched with `TOPO_DEBUG_VOICE=loading` (`DebugRun.voice`) holds the voice unloaded, and one launched with a directory holding the bundle copies it into the store from there as from any source, which is what the talk lane does.

One `VoiceInput` for the app and one gate on its microphone, enforced: a surface pressing while another holds it is refused, since two gates on one input answer the same utterance twice; the chat's composer is the one surface that presses, the first-run answer included (`docs/chat.md`). Every press is a session with a generation, so a release during the permission prompts starts nothing, a late recogniser result or a second release belongs to no session, and what one session heard cannot become the next one's turn. The audio session, the idle timer and the background hold are process-wide, so `AudioSession` counts claims on them rather than assigning them; the record configuration is warmed on the foreground so the press does not pay for the route change — unless another app is playing (`AVAudioSession.isOtherAudioPlaying`, read at the foreground), since the record configuration cannot mix and warming it would pause the podcast with nothing said: then Topo stays on the quiet, mixable configuration and takes the session from other audio only at the press that starts a spoken exchange, which pays the route change and takes the warm claim with its own, so the record configuration stands from the press to the reply's end (the press's claim goes as the microphone closes, before the wait's hold is taken) and until Topo leaves the front (`AudioSession.warmRecord`).

A spoken turn's reply is heard behind the lock, in a pocket, or in front of another app: the iOS target holds the `audio` background mode (`Apps/Topo/Info.plist`), and under it iOS runs the process only while an engine of its own is running, so the play queue keeps a second player node at no volume looping a fifth of a second of zeroes (the keeper) for as long as a hold stands. The process is held by the running engine and the keeper is only what it renders, so with no hold nothing runs: the last hold going stops the keeper and the engine with it, its nodes left attached, and the next hold or frame starts it again through the same refusal path as any other. An engine left running under a stopped keeper is a phone that never suspends. The hold is counted like the other two, with five kinds of owner: `.releasing(token)`, one per spoken press released, from the thumb coming up (or the press that closes a hands-free microphone) until its turn's wait stands — `awaitReply` lets it go, the press's task naming its token just before the send (`Speaker.sending(under:)`), which reaches `awaitReply` before its first suspension — or until a send that took no wait returns, or at 30 s (`Speaker.releaseBound`); a Stop, a press or a sign-out leaves it standing, since the words it is finishing are still sent, and a reset lets it go; `.awaitingReply(nonce)`, one claim per spoken turn outstanding — the chat lets a second press append while the first turn is in flight, and each turn holds for itself — taken at the send and dropped when that turn's reply is handed to `speak`, when the harness says that turn failed or that the guest finished it with iCloud still behind, the reply read as it was written (`Harness.onTurnFailed`, named as the turn ends, since the screen's error line cannot say whose turn stopped), when a press, a Stop, a sign-out or a reset ends things, and at its ceiling: 120 s, or, while the wait is heard and its turn still running, up to 15 min from the send (*Waiting behind the lock*, below); `.speaking`, taken in `speak` after `ensureActive` and dropped when every sentence is made **and** the queue is drained, since a queue that empties between two sentences is not the reply's end; and `.cue`, taken by an earcon that begins while a hold that is not a cue's stands, for its own length, and let go of once the player has finished and the route's tail has passed — the session's output latency and one I/O buffer, plus 250 ms, since the hold is the last one when `done` ends a reply behind the lock, and what the route still holds as the session is let go of is lost (`Earcons.outputTail`) — or at `Earcons.bound` (2 s), whichever is first, so the `done` cue behind the lock is heard before the engine stops — the speaker plays it before it drops `.speaking`, so the holds never go empty between the two; a cue begun with nothing held — `listening` at a press in front — holds nothing; and `.sound`, taken by a sound played beside the voice that begins while a hold that is not a sound's own stands (`AudioSession.heldForATurn`) — a receipt, the bed's fade-out — for its own length (`KeeperSounds.bound` at most) and taken before the hold it follows drops, so the error receipt and the fade behind the lock are heard out before the engine stops (the fade's let go once the bed is paused, so the session is never handed back under a running player); a sound begun with nothing held, or under nothing but another sound's hold, holds nothing. Nothing is held for a turn whose reply could not be heard anyway — replies muted, or the voice not resident at the release — and a typed turn asks for none, so the app suspends behind the lock as it always did. The reply's owners are bounded by the same ceiling, `.awaitingReply` from the send (120 s, or 15 min while heard and running) and `.speaking` from the last frame scheduled or played back (120 s), and a cue's and a sound's each by its own 2 s, so a hold outlives a dead reply by the ceiling, and a cue's or a sound's bound after it, at most; the ceiling's line says which way the wait ended, a reply that never landed or one that landed and was refused, with the count, because the two end the same wait and only that tells a run's log them apart.

An `AVAudioSession` interruption is not the end of either: iOS posts a `.began` at the lock screen with no call and no Siri in it, so `.began` stops the player, keeps the buffers nobody has heard and leaves the hold standing — and a frame arriving while the engine is dead is added to what is owed rather than played, since restarting a dead engine throws and the voice reads that throw as the sentence's end (the notification's type, reason, `wasSuspended` and options are logged), and `.ended` — or the `AVAudioEngineConfigurationChange` a real interruption's end posts — rebuilds through the same path as the lock's category flip, whenever anything is owed or the queue is dead, building an engine from nothing if an earlier refusal left none. Every way the recovery path can fail ends in one refusal: the engine is dropped, the owed frames and the dead mark are kept, the session is invalidated, and the next end, change or reply tries the whole thing again — an activation refused, an engine that will not start, a frame that could not be played, a keeper that could not be started. A reply arriving on a dead queue rebuilds it first and is refused when that rebuild is, and one whose hold cannot be honoured — the keeper's own engine refusing to start — is refused the same way, since a reply taken on an engine that will not start would clear its turn's mark and end its wait for a reading that never happens. The hold's count tells the speaker about every claim taken or dropped, not only about the answer changing, so a claim arriving while another already stands is the chance to start a keeper an earlier refusal left down. Nothing is reported as playing, or as held, that is not. The format survives a refusal, because it is the voice's rate and not the engine's and a frame arriving while there is no engine at all is still made against it and owed; only a media services reset drops it. A reply cut by a short phone call carries on after it; a reply the speaker refuses (`speak` answers whether it took it) is still owed, so its turn stays marked spoken, its wait stands to its ceiling, and the next pass offers the reply again.

The decision to read a reply aloud is `Harness.onReply`, which the chat installs beside `PushWake`: it fires for a reply this phone wrote and for one a pass read that another primary wrote, once per turn, because behind the lock nothing is drawn and whether a view's observer runs is SwiftUI's to decide. A reply is recorded as offered only when a handler took it — one that was not there, and one that could not act, both leave it to be offered again — and installing a handler replays what arrived unheard, since the screen reads the log and sends what an earlier launch left owed before it installs. Of more than one owed reply the newest is read and the older are cleared unread: a person coming back is owed the answer to the last thing they said rather than a backlog read at them, and each reply spoken cuts off the one before it anyway. The handler reads the mark, which the release made, and then the mute as the reply comes: a marked turn's reply is read unless replies have been muted since, and a muted one is settled unread. Whether a turn is spoken is the wait's own answer — `Speaker.awaitReply` answers both `spoken` (the reply is to be read aloud when it lands unless replies are muted by then, which is what marks the turn, and is true in the foreground whatever the audio is doing) and `held` (the keeper is actually rendering for it); the chat records the mark from `spoken` and states no condition of its own, so no later launch turning the setting on reads an old reply aloud, and a keeper that would not start is reported as the refusal it is rather than as a hold. The mark is the harness's, and on disk (`topo.harness.spoken`, the twenty most recent nonces owed a reply, cleared per turn as its reply is read and by a sign-out): the words said before the app went away survive the relaunch in the outbox, so what makes them a spoken turn has to survive with them. Signing out, and the far end of a takeover, stop the speaker: the reply in the ear goes with the login.

While any hold stands the session is not reconfigured: a claim change — the warm record claim dropped at the lock, or any other — is remembered, so the session that was active at the release stays active and untouched, whatever category it was in, until the reply has been heard. An open microphone keeps the session the same way (`AudioSession.microphone(open:)`, told once the press's engine has started and again when it has been torn down): its tap is installed on the format that configuration gave and its voice unit was made for that mode, so a hold that drops over an open microphone applies nothing, and what waited is applied when the microphone closes. What is remembered is applied when the last hold goes, the microphone is closed and the app is in front; behind the lock, where the last hold going is as likely a reply ending as the app coming back, the session is marked as needing configuring instead and the claims are left for the next path that wants audio — the next `ensureActive`, or the foreground's own warm claim, which applies them as it changes. Activating or reconfiguring a non-mixable session from the background is refused (`cannotInterruptOthers`), and a session left invalid by that refusal is one every later `ensureActive` tries the same refused call on, which is a reply spoken only on unlock; an already-active session goes on rendering behind the lock under the `audio` mode, so `ensureActive` at `speak` is free there and nothing sets a category or activates a session from the background. A claim's configure failing is logged with its error rather than thrown, since a claim is not an audio path and the path that is meets it at `ensureActive`. What can still change under a hold is an interruption, whose end is exactly when iOS allows the session back: the queue rebuilds for its own engine on an `.ended` or an `AVAudioEngineConfigurationChange` — `ensureActive` first, then a fresh engine at the same format, every buffer not yet played back scheduled again in order under a new epoch so the discarded completions move nothing, and the keeper back if a hold stands. Resuming a reply after an interruption ends is not built.

**Waiting behind the lock.** Nothing but audio keeps the process running behind the lock or another app: the session Topo activated in front stays active there, and iOS runs the process while an engine of its own renders or records. So a spoken turn's wait is carried by what is heard or recorded while it stands: under `sounds`, with replies read aloud, the working bed plays for it from the release to the reply (above), and a conversation keeps its input engine running from its start to its end (*The conversation*, below). A wait passes its 120 s ceiling standing while it is carried (`Speaker.waitCarried`, read off the audio rather than the settings: the bed playing with replies read aloud, or a conversation's input running, which the app answers, `Speaker.conversationHears`; a bed whose player refused to play, or a microphone suspended, is silence) and its turn is still running (`Speaker.turnRunning`, `Harness.turnOpen`), logging `the ceiling passed with the turn running and the wait heard; it stands`, and goes on so until 15 min from the send (`Speaker.outerBound`; `capped at 900.0 seconds; the turn was still running`); a wait not carried — `receipts` or `off`, replies muted — or one whose turn the harness has closed ends at 120 s, and its reply is read on unlock (`docs/harness.md`). The 15 min bounds the wait, not the turn: a turn longer than that is still answered, and its reply read when Topo is next in front. No silent session is held to wait past the first 120 s (App Review's 2.5.4, `docs/testflight.md`): what keeps the process is a sound playing or a microphone recording, each of which the person hears or sees. Topo places no call: there is no `CXProvider`, no `CXStartCallAction` and no `voip` background mode, which `scripts/check-built-plist.sh` refuses in the product and `scripts/tests/places-no-call-test.sh` in the source; `CXCallObserver` is read only to know whether the person is on a call of their own. Each reply logs the session it begins on (`the reply begins (mode …, voice processing …, route …, volume …)`, `AudioSession.describeOutput`). The shape is Daphne's (samdu/daphne-assistant, `TurnController`'s lock hold).

**The conversation.** A microphone tapped open hands-free on a spoken turn is a conversation, in front and behind the lock, by the same rule (*Each utterance's end*, below) and the same object. Its input engine runs from its start to its end, Daphne's half-duplex: each utterance's end takes what was heard and shuts the microphone's gate with the engine and its tap left running (`VoiceInput.end(as:keepingInput:)`, `VoiceInput.inputKept`), and the next utterance opens the gate on that engine (`VoiceInput.reopen`, `openKept`) with no session, engine, voice processing or format touched, so behind the lock nothing activates or configures the session from the background but an interruption's end and a media services reset's re-apply; an input started there otherwise (the deaf rebuild below, and the reopen after an utterance whose decode an interruption came and went inside) starts on the session already active. With the gate shut nothing the input hears reaches the sink, a caption, a turn or the row (`TapGate`, the check and the append one step under its lock), and it is not the microphone left open: `listening` is false and a reply is read over it. The audio session is kept for it as for an open microphone (`AudioSession.keptInput`): nothing is reconfigured or handed back while it runs, since its tap is on the format the session gave. While it runs with noise suppression on, its voice unit ducks the app's other sounds as little as the system allows (`.min`, as Daphne's ear does under her receipts). It stops (`stopKeptInput`) at the conversation's end, at an interruption's start, at a media services reset, at the chat's cancel and when a press next opens the microphone, which takes that engine as its own. In front (`Conversation.inFront`) a conversation begins as the tap leaves the session hands-free (`beginInFront`, observed on `VoiceInput.handsFree`), when the detector is loaded, the chat's send is installed, no phone call is up, the app is active and the destination is a send (`Dictation.sends`: dictation into the draft never begins one). It runs on the app's own session, which a reopen activates as a press does, and only while the app is active (`live`): at an inactive moment (the lock's own `.began`, Control Center) it holds what is suspended until the app is active again (`becameActive`) or the background carries it, so either order of the lock's `.began` and its background is handled, and a reopen whose permission answers in such a moment opens and reads nothing (`VoiceInput.reopen`'s `live`) and waits for it. An utterance the judge has ended is a release, and its decode is sent whatever ends the conversation meanwhile but the keyboard and the chat going. The caption glances run as a tap's do. Every press of the chat's microphone but Stop's ends it before the press reaches the session (`MicPress`'s `pressed`, `Conversation.pressed`, which leaves the session to the press): a tap on the open microphone sends what it heard and closes it, and a press on the microphone closed between utterances opens a session of its own. Stop while Topo reads keeps it (Daphne's B): the press stops the reading and reaches no session, as Stop always does, and the conversation, which the reading already owed the go-ahead, opens the microphone again and sounds it. The keyboard coming up, the chat going, an interruption in front (the app still active: a phone call over Topo), 120 s with nothing said, and the app leaving the front with nothing to carry it (a phone call up; the scene's `.inactive` or the background) end it, dropping what is open. Behind the lock, a microphone open hands-free on a spoken turn as Topo leaves the front, or a conversation in front, is carried rather than dropped (`Apps/Client/Conversation.swift`, one object the app starts beside `MicrophoneWatch`, outside any view), when the voice activity detector is loaded, the chat's send is installed, no phone call is up (`CXCallObserver`: the session is the call's while one is) and the session's destination is a send (`Dictation.sends`: dictation into the draft is dropped as the scene goes). A held press, with a thumb on it, is not carried. The conversation begins at `didEnterBackgroundNotification`, asked by whichever of it and the resident's lifecycle hears the notification first (`Conversation.beginIfCarried`, `GuestLifecycle.conversing`), and stops the caption glances (`VoiceInput.glancing`), which nobody reads behind the lock. It goes on on the session it was activated on in front, the running input holding the process under the `audio` mode. An interruption — the lock's own `.began`, a phone call, Siri — is survived by suspending the microphone (`VoiceInput.suspend`: the tap off, the engine stopped and dropped, the generation, owner and samples kept, and the kept input stopped, with nothing handed back under the interruption; a kept input stopped under a reading is owed, `VoiceInput.keptOwed`) and resuming it at the interruption's `.ended`, when iOS gives the session back, through the press's own path (`VoiceInput.resume`: `ensureActive`, a new engine, voice processing, the one read of the formats, the tap), going on into the same samples; an owed kept input is started again there with its gate shut (`VoiceInput.restoreKept`), so the reading's end opens its gate with nothing started then, and one that will not start ends the conversation; the log says whether the microphone came off before the conversation began (`conversation: begun behind the lock (the microphone came off at …)`). A chunk whose verdict is with the detector at the resume keeps its feeder, so the verdict is taken rather than lost, since the detector has already judged that chunk and would not give it again, and a reply that waited meanwhile is judged at that moment. Between an interruption's start and its end the microphone opens on nothing (`live`), since an activation the interruption still holds is refused and leaves the session invalid. A microphone listening with no samples arriving for 2 s (`Conversation.deafAfter`: a route change stops the engine with nothing to say so) is suspended and rebuilt the same way, once; deaf again with nothing heard since, the conversation ends with what was kept. A session suspended in front by a `.began` with no conversation after it is dropped when the app is active again.

Each utterance's end is heard on the phone (`Apps/Client/Endpoint.swift`), by two listeners. Silero's voice activity detector through FluidAudio's `VadManager`, fed the sink's samples in whole 256 ms chunks with its streaming state kept between them, says where speech starts and where it ends; speech shorter than 0.25 s is a cough and ends nothing (`Endpoint.Policy`), Silero's end or the judge's: an end the judge or the cap reaches is given only once the speech, from its onset to the end of its last loud frame (`Conversation.loudTo`), has run that long (`Endpoint.Policy.long`, `Conversation.ends`); speech with no loud frame at all ends on Silero's 4 s. From Silero's first start in an utterance, the sink is also counted in 100 ms frames (`Endpoint.Judging.frame`, taken at the feeder's tick, `Conversation.feedEvery`), each quiet when its RMS is at or under −38 dBFS (`Endpoint.loud`, Daphne's onset), and Smart Turn v3.2 (`Apps/Client/SmartTurn.swift`) is asked whether the utterance sounds finished, by Daphne's rule (`Endpoint.Judging`): asked from 0.4 s of quiet and every 0.2 s after, one ask in flight at a time, across the rule's starting over when an end is turned away as a cough's (`Endpoint.Judging.again`), and each ask numbered on from the last for as long as the app runs, a new utterance's rule included (`nextUtterance`, which lets go of an ask the utterance before left out), so an answer to an ask from before is never taken for one made since; a verdict over 0.85 is a vote and one at or under it sets the votes to none; two votes in a row end the utterance once the quiet has run the wait (Settings' *Open mic waits*, `QuietWait`, 0.6–3.0 s in steps of 0.2, 1.2 s unless changed, `topo voice wait`, read at each verdict); 40 quiet frames end it whatever the judge says. A loud frame sets the quiet to none and makes a verdict still in flight count for nothing, the frames that arrived before a verdict lands counted before it is, and the votes are kept across it, as Daphne keeps them. A verdict counts only for the session, the utterance and the ask it was asked for (`voice.generation` and the ask's number), and only while Silero still holds the utterance to be speech. With the judge loaded, Silero's own end waits for 4 s of silence (`Endpoint.silence(judged:)`), so it is the cap rather than an end that races the judge, and the one end in a room too loud for the gate ever to call quiet; with none, it waits 2.1 s, just past the 2 s that cut a speaker off mid-clause in Daphne before Smart Turn judged the end, and nothing else ends the utterance. Which of the two a conversation runs on is chosen as it begins, from whether the judge is loaded, and its first line says which (`conversation: judging ends with Smart Turn`, or `… ending on Silero's 2.1 s of quiet alone (the judge: <state>)`). A judge that throws is logged once an utterance and is a verdict of nothing, so the 4 s cap still ends the turn. The conversation's own tone is the go-ahead, as on Daphne's Claude page: an utterance's onset sounds nothing, since a tone as the person starts to speak reads as the microphone only then opening. The go-ahead (`speak`, her `cueIfReady`) is owed when the conversation begins, when an utterance is sent, while a reply waits for the microphone or is read, and paid once the microphone is open with nothing on its way — open and running, not muted, on a live session (the one the conversation was carried on with no interruption standing, or the app's own in front with the app active), the detector having judged every whole chunk it holds, nobody speaking, no spoken turn's wait standing, nothing being read — as the microphone opens again after an utterance or a reply, or, where it is already open, once the last of those clears (a wait ending with no reply to read); a cue begun in the last 1.5 s stands in for it (`Earcons.recent`, her `earconReceipt`), so one moment has one tone. A reply heard out under a conversation sounds no `done` (`Speaker.conversing`) where the go-ahead can sound, since it is that moment's tone; with While Topo works off no go-ahead sounds, and `done` is said as outside one. A reply heard out with a second spoken turn's wait standing has its go-ahead after that turn's reply, as Daphne's is paid when her microphone is back. A tone sounded into the open microphone shuts its gate for the tone's length with room (`KeeperSounds.toneLength`, her `holdGate`): an onset inside it opens nothing, and only what of that utterance runs on past the gate, by more than the detector's lateness (an end is put a chunk and the pad after the speech it closes), counts toward the 0.25 s, so a tone heard alone is never an utterance, while words begun inside it are still sent once they run on past it by that much. The judge counts its quiet only from an onset given to the person (`Conversation.heardOnset`, Daphne's judge running only on a turn an ungated onset opened), so a tone's own onset is nothing it can end, and words begun inside a tone, which have none, end on Silero's 4 s of silence; its frames are counted by their level alone, a tone's loud as Daphne's are. Two tones the detector hears as one segment are an utterance where the silence between their gates reaches the 0.25 s: no such segment has come from Silero over the bloops, and one would be decoded and sent like any words. A gate runs from the tone's place in the stream, less the detector's start resolution (a chunk and FluidAudio's 0.1 s pad, `Endpoint.startEarly`), to its end: an onset before it is the person's, whenever the detector's verdict on it arrives, so a tone sounded over words already begun — a receipt of the turn still being worked on — takes nothing of them (`Endpoint.Policy`). A tone sounded while the microphone is between utterances (a reopen landing) is no part of the next utterance's gates, which start empty: what of its tail the new session hears is not gated. The judge is handed the utterance's last eight seconds (`SampleSink.tail`, which copies only those) and pads them at the front to its window; it computes Whisper's log-mel features (`Mel`, three `sgemm`s) and runs the model through Core ML on the CPU and the Neural Engine (`.cpuAndNeuralEngine`; never `.all`, which lets it fall to the GPU, and iOS ends a background process that submits GPU work), every load and every verdict one block on its own serial queue (`SmartTurn.queue`), never the main actor or the cooperative pool, since both are synchronous work. The model is Topo's own Core ML package of pipecat's fp32 weights, an FP16 ML Program within 0.05 of pipecat's fp32 model on the same features, so its scores are the fp32 model's and not those of the int8 ONNX export Daphne runs, which sits up to 0.40 from it (`samthehugenerd/Smart-Turn-Topo`, made and measured by `smart-turn-coreml` in samdu/experiments at `c8d4467`). The phone compiles the package the first time it loads it and keeps the compile in Caches under `smart-turn/`, named for the package's bytes (`SmartTurn.compiled`), outside the model store, whose sweep would remove it; a new package compiles afresh, and a purged cache costs one compile. A compile is loaded only while its bytes match the digest written beside it after the compile (`<name>.sha256`): Core ML crashes, past any `catch`, on a compile missing a file or cut short, so one damaged in part is compiled again. A load ends with one prediction on silence, so a conversation's first verdict does not pay the model's first run. Each end logs one line, `conversation: ended an utterance (complete 0.93 after 1.4 s quiet, judged in 14 ms)` or `(4.0 s of quiet; last verdict 0.41, judged in 14 ms)` or `(Silero's 4.0 s of quiet; …)`, the time being the last counted verdict's from its ask to its answer; no line is logged per ask and no sample ever. Each load logs one line with its three times: `smart turn: compiled in 9120 ms` (or `the kept compile checked in 40 ms`), `loaded in …`, `its first prediction in …`. Both models (`silero-vad-coreml`, `ModelManifest.vad`; `smart-turn-v3`, `ModelManifest.smartTurn`) are fetched with the ear's and loaded in front (`Endpoint.prepare`, on every foreground); Silero's is kept where `VadManager` reads it (`<support>/Models/silero-vad`, `ModelStore.vadHome`: FluidAudio's `Repo.vad.folderName` drops `-coreml`, so under its manifest id it is present and never found) and loaded offline (`Endpoint.silero`), and Smart Turn's is loaded from `Models/smart-turn-v3` and compiled into Caches (below); both, never first behind the lock, where a model's first load has taken minutes; each has its own state, so a judge that failed holds the detector back from nothing, and a conversation is carried with the detector alone. Smart Turn's mel filterbank is bundled (`smartturn-mel.bin`, 64 KB, written by `scripts/smartturn-mel.py` from pipecat's numpy reference, vendored at `scripts/vendor/whisper_features.py`, and checked bit for bit by `scripts/tests/smartturn-mel-test.sh`). At an end the utterance is held as a release is (`Speaker.releasing`, taken before the decode and let go as the send takes its turn's wait, at once when nothing is sent, or at 30 s), decoded as a release decodes it (`VoiceInput.end`, keeping the input), sent through the chat's own send (`ChatView.sendSpoken`: the row, the one nonce, the wait and the mark) in a task of its own, and the microphone opened again at once (`VoiceInput.reopen`, a press with no thumb: the permission not asked, one not already granted refusing, and a session no longer live refused rather than waited out, whenever the permission answers; on the kept input it is the gate opened), so the send's wait is not time the microphone is deaf; the gap is logged (`conversation: reopened after N ms`). The microphone is closed while Topo reads, its gate shut and its engine running: a reply that lands over an open microphone with nothing said in it closes it unsent so the reply is read, one landing over speech waits for the utterance's end as any reply waits for a microphone, and the microphone opens again when the reading is done and nothing waits for it (observed on `VoiceInput.listening`, `suspended`, `Speaker.speaking` and `Speaker.waitingForMicrophone`, and asked again after each pass of the detector and as each verdict lands; a reply closes the microphone only once the detector has judged every whole chunk the sink holds, the one in flight included, and no verdict of the judge's is in flight). A chunk is counted fed only once its verdict is in; a detector that fails more than nine times in a row, each a retry of the same chunk a feed later (`Conversation.failuresTolerated`, about a second) ends the conversation, sending what was heard. A microphone that will not open again ends the conversation, except one refused while no session is live (the lock's `.began` in front, an interruption standing behind the lock): that waits for one, bounded by the conversation's 120 s.

The conversation ends when the chat stops answering (`send` taken away: a sign-out, a takeover; what an utterance's end is still decoding is dropped), when Topo comes to the front (`willEnterForegroundNotification`; what is open sent if it held speech or holds samples the detector has not judged — suspended, with the detector, or not yet fed — and dropped if not), and after two minutes with nothing said (`Conversation.idle`; a wait standing, a reading, a decode or speech under way starts the clock again, and a microphone suspended for the whole two minutes ends it whatever waits, sending what it kept). Every end is `Conversation.stop`, which runs once per conversation: the glances back on, the kept input stopped — which, with Topo away and nothing else holding the session, hands it back (*The hand-back*, below) — and the resident's lifecycle told (`GuestLifecycle.conversationEnded`, `docs/guest.md`), which is what lets the resident be frozen. The battery this costs is the microphone recording behind the lock for the whole conversation — through a turn being answered and its reply being read, since the engine never stops between utterances, and up to two minutes past the last thing said — with a running input engine, the detector every 256 ms and Smart Turn up to five times a second over a pause, against a phone that would otherwise suspend; the recording indicator shows for as long.

**The hand-back.** The record configuration is non-mixable, so the press pauses whatever else the phone was playing, and a session that merely stops rendering never tells it to resume. So when the last hold goes with Topo away (`AudioSession.letGo`), and when the microphone closes or a conversation's kept input stops with nothing else keeping the session (`microphone(open:)`, `keptInput(running:)`), the session is deactivated with `notifyOthersOnDeactivation` (`handBack`), which is allowed from the background where an activation is not: the podcast resumes, and the claims that waited are left for the next audio path, which configures and activates afresh. Two things keep it. A conversation keeps the session from its beginning to its end (`AudioSession.conversation`, `RecordClaim.conversation`): nothing between two of its utterances — an utterance's end, a wait's or a reading's end, an interruption's end, a route change — hands it back or configures it for playback, so an interruption's end resumes it as the microphone's and the next utterance opens on it with nothing activated from the background; its end lets the session go as the last hold going does. And an interruption's start keeps it for a microphone the conversation carries, since the session is the interruption's (`lettingGo: false`, at `VoiceInput.suspend` and the kept input's stop there); a microphone nothing carries is dropped there and handed back as any close is. The speaker is told the hold's drop first, so the keeper's engine is stopped before the hand-back, which an engine still rendering would refuse as busy; a refusal is logged and leaves the session marked as needing configuring. Entering the quiet configuration from the record one — the warm claim going as Topo leaves the front with nothing held, Control Center pulled down over it included — hands back the same way before the mixable session is activated beside it. So a podcast plays on while Topo is in front with nothing said, pauses at the press, and resumes when the reply has been read behind the lock or another app, or the conversation has ended there, or, with Topo in front, when it leaves the front. The podcast does not play under the reply itself: the record configuration cannot mix. Each hand-back logs whether other audio is playing, and again a second later (`noteOtherAudio`), since whether the other app takes up again is its own to decide and the log is the only sight of it.

Nothing that is a handle into mediaserverd — an `AVAudioEngine`, its input node, a tap, an `AVAudioPlayerNode` — is created, read, started or spoken to until `AudioSession` has configured **and** activated the session since the last reset; a failure to activate is a refusal, never a fall-through. `AudioSession.ensureActive()` is the call every audio path makes first, and costs nothing on a session that is already valid, so a press still does not pay for the route change the foreground paid for, where it paid for one.

The microphone's engine is off the main actor (`Apps/Client/InputEngine.swift`): the input `AVAudioEngine`, its node and its tap are touched only on one serial queue, so the press's open never holds the main thread the gesture's events and the long press's verdict arrive on. The press claims and activates the session on the main actor, whose state it is (and the speaker's), reads the input's reset count before the activation, tells the session the microphone is open **before** the first handle exists (`AudioSession.microphone(open:)`, so no claim, hold or setting change reconfigures or hands back the session under an engine starting on the queue; what activates a session that is no longer valid reads no mark, so a media services reset can activate it afresh before the open's next check of the reset count refuses it, over handles the reset has already killed), and hands the open to the queue as one block: the engine made or the kept one taken, voice processing set to the session's `voiceProcessed`, the formats read once, the guard, the tap on the very format object the guard judged, `prepare()`, `start()`. A media services reset since the count was read refuses the open before the engine, the tap and the start (the input counts resets on the posting thread at the notification itself), and one the main actor sees after the open has answered drops what it made. While the open is in flight `VoiceInput.opening` is true, and the app answers `Speaker.microphoneOpen` with `VoiceInput.busy` (`listening || opening`), so a reply landing then waits for the microphone whoever is opening it — a conversation's reopen tells the speaker nothing else, where a thumb's press has already said so (`Speaker.microphoneOpening`); `MicrophoneWatch` hears the microphone close once neither stands. The open is put on the queue from the main actor before the press waits for it, so a teardown made while it waits is behind it on the queue and stops what it started. An interruption's start while the open is in flight drops what it starts: a session the conversation carries is suspended as the open answers, to be resumed as an open one is, and any other press is cancelled. Every teardown from the main actor — a cancel, a release, a suspend, a kept input's stop, a reset's handler — is a `queue.sync` that returns only once the tap is off and the engine stopped, so one made while an open is in flight waits for it, and the session is never reconfigured or handed back under a running tap; an open whose press was cancelled meanwhile changes nothing when it answers, since whatever cancelled it tore it down. A conversation's resume is the same block waited for (`openNow`), since its caller reads the answer at once. Each `microphone open` line names how long the open took on each side: the session's claim and activation on the main actor (`session`), the whole wait for the queue's answer (`queue`), and each of the queue's steps (`engine`, `voice processing`, `formats and tap`, `prepare`, `start`). The engine's only warm-up is Apple's `prepare()`; `AudioSession.warmRecord` warms the session's category, the route change, which `prepare()` cannot reach. `start()` prepares an engine not prepared since its `stop()`, and `stop()` releases what `prepare()` allocated, so the explicit call right before `start()` costs what `start()` would and is kept so the log times allocation and start apart; voice processing, set at the press alone, rebuilds the unit, so there is no earlier moment a cold press's could be prepared.

When iOS resets the media server (`AVAudioSession.mediaServicesWereResetNotification`) the session is marked invalid at the notification, its reset counted (`AudioSession.resets`), and re-applied if it had ever been configured, a failure there being remembered rather than swallowed; `VoiceInput` cancels any press, dropping its words, a released press's decode included, and drops its engine; and `Speaker` drops the keeper's sounds' players first, stops the reply, drops its holds and drops the play queue's engine, players and time-pitch unit, which an interruption deliberately does not, and then the keeper's sounds' hold, the cues' players and the cue's hold; a hold change under the handler starts nothing (`resetting`), since a wait ending with a sound's or a cue's hold still standing would otherwise restart the keeper on the dead engine. Nothing is rebuilt in a handler: the press and `speak` each reactivate and build what they need, so recovery does not depend on which of the two comes first, and Say it again after a reset works with no press before it. A press reads the input node's client and hardware formats and refuses (`no audio input`) when either has no sample rate or no channel or the two rates differ — both are ways `installTap` raises an exception no `catch` sees — and a refusal, like an activation that threw, drops the engine and invalidates the session so the next press rebuilds rather than reading the same dead node. ## Model downloads

On-device model weights are downloaded by Topo, never by the libraries: one background `URLSession` (`ModelDownloads`, identifier `zone.hexagon.topo.models`; expensive and constrained network access off, waits for connectivity, not discretionary) so iOS applies the person's data settings and finishes the transfer with the app suspended or gone, with no prompt, toggle or gate of ours. What it fetches is `Apps/Topo/Resources/models.json`, the pinned manifest `scripts/model-manifest.sh` writes from the Hugging Face tree API: `FluidInference/parakeet-tdt-0.6b-v2-coreml` at `ee09c569`, `FluidInference/parakeet-ctc-110m-coreml` at `accdafd8`, `FluidInference/silero-vad-coreml` at `b419383c` (the conversation's voice activity detector, 1 MB) and `samthehugenerd/Smart-Turn-Topo` at `2f07bf86` (Smart Turn v3.2 as Topo's own Core ML package, one 16 MB `.mlpackage` directory, compiled on the phone); each entry is the flattened file list (a `.mlmodelc` is a directory of files on the Hub) with sizes and sha256 digests. Download tasks only, one per file, each verified against its digest and moved into `Application Support/Models/<id>/` with the digest recorded in the directory's ledger (two entries live elsewhere, `ModelStore.homes`, because the library that reads them reads one path and no other: the CTC spotter's is FluidAudio's own `CtcModels.defaultCacheDirectory`, where `VocabularyBoostingSession` reads its tokenizer, and the voice activity detector's is `Models/silero-vad`, where `VadManager` looks beneath the base directory it is given; a set downloaded under the root before that is renamed into place rather than fetched again); a model is present only when every file is on disk at its size and in the ledger, a partial set carries on from the files it has (resume data where the server gave any), and a bump is a new revision in the script and a re-run. A pass enqueues the wanted models not yet present (`ModelDownloads.plan`); a failed one only on a pass that retries, which is a `start`. A watchdog (`DownloadWatchdog`, `Apps/Client/DownloadWatchdog.swift`) judges each task's rate from the session's own progress, since the Hub's CDN sometimes serves one connection at tens of kilobytes a second for the whole of a transfer while its neighbours run at tens of megabytes, and the same bytes asked for again come fast: a task that is slow over a 20 s window of foreground samples (under 256 KB/s and, where another task is flowing beside it, under a tenth of the fastest; one flowing alone is judged by the floor) is cancelled with its resume data (`cancel(byProducingResumeData:)`, through the relay, so its completion is never a failure, and `.restarting` is said only once both the cancel's handler and the task's completion have come, with whatever resume data either carried on disk; a task that finished as it was cancelled is owed nothing) and made again from that data under the same key, at once the first time, then 15, 30 and 60 s after its cancel, and past those at once again but no more than once in five minutes, the task left running between; a replacement is judged on its own samples, from its own first byte, and a key whose replacement had no resume data to carry on from, or whose resume the server answered with the whole file, is not cancelled again. While a task flowing beside the others has samples but no window yet, nothing is judged: its rate is the comparison, a few ticks away. The watchdog ticks every 5 s only while the app is in front and a task has samples or a replacement is owed: a background session carries on with the app suspended and no progress reaches the process, so at resign it keeps the bytes each task is at and takes no sample, on return it reads each task's bytes off the session and judges the time away as one span (a crawl that ran the whole time the phone was locked is cancelled at once; nothing, where a task flowing had no sample at the resign to measure from), and every sample from before is dropped, each task left running with a first byte anchored at the bytes it is at on return, so one that stalls then is judged by that silence a window on; the read is applied only for the return that asked for it with the app still in front, and leaves out a task finished or failed since it was asked for, so a read taken before a completion never restores a task that will report nothing more; a cancel in flight and a replacement owed are kept across the time away, and made on the first tick after the return. Between a task's cancel and its replacement, and while a task this process made is in flight, `enqueue` leaves the key alone, so a foreground `start()` never makes a second task for a file. A task made from resume data that the server answers with 403, 412 or 416 (the Hub's signed URLs expire) is fetched afresh from its URL rather than failed; which key's task was made from resume data is kept in defaults (`topo.models.resumedKeys`), so a relaunch the session wakes for still knows. Slowness never fails a model, settles a waiter or sets `failures`.

`TopoAppDelegate` (a `UIApplicationDelegateAdaptor`) takes `handleEventsForBackgroundURLSession`, so a transfer that finished while the app was dead is admitted on the relaunch and the handler called. The ear's status line and the diagnostics `speech` row say what the session reports: waiting for a network the settings allow, downloading with bytes done of total, verifying, then preparing the model for this phone (the CoreML load, which after an install is the Neural Engine compiling the models afresh) and resident. The voice's line and the `voice` row say what its store is doing (`Voice.fetchWords`): checking Topo's voice while the store finds its copy whole, which every launch does and draws no meter for; downloading Topo's voice, or Topo's new voice with replies written until it is in, with the pack's percentage; copying Topo's voice; waiting for the ear; then preparing the model for this phone and resident.

The store keeps only what the manifest accounts for (`ModelStore.sweep`, `Apps/Client/ModelHousekeeping.swift`, a function over the manifest rather than a step of the download path), run at launch for every model already present and again after each arrival that makes one present. The protected set is each entry's directory as `directory(for:)` resolves it, never its id, since the voice activity detector's id is `silero-vad-coreml` and its home `Models/silero-vad`: anything under `Models/` that is none of those homes is removed, and inside a home under `Models/` whose model is present, anything that is not a manifest file, the ledger or a file's resume data. A model that is not present is not swept at all, and a home outside `Models/` (the spotter's, FluidAudio's own cache) is a library's and is never entered. Every folder from Application Support down to what the sweep removes or enters, `Models/` included, is judged with `lstat`: a `Models/` reached through a link is not swept at all, a home reached through one is not entered, a link inside a home is removed as a link and never descended, and the link a skipped `Models/` or home is reached through is left where it stands.

CoreML's compiled Neural Engine bundles land in `Library/Caches/<bundle id>/com.apple.e5rt.e5bundlecache` on a model's first load and are kept across installs (`CompileCache`, `Apps/Client/ModelHousekeeping.swift`), so that an update whose models are the same bytes may skip compiling them again — whether CoreML's key for a compiled bundle survives an install is unmeasured, and a generation compiled under another OS build or model pack stays until iOS purges Caches under pressure or the person clears it. The settings sheet's `Clear compiled model cache` sets a request (`topo.models.clearCompileCache`) and the next launch removes that directory whole, and nothing else in Caches, before the ear and the voice are made (`ModelHousekeeping.launch` in `TopoApp.init`, since a debug build's start loading as they are made), so no compile is writing into it as it goes; the request is removed only once the directory is gone or was never there, so a removal that fails is tried again, and nothing is removed when Caches or the app's folder in it is reached through a link. Under the `models` category, every launch with no clear pending logs `compile cache: kept for install <key>`, with ` (new install)` after it at an install's first; a clear logs `cleared on request`, or `absent on request` when there was nothing there, and a refused one `not cleared`. An install is the `LC_UUID` of the image the app's code is linked into (the main executable in a release build, `Topo.debug.dylib` in a debug one) together with the app bundle's path, whose container directory every install makes new, compared with the one last recorded in defaults (`topo.models.compileCacheInstall`), because `CFBundleVersion` is 1 on every development install.
