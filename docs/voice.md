# Voice

Push to talk, the on-device ear and voice, the audio session and the background hold, and how the models get onto the phone. The invariants a change here must keep are in CLAUDE.md's *Where the risk lives* (audio lifecycle, the press path).

## Push to talk, the ear and the voice

Voice on the phone is push to talk (`Apps/Client/VoiceInput.swift`): hold the microphone to talk and release to send, or tap to open it until the next press. The first press asks for the microphone, which is the only permission a press asks for, and nothing is asked before it.

Recognition is on the device, and it is the phone's one ear: Parakeet-tdt-0.6b-v2 through FluidAudio (`Apps/Client/Ear.swift`, the iOS target only), the audio so far decoded bare every second for the caption and the whole utterance decoded and rescored at the release against the person's own vocabulary (`Apps/Client/Vocabulary.swift`: empty until they add to it, since none of anyone else's words are theirs; edited from the settings sheet; kept in this device's defaults rather than the vault, because a vocabulary is this device's ear and not the person's memory). An edit rebuilds the spotter's session live, so a word works from the next press; the gate is constant (no aliases, similarity 0.65, three characters minimum, and FluidAudio's confident-word bias gate off, since the sweep measured the rescorer without it: Daphne's measured config, and the reason additions are safe). The session is a layer over Parakeet, not a condition of the ear: an empty list builds none, and one that cannot be built leaves Parakeet recognising bare, with the reason in the diagnostics `speech` row.

The microphone is heard through Apple's voice processing — noise suppression, echo cancellation and gain control, one unit on the engine's input node — unless Noise suppression is off (`NoiseSuppression`, on for a phone never asked; a toggle in the settings sheet and the mind's own `topo voice noise-suppression on|off`, `docs/guest.md`; kept as the `noiseSuppression` default, this device's alone like the vocabulary). The setting is read at the press and nowhere else, so a change is the next press's: the unit can be changed only on an engine that is not running, which every press finds, and it changes the input node's formats, so the press sets it after the engine's input node is made and before the one read of the formats the guard judges and the tap carries (`VoiceInput.setVoiceProcessing`, called only when the node's own answer differs, since a change rebuilds the node's unit). The sink's converter follows whatever format the buffers arrive in. Off is the unit gone, not bypassed: the microphone as it comes. The voice unit ducks every other sound on the phone while it runs, a reply of Topo's among them, so its ducking is set to the least it allows (`voiceProcessingOtherAudioDuckingConfiguration`, advanced ducking off and the level at its minimum); some remains for as long as the microphone is open. A node that will not take the change refuses the press in words and drops the engine, the session left as it was. Every microphone that opens says which it is in the log (`microphone open: noise suppression on`, the `audio` category), after the engine has started.

The session's mode goes with the unit, and it is `AudioSession`'s to set: the record configuration is `voiceChat` with voice processing and `default` without (`AudioSession.wantVoiceProcessing`, told the setting when `VoiceInput` is made and again at each press, before `ensureActive`), the category and its options the same either way. A voice unit made on a session in no chat mode has the system set `voiceChat` by itself and leave it there when the unit goes, which would be a mode nobody here chose under a session counted as configured. A change of setting reconfigures like a claim does, so not while a hold stands or the microphone is open; the press hands the unit the state the session is actually in (`AudioSession.voiceProcessed`), so under a hold both stay as they were and change together at the first press after it.

The models are not in the bundle: about 540 MB of CoreML that `ModelDownloads` (`Apps/Client/ModelDownloads.swift`) fetches from the first foreground on (`VoiceInput.prepare`) into the app's Application Support, where FluidAudio loads them from, told to touch no network of its own (`ModelHub.offlineMode`). Until they are resident, or if they fail to load, a press is refused with the ear's own status line and nothing touches the audio session or the engine; the chat's microphone is dimmed whenever a press would not open one (`VoiceInput.canListen`, the microphone denied or the ear not resident, read from the state as it is, so the load finishing undims it with no press in between); the first-run line's copy about allowing it in Settings (`FirstRunLine`) stays tied to `denied` alone, since an ear that is still downloading is a wait rather than something to go and allow; a decode that throws at the release sends the caption the glances left, and nothing when there is none, with the error in the debug `Capture`. The diagnostics screen's `speech` row says which state the ear is in.

A spoken turn's reply is read aloud (`Speaker`; the mute in the chat's navigation bar turns it off, kept as the `readAloud` default, and muting stops what is being read, for good — what the guest writes while muted is not read, and the reply the mute stopped is not begun again when it is lifted — ends every wait, and leaves a reply that lands muted unread: `SpokenReply.wire` and `SpokenReply.read`'s `muted`, asked of the defaults as the reply comes), a typed one's is not; holding any of Topo's turns in the transcript opens a menu that says it again, which is how a typed turn's reply is heard (`Replay` in `Apps/Client/TranscriptView.swift`, threaded from the chat screen, so the watch, the television and a viewer offer nothing). The item reads Stop while the speaker is speaking, and is gone while the voice is not resident; the chat's microphone is a stop button for as long, too (`MicPress`, `docs/chat.md`). Nothing is read into an open microphone: a reply that lands while one is open — held, hands free, or opening, which a press marks before `VoiceInput` awaits the permission prompt (`Speaker.microphoneOpening`) — is taken and waits, with its turn's wait standing, and is read when the microphone closes (`Speaker.microphoneOpen`, asked at every `speak`, and `Speaker.microphoneClosed`, called when the press's call into `VoiceInput` returns and by `MicrophoneWatch` whenever `VoiceInput.listening` goes false — an observation the app starts, not a view, so it runs behind the lock); a newer reply replaces it and a stop drops it, each letting go of its turn's wait, and a press that opens the microphone again keeps it and its wait, to be read when that one closes. Its turn stays marked spoken until it is read or dropped (`Speaker.settled`, which the chat answers with `Harness.answeredAloud`), so a reply the session refuses at the close keeps waiting and is still owed.

The voice is on the device, and it is the phone's one voice: Kyutai's Pocket TTS through FluidAudio (`Apps/Client/Voice.swift`, the iOS target only), speaking its stock `marius` at a temperature that is a setting (`VoiceTemperature`: 0.5 for a phone never asked, chosen by ear between the 0.3 Kyutai's own package speaks English at and the 0.7 FluidAudio speaks the April pack at, its default for `.english2026Apr` (its `.english`, Kyutai's October checkpoint, follows Kyutai at 0.3); a slider in the settings sheet from 0 to 1 and the mind's own `topo voice temperature`, `docs/guest.md`; kept as the `voiceTemperature` default, this device's alone, and read as each sentence is asked for (`Voice.synthesise`, which hands it to the engine), which is ahead of its playing, so a change is heard from the next reply and, in a reply being read, only from the sentences not yet made; anything kept that is not a number in the range, a Boolean included, is read as 0.5): each person names their own mind, so the default voice is a neutral stock one rather than anyone's blend. The pack is Topo's own (`samthehugenerd/Marius-Topo` on the Hub; the recipe is `topo-voice-pack` in samdu/experiments): FluidInference's English v2.1 pack, which is Kyutai's `english_2026-04` weights, file for file but for the flow decoder, converted from the same weights at one integration step a frame in place of eight, since the count is fixed in the model at conversion and one step is what Kyutai's own package runs. Every stage is placed off the GPU — the conditioner, the flow-LM and the fused flow decoder at `.cpuAndNeuralEngine` on the rank-4 `.ane` variants, Mimi at `.cpuOnly`, where the port found it fastest and where its fp16 state feedback does not beep; `.all` is never used, because it lets a stage fall to the GPU. What the voice reads is the reply's words as the transcript draws them, not its source (`Speakable`, `Apps/Client/Speakable.swift`, applied in `Speaker.speak` and never to the transcript): cut by the transcript's own parse, so emphasis, heading marks and list markers are gone, a link whose words are not its address is its words, and a bare URL — a link whose words are its address — is "a link to" its host, each dot said ("a link to example dot com"); a code block is "See code block N.", N the number the transcript draws over it; a table is "A table with N rows.", not counting the header; an image is "An image: " and its alternative text, or "An image." with none, said after the block it was written in, as it is drawn — so of a reply still being written, a block is read no further than an image in it until a blank line ends the block (`Speaker.settled`); a rule is nothing; and in every other block a URL the parse did not link (one inside code, or with a scheme a tap does not follow) or an address is left exactly as written, inline code is a literal whose every `/`, `~` and `.` followed by something is said (`./look.json` "dot slash look dot json"), and outside backticks a file name or a path is read with its punctuation said — `look.json` "look dot json", `/home/topo` "slash home slash topo", `Apps/Client` "Apps slash Client" — while a decimal, a version, `e.g.`, `and/or` and a sentence's own full stop are left as written. Pocket normalises nothing beyond quotes and whitespace, so that is all the rewriting a reply gets. It is cut into sentences on sentence-final punctuation, each synthesised behind the one before as a stream of 80 ms frames pushed to one player node as they decode, so the wait is the first frame. A code block's line, "See code block N.", is always a sentence of its own, and it is a cue — the line carries its block from `Speakable.lines` (`Speakable.Line.codeBlock`), so prose that says the same words is never one — (`Speaker.cue`, a `CodeBlockCue` naming the reply's turn, the block and a serial): its first frame is marked on the play queue (`PlayQueue.play`'s `begins`), and the mark fires when every frame scheduled before it has been heard — with nothing scheduled before it, a lead-in of two milliseconds of silence, written as zeroes (`PlayQueue.leadIn`), is queued ahead of the frame to carry it — which is the moment the sentence starts, however far synthesis has run ahead. What counts as heard is `.dataPlayedBack`; a test's offline engine never plays back, so a test hands `Speaker` `.dataRendered` and renders. A reply stopped or replaced before the mark fires cues nothing, a reply said again cues its blocks afresh, and a reply not read aloud makes no cue at all; the debug report's `blocks` lists the blocks the reply reached, in order. What the cue does on the screen is `docs/chat.md`'s. Pocket has no pace of its own, so the pacing is the play queue's `AVAudioUnitTimePitch` at `Voice.tempo`, with the pitch untouched: a per-speaker constant, explained in the doc comment, and the only thing between the voice's frames and the speaker. For `marius` it is 1.0, the pace he speaks at. `Speaker` reads the clock through an injected `now` (the continuous clock in production), so the debug report's two measurements are arithmetic a unit test drives rather than a race it has to wait out. The model is not in the bundle either: about 350 MB (the four CoreML bundles the ANE placement loads, the constants and the tokenizer beside them, and the one speaker) that `ModelDownloads` fetches on the same cue (`Speaker.prepare`) and FluidAudio loads from the store, told to touch no network of its own. The ear comes first, because the first thing a person does is talk and a reply can be text until the voice is in: the voice's files are asked for after the ear's (`ModelDownloads.start(_:after:)`, so none is enqueued until both of the ear's models are on the phone or either has failed), and its compile waits while the ear is still to be fetched or is compiling (`Voice.mayLoad`, over the ear `TopoApp` hands it), so the ear's compile is not shared with the voice's even when the voice's files are already here: refused for an ear being fetched, the voice waits for the ear's download to settle (`whenSettled`), and the ear calls `Voice.earSettled` when its compile ends, resident or failed (`Ear.settled`). An ear whose download failed lets the voice download and compile, which is the one way the two still compile at once: a later foreground's retry can bring the ear in while that voice is compiling, and nothing holds the ear back for the voice. A debug stand-in ear holds nothing back. On every launch the voice's load follows the ear's cached one. The pass that lets the held voice go runs only with the app in front, since iOS starts a transfer created in the background at its own discretion; one let go in the background is created by the next foreground's `start`. A reply is not read aloud at all when the model is not resident or fails to load — there is nothing to fall back to — and the diagnostics screen's `voice` row says which state the model is in; a debug build launched with `TOPO_DEBUG_VOICE=loading` (`DebugRun.voice`) holds the voice unloaded, and one launched with a directory loads Pocket from there instead of downloading it, which is what the talk lane does.

One `VoiceInput` for the app and one gate on its microphone, enforced: a surface pressing while another holds it is refused, since two gates on one input answer the same utterance twice; the chat's composer is the one surface that presses, the first-run answer included (`docs/chat.md`). Every press is a session with a generation, so a release during the permission prompts starts nothing, a late recogniser result or a second release belongs to no session, and what one session heard cannot become the next one's turn. The audio session, the idle timer and the background hold are process-wide, so `AudioSession` counts claims on them rather than assigning them; the record configuration is warmed on the foreground so the press does not pay for the route change — unless another app is playing (`AVAudioSession.isOtherAudioPlaying`, read at the foreground), since the record configuration cannot mix and warming it would pause the podcast with nothing said: then Topo stays on the quiet, mixable configuration and takes the session from other audio only at the press that starts a spoken exchange, which pays the route change and takes the warm claim with its own, so the record configuration stands from the press to the reply's end (the press's claim goes as the microphone closes, before the wait's hold is taken) and until Topo leaves the front (`AudioSession.warmRecord`).

A spoken turn's reply is heard behind the lock, in a pocket, or in front of another app: the iOS target holds the `audio` background mode (`Apps/Topo/Info.plist`), and under it iOS runs the process only while an engine of its own is running, so the play queue keeps a second player node at no volume looping a fifth of a second of zeroes (the keeper) for as long as a hold stands. The process is held by the running engine and the keeper is only what it renders, so with no hold nothing runs: the last hold going stops the keeper and the engine with it, its nodes left attached, and the next hold or frame starts it again through the same refusal path as any other. An engine left running under a stopped keeper is a phone that never suspends. The hold is counted like the other two, with three kinds of owner: `.releasing(token)`, one per spoken press released, from the thumb coming up (or the press that closes a hands-free microphone) until its turn's wait stands — `awaitReply` lets it go, the press's task naming its token just before the send (`Speaker.sending(under:)`), which reaches `awaitReply` before its first suspension — or until a send that took no wait returns, or at 30 s (`Speaker.releaseBound`); a Stop, a press or a sign-out leaves it standing, since the words it is finishing are still sent, and a reset lets it go; `.awaitingReply(nonce)`, one claim per spoken turn outstanding — the chat lets a second press append while the first turn is in flight, and each turn holds for itself — taken at the send and dropped when that turn's reply is handed to `speak`, when the harness says that turn failed or that the guest finished it with iCloud still behind, the reply read as it was written (`Harness.onTurnFailed`, named as the turn ends, since the screen's error line cannot say whose turn stopped), when a press, a Stop, a sign-out or a reset ends things, and at its own ceiling of 120 s, while no call is up (*The call*, below); and `.speaking`, taken in `speak` after `ensureActive` and dropped when every sentence is made **and** the queue is drained, since a queue that empties between two sentences is not the reply's end. Nothing is held for a turn whose reply could not be heard anyway — replies muted, or the voice not resident at the release — and a typed turn asks for none, so the app suspends behind the lock as it always did. `.awaitingReply` and `.speaking` are bounded by the same 120 s ceiling, `.awaitingReply` from the send and `.speaking` from the last frame scheduled or played back, so a hold outlives a dead reply by the ceiling at most; the ceiling's line says which way the wait ended, a reply that never landed or one that landed and was refused, with the count, because the two end the same wait and only that tells a run's log them apart.

An `AVAudioSession` interruption is not the end of either: iOS posts a `.began` at the lock screen with no call and no Siri in it, so `.began` stops the player, keeps the buffers nobody has heard and leaves the hold standing — and a frame arriving while the engine is dead is added to what is owed rather than played, since restarting a dead engine throws and the voice reads that throw as the sentence's end (the notification's type, reason, `wasSuspended` and options are logged), and `.ended` — or the `AVAudioEngineConfigurationChange` a real interruption's end posts — rebuilds through the same path as the lock's category flip, whenever anything is owed or the queue is dead, building an engine from nothing if an earlier refusal left none. Every way the recovery path can fail ends in one refusal: the engine is dropped, the owed frames and the dead mark are kept, the session is invalidated, and the next end, change or reply tries the whole thing again — an activation refused, an engine that will not start, a frame that could not be played, a keeper that could not be started. A reply arriving on a dead queue rebuilds it first and is refused when that rebuild is, and one whose hold cannot be honoured — the keeper's own engine refusing to start — is refused the same way, since a reply taken on an engine that will not start would clear its turn's mark and end its wait for a reading that never happens. The hold's count tells the speaker about every claim taken or dropped, not only about the answer changing, so a claim arriving while another already stands is the chance to start a keeper an earlier refusal left down. Nothing is reported as playing, or as held, that is not. The format survives a refusal, because it is the voice's rate and not the engine's and a frame arriving while there is no engine at all is still made against it and owed; only a media services reset drops it. A reply cut by a short call carries on after it; a reply the speaker refuses (`speak` answers whether it took it) is still owed, so its turn stays marked spoken, its wait stands to its ceiling, and the next pass offers the reply again.

The decision to read a reply aloud is `Harness.onReply`, which the chat installs beside `PushWake`: it fires for a reply this phone wrote and for one a pass read that another primary wrote, once per turn, because behind the lock nothing is drawn and whether a view's observer runs is SwiftUI's to decide. A reply is recorded as offered only when a handler took it — one that was not there, and one that could not act, both leave it to be offered again — and installing a handler replays what arrived unheard, since the screen reads the log and sends what an earlier launch left owed before it installs. Of more than one owed reply the newest is read and the older are cleared unread: a person coming back is owed the answer to the last thing they said rather than a backlog read at them, and each reply spoken cuts off the one before it anyway. The handler reads the mark, which the release made, and then the mute as the reply comes: a marked turn's reply is read unless replies have been muted since, and a muted one is settled unread. Whether a turn is spoken is the wait's own answer — `Speaker.awaitReply` answers both `spoken` (the reply is to be read aloud when it lands unless replies are muted by then, which is what marks the turn, and is true in the foreground whatever the audio is doing) and `held` (the keeper is actually rendering for it); the chat records the mark from `spoken` and states no condition of its own, so no later launch turning the setting on reads an old reply aloud, and a keeper that would not start is reported as the refusal it is rather than as a hold. The mark is the harness's, and on disk (`topo.harness.spoken`, the twenty most recent nonces owed a reply, cleared per turn as its reply is read and by a sign-out): the words said before the app went away survive the relaunch in the outbox, so what makes them a spoken turn has to survive with them. Signing out, and the far end of a takeover, stop the speaker: the reply in the ear goes with the login.

While any hold stands the session is not reconfigured: a claim change — the warm record claim dropped at the lock, or any other — is remembered, so the session that was active at the release stays active and untouched, whatever category it was in, until the reply has been heard. An open microphone keeps the session the same way (`AudioSession.microphone(open:)`, told once the press's engine has started and again when it has been torn down): its tap is installed on the format that configuration gave and its voice unit was made for that mode, so a hold that drops over an open microphone applies nothing, and what waited is applied when the microphone closes. What is remembered is applied when the last hold goes, the microphone is closed and the app is in front; behind the lock, where the last hold going is as likely a reply ending as the app coming back, the session is marked as needing configuring instead and the claims are left for the next path that wants audio — the next `ensureActive`, or the foreground's own warm claim, which applies them as it changes. Activating or reconfiguring a non-mixable session from the background is refused (`cannotInterruptOthers`), and a session left invalid by that refusal is one every later `ensureActive` tries the same refused call on, which is a reply spoken only on unlock; an already-active session goes on rendering behind the lock under the `audio` mode, so `ensureActive` at `speak` is free there and nothing sets a category or activates a session from the background. A claim's configure failing is logged with its error rather than thrown, since a claim is not an audio path and the path that is meets it at `ensureActive`. What can still change under a hold is an interruption, whose end is exactly when iOS allows the session back: the queue rebuilds for its own engine on an `.ended` or an `AVAudioEngineConfigurationChange` — `ensureActive` first, then a fresh engine at the same format, every buffer not yet played back scheduled again in order under a new epoch so the discarded completions move nothing, and the keeper back if a hold stands. Resuming a reply after an interruption ends is not built.

**The call.** Behind the lock or another app, the exchange is an outgoing CallKit call (`Apps/Client/SpokenCall.swift`): placed while a hold stands with the app in the background — from the release of a press that sends a spoken turn on, since the release holds the process (`Speaker.releasing`, the `.releasing` hold, taken in the gesture's callback before the final transcription and let go as the turn's own wait is taken, once a send that took no wait returns, or at 30 s), so a lock between the thumb coming up and the send finds the process held and places the call, and a press under a call kept in front for a wait releases into the next turn's wait without the call ending between them — and Settings' *Call for spoken replies* on (`SpokenCallSetting`, `callForSpokenReplies`, on unless turned off; `topo voice call`), and kept for the whole exchange once it is up: coming forward with a hold standing leaves the call and its card over the chat until the reply has been read and the hold goes (`SpokenCallDriver.wants`'s `up`, as Daphne's call is kept), since ending it at an unlock and placing it again at the next lock hands the session back and forth under the reply and takes it back from whatever other audio was told it could resume. An open microphone keeps a call that is up as a hold does (`Speaker.onMicrophone`, told at the press before the waits it ends and again once no microphone is open or opening and a reply that waited for it has been read): a press in front under the call would otherwise end it, and the system would deactivate the session under the microphone it had just opened on. No call is placed in front: a refused placing's retry and a call wanted while the last one was closing are dropped once the app has come forward (`SpokenCall.mayPlace`). The call's speaker override is cleared at the call's end, or, with a hold or an open microphone still keeping the session, when the last of them goes. Resigning active — Control Center, a notification pulled down — places none. The background is UIKit's (`UIApplication.applicationState` when the driver is made, then `didEnterBackgroundNotification` until `willEnterForegroundNotification`, as Daphne's call follows it) rather than SwiftUI's scene phase, and each decision is logged with its three facts (`call driver: …`, the background as `app …`) beside the scene phase as SwiftUI reports it (`scene …`), so a lock that placed no call says why and which of the two the lock reached first. The decision is `SpokenCallDriver.wants(holding:conversing:phase:enabled:up:microphone:)`, told the hold through `Speaker.onHold` after the speaker has dealt with the keeper, a conversation behind the lock through `conversingChanged` (*The conversation*, below), and the microphone through `Speaker.onMicrophone`. The system activates the session for a call itself, at a call's priority, and holds it for the call's length, so the wait and the reading are not bounded by the ceiling while one is up: `Speaker.capped` under a call re-arms the wait and logs `the ceiling passed under the call; the wait stands`; the `.speaking` progress ceiling stands everywhere, since a reply making no progress for 120 s under a call is a dead engine. The card is the receipt and its hang-up is a mute: every awaited turn's spoken mark goes with its wait (`Speaker.hangUp`, through `settled` to `Harness.answeredAloud`) and what is being read stops — the turn being read as the guest writes it has no wait left and goes the same way, and what the guest writes of a hung-up turn is not begun (`hungUp`, forgotten as the turn ends) — so the reply is read neither then nor at unlock; the card's mute is always fulfilled, and closes the microphone of a conversation behind the lock until the unmute (*The conversation*, below); between turns it changes nothing. Under a call the session is the system's (`AudioSession.call`): `callPlaced` at `CXStartCallAction` sets the record category with the mode the session is in — a change of voice processing waiting for a hold stays waiting, and is applied once the call is over and the last hold and the microphone have gone, as any claim waiting for them is — and activates nothing, and marks the session invalid, and the speaker marks its queue dead at the same moment (`PlayQueue.interrupted`), so a frame of a reply being read is owed rather than scheduled on a session the system is taking (one scheduled there would be heard twice once the activation's rebuild put it back) and a rebuild asked for meanwhile finds `ensureActive` throwing `CallNotActive`; a turn's wait taken while a call is on its way (asked for, `SpokenCall.state` `.starting`, or placed) is held with the keeper down, since the activation starts it again (`Speaker.awaitReply`); `didActivate` (`callActivated`) is what makes the session live, and the speaker rebuilds, restarts the keeper and reads a reply that landed in between (`readWhatWaited`, as for a reply that waited on an open microphone); a call that ends without activating reads it then instead; an ended call's session is still active until the system deactivates it about a second later, and it is `closing` from the end (`callClosing`, by `end` or the card's hang-up) to `callOver`: nothing new goes on it, so a reply landing then waits for the call's end as it does for an activation, and a press waits it out (`AudioSession.settled`, bounded at 3 s, past the call's 2 s closing grace; a hold released meanwhile cancels the press, as one under the permission prompt does, and a tap opens the microphone hands-free once the session settles; the speaker counts the presses opening, so one cancelled while it waited does not read a reply under the press after it) rather than opening a tap the deactivation would cut; `didDeactivate` with the call standing (a phone call holds this one) is an interruption, the engine dead and the hold standing; and under an active call the session stays live through what would otherwise invalidate it — the `.began` posted at the lock screen or as the call takes the session, a queue that found its engine dead (`invalidate` changes nothing while the phase is active; a media services reset still does) — so `ensureActive` returns free and a moment's sound that asks only that the session be live (`ensureLive`) is played, since the system holds it. Nothing calls `setActive` while the phase is the call's: a claim change under it is remembered and applied once the call is over and nothing holds the session. The `voip` background mode is declared for it (`project.yml`, no VoIP push): without it the system refuses the start action as unentitled. CallKit routes an activated call to the earpiece whatever the category asks, so `callActivated` overrides an earpiece route to the speaker (`overrideOutputAudioPort`, a route and not a category or an activation, made before the speaker's rebuild puts an engine on the session) and leaves any other route — AirPods, a car, headphones — as it is; the call's end clears the override (below), and the activation's line names the route or the override. A placing the system refuses is placed again under a new id after 750 ms, up to three attempts (`SpokenCall.placeAttempts`), each refusal logged with its code and the app's state; an end meanwhile places nothing more. A call that is refused three times, never activated inside 10 s, or taken by the call service restarting (`providerDidReset`) ends with the hold standing and the keeper where the call left it: in front the resume brings it back; behind the lock the activation is refused and the reply is read on unlock, as it is with the setting off and the ceiling passed. Over AirPods a call's audio is HFP, narrowband, as a phone call's is. The shape is Daphne's `SessionCall`.

**The conversation.** A microphone open hands-free on a spoken turn as Topo leaves the front is carried into the call rather than dropped (`Apps/Client/Conversation.swift`, one object the app starts beside `MicrophoneWatch`, outside any view), when the call setting is on, the voice activity detector is loaded, the chat's send is installed, no phone call is up (`CXCallObserver`: Topo's call placed over the person's would put theirs on hold) and the session's destination is a send (`Dictation.sends`: dictation into the draft is dropped as the scene goes, as before). A held press, with a thumb on it, is not carried. The conversation begins at `didEnterBackgroundNotification`, asked by whichever of it and the resident's lifecycle hears the notification first (`Conversation.beginIfCarried`, `GuestLifecycle.conversing`), tells the call driver it is on, and stops the caption glances (`VoiceInput.glancing`), which nobody reads behind the lock. The session changing hands to the call is survived by suspending the microphone (`VoiceInput.suspend`: the tap off, the engine stopped and dropped, the generation, owner and samples kept) at whichever of the interruption's `.began` and the call's `CXStartCallAction` comes first — either order is handled, and the log says which (`conversation: begun behind the lock (the microphone came off at …)`) — and resuming it on the call's activation through the press's own path (`VoiceInput.resume`: `ensureActive`, a new engine, voice processing, the one read of the formats, the tap), going on into the same samples. No engine is carried across a session event: a `.began` under the active call (the lock's) suspends the session as any other does, and a phone call taking ours suspends it at the call's deactivation; whenever the call's session is live, a suspended session is rebuilt at once, and a reply that waited meanwhile is judged at that moment. A microphone listening with no samples arriving for 2 s (`Conversation.deafAfter`: a route change stops the engine with nothing to say so) is suspended and rebuilt the same way, once; deaf again with nothing heard since, the conversation ends with what was kept. A session suspended in front by a `.began` with no conversation after it is dropped when the app is active again. Behind the lock the microphone is opened only on the call's live session (from `.active` until the session is taken or the call is ended (`closing`, then over)), since an activation from the background without one is refused and leaves the session invalid.

Each utterance's end is heard on the phone (`Apps/Client/Endpoint.swift`): Silero's voice activity detector through FluidAudio's `VadManager`, fed the sink's samples in 256 ms chunks with its streaming state kept between them, holding an end back until 2.1 s of silence (`Endpoint.silence`, just past the 2 s that cut a speaker off mid-clause in Daphne, which had a model judging the sentence complete and Topo has not); speech shorter than 0.25 s is a cough and ends nothing (`Endpoint.Policy`). The model (`silero-vad-coreml`, `ModelManifest.vad`) is fetched with the ear's and loaded in front (`Endpoint.prepare`, on every foreground), never first behind the lock, where a model's first load has taken minutes. At an end the utterance is decoded as a release decodes it (`VoiceInput.end`), sent through the chat's own send (`ChatView.sendSpoken`: the row, the one nonce, the wait and the mark) in a task of its own, and the microphone opened again at once (`VoiceInput.reopen`, a press with no thumb: the permission not asked, one not already granted refusing), so the send's wait is not time the microphone is deaf; the gap is logged (`conversation: reopened after N ms`). The microphone is closed while Topo reads: a reply that lands over an open microphone with nothing said in it closes it unsent so the reply is read, one landing over speech waits for the utterance's end as any reply waits for a microphone, and the microphone opens again when the reading is done and nothing waits for it (observed on `VoiceInput.listening`, `suspended`, `Speaker.speaking` and `Speaker.waitingForMicrophone`, and asked again after each pass of the detector; a reply closes the microphone only once the detector has judged every whole chunk the sink holds, the one in flight included). A microphone that will not open again ends the conversation. The card's mute closes the microphone, dropping what is open or being decoded, and keeps it closed until the unmute.

The conversation ends at the card's hang-up (what is open dropped, an utterance being decoded included), when the chat stops answering (`send` taken away: a sign-out, a takeover), when the call is over any other way or when Topo comes to the front (`willEnterForegroundNotification`; what is open sent if it held speech or was suspended before the detector judged it, dropped if not), and after two minutes with nothing said (`Conversation.idle`; a wait standing, a reading, a decode or speech under way starts the clock again, and a microphone suspended for the whole two minutes ends it whatever waits, sending what it kept). Every end is `Conversation.stop`, which runs once per conversation: the glances back on, the call driver told it is off, and the resident's lifecycle told (`GuestLifecycle.conversationEnded`, `docs/guest.md`), which is what lets the resident be frozen. The battery this costs is the microphone open behind the lock for the whole conversation — through a turn being answered, since it opens again as the words are sent, and up to two minutes past the last thing said — with a running input engine, the detector every 256 ms and the call's session, against a phone that would otherwise suspend.

**The hand-back.** The record configuration is non-mixable, so the press pauses whatever else the phone was playing, and a session that merely stops rendering never tells it to resume. So when the last hold goes with Topo away (`AudioSession.letGo`), and when a call is over with nothing held, the session is deactivated with `notifyOthersOnDeactivation` (`handBack`), which is allowed from the background where an activation is not: the podcast resumes, and the claims that waited are left for the next audio path, which configures and activates afresh. The speaker is told the hold's drop first, so the keeper's engine is stopped before the hand-back, which an engine still rendering would refuse as busy; a refusal is logged and leaves the session marked as needing configuring. Entering the quiet configuration from the record one — the warm claim going as Topo leaves the front with nothing held, Control Center pulled down over it included — hands back the same way before the mixable session is activated beside it. So a podcast plays on while Topo is in front with nothing said, pauses at the press, and resumes when the reply has been read behind the lock or another app, or, with Topo in front, when it leaves the front. Under a call nothing is handed back until the system says the call is over. The podcast does not play under the reply itself: a call interrupts other audio at the system's level, and the record configuration cannot mix. The call's end and each hand-back log whether other audio is playing, and again a second later (`noteOtherAudio`), since whether the other app takes up again is its own to decide and the log is the only sight of it.

Nothing that is a handle into mediaserverd — an `AVAudioEngine`, its input node, a tap, an `AVAudioPlayerNode` — is created, read, started or spoken to until `AudioSession` has configured **and** activated the session since the last reset; a failure to activate is a refusal, never a fall-through. `AudioSession.ensureActive()` is the call every audio path makes first, and costs nothing on a session that is already valid, so a press still does not pay for the route change the foreground paid for, where it paid for one.

When iOS resets the media server (`AVAudioSession.mediaServicesWereResetNotification`) the session is marked invalid and re-applied if it had ever been configured, a failure there being remembered rather than swallowed; `VoiceInput` cancels any press, dropping its words, a released press's decode included, and drops its engine; and `Speaker` stops the reply, drops its holds and drops the play queue's engine, players and time-pitch unit, which an interruption deliberately does not. Nothing is rebuilt in a handler: the press and `speak` each reactivate and build what they need, so recovery does not depend on which of the two comes first, and Say it again after a reset works with no press before it. A press reads the input node's client and hardware formats and refuses (`no audio input`) when either has no sample rate or no channel or the two rates differ — both are ways `installTap` raises an exception no `catch` sees — and a refusal, like an activation that threw, drops the engine and invalidates the session so the next press rebuilds rather than reading the same dead node. Lifted from Daphne, per `THIRD-PARTY`.

## Model downloads

On-device model weights are downloaded by Topo, never by the libraries: one background `URLSession` (`ModelDownloads`, identifier `zone.hexagon.topo.models`; expensive and constrained network access off, waits for connectivity, not discretionary) so iOS applies the person's data settings and finishes the transfer with the app suspended or gone, with no prompt, toggle or gate of ours. What it fetches is `Apps/Topo/Resources/models.json`, the pinned manifest `scripts/model-manifest.sh` writes from the Hugging Face tree API: `FluidInference/parakeet-tdt-0.6b-v2-coreml` at `ee09c569`, `FluidInference/parakeet-ctc-110m-coreml` at `accdafd8`, `samthehugenerd/Marius-Topo` at `0e896ab5` (the voice's pack, which holds only what the ANE placement loads); each entry is the flattened file list (a `.mlmodelc` is a directory of files on the Hub) with sizes and sha256 digests. Download tasks only, one per file, each verified against its digest and moved into `Application Support/Models/<id>/` with the digest recorded in the directory's ledger (two entries live elsewhere, `ModelStore.homes`, because the library that reads them reads one path and no other: the CTC spotter's is FluidAudio's own `CtcModels.defaultCacheDirectory`, where `VocabularyBoostingSession` reads its tokenizer, and the voice's pack is `Models/pocket-tts/`, where `PocketTtsManager` looks beneath the base directory it is given, with the manifest's paths kept repository-relative so each file lands where the loader looks; a set downloaded under the root before that is renamed into place rather than fetched again); a model is present only when every file is on disk at its size and in the ledger, a partial set carries on from the files it has (resume data where the server gave any), and a bump is a new revision in the script and a re-run. A model asked for after others (`start(_:after:)`, the voice after the ear) is held while any of them is wanted and not present and none has failed (`ModelDownloads.held`; what a pass enqueues and holds is `ModelDownloads.plan`), says so in its status (`queued`, `waiting for the ear to download first`), and is enqueued by one pass at the arrival or failure that lets it go; that pass retries no failure, which stays the next `start`'s. Tasks the session already holds for a held model carry on.

`TopoAppDelegate` (a `UIApplicationDelegateAdaptor`) takes `handleEventsForBackgroundURLSession`, so a transfer that finished while the app was dead is admitted on the relaunch and the handler called. The ear's and the voice's status lines, and the diagnostics `speech` and `voice` rows, say what the session reports: waiting for a network the settings allow, downloading with bytes done of total, verifying, then preparing the model for this phone (the CoreML load, which after an install is the Neural Engine compiling the models afresh) and resident.

The store keeps only what the manifest accounts for (`ModelStore.sweep`, `Apps/Client/ModelHousekeeping.swift`, a function over the manifest rather than a step of the download path), run at launch for every model already present and again after each arrival that makes one present. The protected set is each entry's directory as `directory(for:)` resolves it, never its id, since the voice's id is `pocket-tts-coreml` and its home `Models/pocket-tts`: anything under `Models/` that is none of those homes is removed, and inside a home under `Models/` whose model is present, anything that is not a manifest file, the ledger or a file's resume data. A model that is not present is not swept at all, and a home outside `Models/` (the spotter's, FluidAudio's own cache) is a library's and is never entered. Every folder from Application Support down to what the sweep removes or enters, `Models/` included, is judged with `lstat`: a `Models/` reached through a link is not swept at all, a home reached through one is not entered, a link inside a home is removed as a link and never descended, and the link a skipped `Models/` or home is reached through is left where it stands.

CoreML's compiled Neural Engine bundles land in `Library/Caches/<bundle id>/com.apple.e5rt.e5bundlecache` on a model's first load and are kept across installs (`CompileCache`, `Apps/Client/ModelHousekeeping.swift`), so that an update whose models are the same bytes may skip compiling them again — whether CoreML's key for a compiled bundle survives an install is unmeasured, and a generation compiled under another OS build or model pack stays until iOS purges Caches under pressure or the person clears it. The settings sheet's `Clear compiled model cache` sets a request (`topo.models.clearCompileCache`) and the next launch removes that directory whole, and nothing else in Caches, before the ear and the voice are made (`ModelHousekeeping.launch` in `TopoApp.init`, since a debug build's start loading as they are made), so no compile is writing into it as it goes; the request is removed only once the directory is gone or was never there, so a removal that fails is tried again, and nothing is removed when Caches or the app's folder in it is reached through a link. Under the `models` category, every launch with no clear pending logs `compile cache: kept for install <key>`, with ` (new install)` after it at an install's first; a clear logs `cleared on request`, or `absent on request` when there was nothing there, and a refused one `not cleared`. An install is the `LC_UUID` of the image the app's code is linked into (the main executable in a release build, `Topo.debug.dylib` in a debug one) together with the app bundle's path, whose container directory every install makes new, compared with the one last recorded in defaults (`topo.models.compileCacheInstall`), because `CFBundleVersion` is 1 on every development install.
