# Topo

One always-on mind per person, every Apple device a limb. The design is `docs/design.md`; read it before changing anything, and keep it and this file describing what **is**, never what was or what is planned.

## Stack

- Swift and SwiftUI, except in Womble, which is as old as its devices. Three bundles; the first two are targets of one Xcode project, `Topo.xcodeproj`, generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` (edit the yml, run `xcodegen generate`, commit both; a new file under `Apps/`, `Tests/Client` or `Tests/ClientUI` belongs to no target until that runs, and xcodebuild reports success without having compiled it):
  - **client**: iOS, iPadOS, watchOS, tvOS. One codebase (`Apps/Client`, with `Apps/Shared` for what the hub shares) in three targets, `Topo`, `TopoWatch`, `TopoTV`; role (primary, viewer, limb) is decided at first launch from the CloudKit records. Only the iOS target can sign in; the watch and TV builds show a viewer screen.
  - **hub**: `TopoHub`, the macOS menu-bar app bundling the Claude CLI and the channel servers. The only target that runs resident code. It holds the primary lease, answers probes for it, shows the pairing code (`docs/pairing.md`) and the devices on the Apple ID. An unsigned build has no iCloud entitlement and runs against the in-memory database instead, and says so in its menu.
  - **Womble**: the viewer-only bundle for old devices, in its own project (`Womble/`, generated with XcodeGen) because it targets iOS 12 — UIKit, completion handlers, no concurrency and no scenes. It reads the same CloudKit records without depending on TopoCore, whose minimum is iOS 17; no mic, no models, no sign-in.
- Build check for a PR: `scripts/build-ish.sh`, then `xcodebuild -scheme Topo -destination 'generic/platform=iOS Simulator' build`; every scheme resolves `Packages/TopoUserland`, whose framework the script builds and nothing commits. No entitlements or team are set, so every target builds unsigned for a simulator; `CODE_SIGNING_ALLOWED=NO` for the macOS hub.
- Sign in with Claude is `Packages/TopoAuth`: the Claude Code CLI's OAuth client (authorization code with PKCE against `claude.com/cai/oauth/authorize`, exchange and refresh at `platform.claude.com/v1/oauth/token`, the CLI's client id and scopes). The browser redirects to a loopback listener in the app; if that cannot bind, to the hosted callback page, whose `code#state` the user pastes. Tokens live in the device keychain, never synced; only the primary and the hub ever hold one. The ordinary tokens are read and refreshed through one `StoredTokenProvider`, made in `TopoApp` and handed to the harness and to the guest's hand-over (`DebugRun.handOver`): a refresh token is single-use, a second grant on a spent one is refused, so the provider has one refresh in flight at most, held as a `Task` every caller of an expired set (or of `refresh()`) awaits for its tokens or its error, and cleared as it ends so a failed refresh is not kept. The phone's sign-in (`SignIn(guestStore:)`, given `KeychainTokenStore.guest`) is two authorizations, as `claude login` and `claude setup-token` are two, so the person approves twice: the ordinary login, then the guest's token (`ClaudeOAuth.Grant.longLived`), asked for as `setup-token` asks — its own code and verifier, `user:inference` alone on the authorize URL and `expires_in: 31536000` on the code exchange — of which only the access token is kept, as its own keychain item beside the ordinary tokens. The second never touches the ordinary tokens: they are their own exchange's, refresh token included, because a refresh grant asking for `user:inference` rotates the refresh token it spends into one that will not refresh the ordinary scopes. With a loopback listener the login's callback answers with a redirect to the second authorization (`LoopbackCallback.redirectOnSuccess`), so one browser sheet carries both; without one the sign-in screen opens the second (`SignIn.Phase.approvingGuest(opening:)`) and its code is pasted like the first. A second authorization declined (Skip, or the sheet closed) or refused still signs in, with no guest token kept. Sign-out clears both. `GuestCredential` hands the guest the long-lived token while it is unexpired and otherwise the ordinary access token, refreshed first when it is about to expire. The debug userland launch prints the guest token's scope and days left as `userland: mint scope:` (or that none is held) and refreshes the ordinary tokens once, asking for their own scopes, printing what that refresh granted as `userland: ordinary refresh scope:` or its refusal, never a value.
- One container, `iCloud.zone.hexagon.topo`, private database, custom zone `Topo`. Every bundle reads and writes that one, so the identifiers are a contract between them and not a per-target setting.
- The phone harness is `Packages/TopoTurn`: `TurnRunner` (take the primary lease, append the person's turn under a nonce the caller keeps until the turn is known to be in the log, ask the `Brain`, append the reply as its child in one atomic batch with a lease heartbeat; a failed answer leaves the person's turn in the log, a lost lease leaves the reply out) and `Brain` (`Sources/TopoTurn/Brain.swift`), the one seam between the runner and a model: a `BrainRequest` (the log as read, the person's turns being answered, the last 40 turns, the reply's parents and nonce, the model) in and a reply out, told when a reply is in the log (`landed`), asked which person turns it holds as unresolved and whether it owes the log a reply it finished before a crash. The runner writes an owed reply, under its own nonce and parents, before it writes or answers anything else, and `answerPending` does not answer an unresolved head. The only brain the app composes is Claude Code in the guest (`GuestBridge`, below; `Harness.standard`), and there is no fallback from it: `MessagesAPIBrain` over `MessagesAPI` (one non-streaming `POST /v1/messages` with the OAuth bearer token, the `oauth-2025-04-20` beta and the Claude Code CLI's identity line as the first system block; `Transport` is the seam the tests mock) is compiled for the suites, which run the harness over both brains, and nothing in the app constructs it. A reply's nonce is a hash of the turns it answers, so a retry or a second brain finds the one reply. The row at the end of the transcript is drawn against that contract: it holds the words under the nonce `willSend` gave them until `Harness.said(nonce)` is true, which is what the outbox's own retry is keyed to, so a turn that never settled stays in flight and one whose reply failed clears, its turn standing in the log. `Harness.withdraw(nonce)` is the way back from the first: it takes the entry off the line so the words can be said again as one turn under one nonce, and it asks the log before it does — a turn already there cannot be taken back, and neither can one whose log could not be read, since a read that failed is not an answer. It is refused while an attempt is running, which is a write that may be landing as it is asked. The row is `NextTurn` (`Apps/Client/NextTurn.swift`) rather than the chat screen's own state, because what it holds outlives the screen: the line is on disk, so a chat appearing over an unsettled line takes the oldest words on it whose turn the read did not find in the log back up as the turn on its way (`resume(from:)`), which is where the way back from a turn that never landed is and where it is most needed. The oldest still owed and not the head, since the head can be a turn that reached the log and lost its acknowledgement, with a turn said behind it still owed; words already in the log belong to the transcript and not to the row, whichever entry they are. It resumes nothing over a row already in use. It refuses a landed turn's words while a turn is on its way (`edit(_:in:)`), since the row draws the words being sent until they land or are taken back. `answerPending` is the log's own path for a limb's words: the primary answers any person turn at the log's head, whoever wrote it, one reply continuing every head; the phone runs it every five seconds while the chat is open, which is also how a reply that failed is retried. A phone that is not primary writes the person's turn as a limb and the primary answers it there. The model is a setting: Sonnet 5 by default, Opus 5 or Fable 5.1 from the settings sheet — except in a debug build, which is pinned to Haiku 4.5 (`ClaudeModel.pinned`, through `ClaudeModel.effective`, which `MessagesAPI.complete`, the bridge and the resident's first launch all apply, so every caller obeys it, not only the picker), because every debug build here is signed into a real subscription and a stray turn spends it. The setting reaches the guest as `--model`: a change restarts the resident process at its next idle moment, never mid-turn (`GuestSession.use(model:)`).
- Voice on the phone is push to talk (`Apps/Client/VoiceInput.swift`): hold the microphone to talk and release to send, or tap to open it until the next press; the first-run answer is hold-to-talk only. The first press asks for the microphone, which is the only permission a press asks for, and nothing is asked before it. Recognition is on the device, and it is the phone's one ear: Parakeet-tdt-0.6b-v2 through FluidAudio (`Apps/Client/Ear.swift`, the iOS target only), the audio so far decoded bare every second for the caption and the whole utterance decoded and rescored at the release against the person's own vocabulary (`Apps/Client/Vocabulary.swift`: empty until they add to it, since none of anyone else's words are theirs; edited from the settings sheet; kept in this device's defaults rather than the vault, because a vocabulary is this device's ear and not the person's memory). An edit rebuilds the spotter's session live, so a word works from the next press; the gate is constant (no aliases, similarity 0.65, three characters minimum: Daphne's measured config, and the reason additions are safe). The session is a layer over Parakeet, not a condition of the ear: an empty list builds none, and one that cannot be built leaves Parakeet recognising bare, with the reason in the diagnostics `speech` row. The models are not in the bundle: about 540 MB of CoreML that `ModelDownloads` (`Apps/Client/ModelDownloads.swift`) fetches from the first foreground on (`VoiceInput.prepare`) into the app's Application Support, where FluidAudio loads them from, told to touch no network of its own (`ModelHub.offlineMode`). Until they are resident, or if they fail to load, a press is refused with the ear's own status line and nothing touches the audio session or the engine; both surfaces' microphone buttons, the chat's and the first run's, are dimmed whenever a press would not open one (`VoiceInput.canListen`, the microphone denied or the ear not resident, read from the state as it is, so the load finishing undims them with no press in between); the first run's copy about allowing it in Settings stays tied to `denied` alone, since an ear that is still downloading is a wait rather than something to go and allow; a decode that throws at the release sends the caption the glances left, and nothing when there is none, with the error in the debug `Capture`. The diagnostics screen's `speech` row says which state the ear is in. A spoken turn's reply is read aloud (`Speaker`; a setting in the settings sheet), a typed one's is not; holding any of Topo's turns in the transcript opens a menu that says it again, which is how a typed turn's reply is heard (`Replay` in `Apps/Client/TranscriptView.swift`, threaded from the chat screen, so the watch, the television and a viewer offer nothing). The item reads Stop while the speaker is speaking, and is gone while the voice is not resident. The voice is on the device, and it is the phone's one voice: Kyutai's Pocket TTS through FluidAudio (`Apps/Client/Voice.swift`, the iOS target only), speaking its stock `eponine`: each person names their own mind, so the default voice is a neutral stock one rather than anyone's blend. Every stage is placed off the GPU — the conditioner, the flow-LM and the fused flow decoder at `.cpuAndNeuralEngine` on the rank-4 `.ane` variants, Mimi at `.cpuOnly`, where the port found it fastest and where its fp16 state feedback does not beep; `.all` is never used, because it lets a stage fall to the GPU. A reply is cut into sentences on sentence-final punctuation, each synthesised behind the one before as a stream of 80 ms frames pushed to one player node as they decode, so the wait is the first frame. Pocket has no pace of its own, so the pacing is the play queue's `AVAudioUnitTimePitch` at `Voice.tempo`, 1.20 with the pitch untouched: a per-speaker constant, explained in the doc comment, and the only thing between the voice's frames and the speaker. `Speaker` reads the clock through an injected `now` (the continuous clock in production), so the debug report's two measurements are arithmetic a unit test drives rather than a race it has to wait out. The model is not in the bundle either: about 351 MB (the four CoreML bundles the ANE placement loads, the constants and the tokenizer beside them, and the one speaker) that `ModelDownloads` fetches on the same cue (`Speaker.prepare`) and FluidAudio loads from the store, told to touch no network of its own. A reply is not read aloud at all when the model is not resident or fails to load — there is nothing to fall back to — and the diagnostics screen's `voice` row says which state the model is in; a debug build launched with `TOPO_DEBUG_VOICE=loading` (`DebugRun.voice`) holds the voice unloaded, and one launched with a directory loads Pocket from there instead of downloading it, which is what the talk lane does. One `VoiceInput` for the app and one gate on its microphone, enforced: a surface pressing while another holds it is refused, since two gates on one input answer the same utterance twice; the two surfaces are never mounted together and each cancels its session on disappearing. Every press is a session with a generation, so a release during the permission prompts starts nothing, a late recogniser result or a second release belongs to no session, and what one session heard cannot become the next one's turn. The audio session, the idle timer and the background hold are process-wide, so `AudioSession` counts claims on them rather than assigning them; the record configuration is warmed on the foreground so the press does not pay for the route change. A block handed to the system from a main-actor context and called back off the main thread (the input tap, on the audio thread) is written `@Sendable`: without it the closure is main-actor-isolated by inference, and Swift 6 opens it with an executor check that traps off the main thread, past any `catch`. A spoken turn's reply is heard behind the lock, in a pocket, or in front of another app: the iOS target holds the `audio` background mode (`Apps/Topo/Info.plist`), and under it iOS runs the process only while an engine of its own is running, so the play queue keeps a second player node at no volume looping a fifth of a second of zeroes (the keeper) for as long as a hold stands. The process is held by the running engine and the keeper is only what it renders, so with no hold nothing runs: the last hold going stops the keeper and the engine with it, its nodes left attached, and the next hold or frame starts it again through the same refusal path as any other. An engine left running under a stopped keeper is a phone that never suspends. The hold is counted like the other two, with two kinds of owner: `.awaitingReply(nonce)`, one claim per spoken turn outstanding — the chat lets a second press append while the first turn is in flight, and each turn holds for itself — taken at the release and dropped when that turn's reply is handed to `speak`, when the harness says that turn failed (`Harness.onTurnFailed`, named as the turn ends, since the screen's error line cannot say whose turn stopped), when a press, a Stop, a sign-out or a reset ends things, and at its own ceiling of 120 s; and `.speaking`, taken in `speak` after `ensureActive` and dropped when every sentence is made **and** the queue is drained, since a queue that empties between two sentences is not the reply's end. Nothing is held for a turn whose reply could not be heard anyway — Read replies aloud off, or the voice not resident at the release — and a typed turn asks for none, so the app suspends behind the lock as it always did. Both owners are bounded by the same 120 s ceiling, `.awaitingReply` from the release and `.speaking` from the last frame scheduled or played back, so a hold outlives a dead reply by the ceiling at most; the ceiling's line says which way the wait ended, a reply that never landed or one that landed and was refused, with the count, because the two end the same wait and only that tells a run's log them apart. An `AVAudioSession` interruption is not the end of either: iOS posts a `.began` at the lock screen with no call and no Siri in it, so `.began` stops the player, keeps the buffers nobody has heard and leaves the hold standing — and a frame arriving while the engine is dead is added to what is owed rather than played, since restarting a dead engine throws and the voice reads that throw as the sentence's end (the notification's type, reason, `wasSuspended` and options are logged), and `.ended` — or the `AVAudioEngineConfigurationChange` a real interruption's end posts — rebuilds through the same path as the lock's category flip, whenever anything is owed or the queue is dead, building an engine from nothing if an earlier refusal left none. Every way the recovery path can fail ends in one refusal: the engine is dropped, the owed frames and the dead mark are kept, the session is invalidated, and the next end, change or reply tries the whole thing again — an activation refused, an engine that will not start, a frame that could not be played, a keeper that could not be started. A reply arriving on a dead queue rebuilds it first and is refused when that rebuild is, and one whose hold cannot be honoured — the keeper's own engine refusing to start — is refused the same way, since a reply taken on an engine that will not start would clear its turn's mark and end its wait for a reading that never happens. The hold's count tells the speaker about every claim taken or dropped, not only about the answer changing, so a claim arriving while another already stands is the chance to start a keeper an earlier refusal left down. Nothing is reported as playing, or as held, that is not. The format survives a refusal, because it is the voice's rate and not the engine's and a frame arriving while there is no engine at all is still made against it and owed; only a media services reset drops it. A reply cut by a short call carries on after it; a reply the speaker refuses (`speak` answers whether it took it) is still owed, so its turn stays marked spoken, its wait stands to its ceiling, and the next pass offers the reply again. The decision to read a reply aloud is `Harness.onReply`, which the chat installs beside `PushWake`: it fires for a reply this phone wrote and for one a pass read that another primary wrote, once per turn, because behind the lock nothing is drawn and whether a view's observer runs is SwiftUI's to decide. A reply is recorded as offered only when a handler took it — one that was not there, and one that could not act, both leave it to be offered again — and installing a handler replays what arrived unheard, since the screen reads the log and sends what an earlier launch left owed before it installs. Of more than one owed reply the newest is read and the older are cleared unread: a person coming back is owed the answer to the last thing they said rather than a backlog read at them, and each reply spoken cuts off the one before it anyway. The handler reads the mark and not the setting, since the setting governs what the next release decides and not what a turn already released is owed. Whether a turn is spoken is the wait's own answer — `Speaker.awaitReply` answers both `spoken` (the reply will be read aloud when it lands, which is what marks the turn, and is true in the foreground whatever the audio is doing) and `held` (the keeper is actually rendering for it); the chat records the mark from `spoken` and states no condition of its own, so no later launch turning the setting on reads an old reply aloud, and a keeper that would not start is reported as the refusal it is rather than as a hold. The mark is the harness's, and on disk (`topo.harness.spoken`, the twenty most recent nonces owed a reply, cleared per turn as its reply is read and by a sign-out): the words said before the app went away survive the relaunch in the outbox, so what makes them a spoken turn has to survive with them. Signing out, and the far end of a takeover, stop the speaker: the reply in the ear goes with the login. While any hold stands the session is not reconfigured: a claim change — the warm record claim dropped at the lock, or any other — is remembered, so the session that was active at the release stays active and untouched, whatever category it was in, until the reply has been heard. What is remembered is applied when the last hold goes and the app is in front; behind the lock, where the last hold going is as likely a reply ending as the app coming back, the session is marked as needing configuring instead and the claims are left for the next path that wants audio — the next `ensureActive`, or the foreground's own warm claim, which applies them as it changes. Activating or reconfiguring a non-mixable session from the background is refused (`cannotInterruptOthers`), and a session left invalid by that refusal is one every later `ensureActive` tries the same refused call on, which is a reply spoken only on unlock; an already-active session goes on rendering behind the lock under the `audio` mode, so `ensureActive` at `speak` is free there and nothing sets a category or activates a session from the background. A claim's configure failing is logged with its error rather than thrown, since a claim is not an audio path and the path that is meets it at `ensureActive`. What can still change under a hold is an interruption, whose end is exactly when iOS allows the session back: the queue rebuilds for its own engine on an `.ended` or an `AVAudioEngineConfigurationChange` — `ensureActive` first, then a fresh engine at the same format, every buffer not yet played back scheduled again in order under a new epoch so the discarded completions move nothing, and the keeper back if a hold stands. Resuming a reply after an interruption ends is not built. Nothing that is a handle into mediaserverd — an `AVAudioEngine`, its input node, a tap, an `AVAudioPlayerNode` — is created, read, started or spoken to until `AudioSession` has configured **and** activated the session since the last reset; a failure to activate is a refusal, never a fall-through. `AudioSession.ensureActive()` is the call every audio path makes first, and costs nothing on a session that is already valid, so a press still does not pay for the route change the foreground paid for. When iOS resets the media server (`AVAudioSession.mediaServicesWereResetNotification`) the session is marked invalid and re-applied if it had ever been configured, a failure there being remembered rather than swallowed; `VoiceInput` cancels any press, dropping its words as an interruption does, and drops its engine; and `Speaker` stops the reply, drops both holds and drops the play queue's engine, players and time-pitch unit, which an interruption deliberately does not. Nothing is rebuilt in a handler: the press and `speak` each reactivate and build what they need, so recovery does not depend on which of the two comes first, and Say it again after a reset works with no press before it. A press reads the input node's client and hardware formats and refuses (`no audio input`) when either has no sample rate or no channel or the two rates differ — both are ways `installTap` raises an exception no `catch` sees — and a refusal, like an activation that threw, drops the engine and invalidates the session so the next press rebuilds rather than reading the same dead node. - On-device model weights are downloaded by Topo, never by the libraries: one background `URLSession` (`ModelDownloads`, identifier `zone.hexagon.topo.models`; expensive and constrained network access off, waits for connectivity, not discretionary) so iOS applies the person's data settings and finishes the transfer with the app suspended or gone, with no prompt, toggle or gate of ours. What it fetches is `Apps/Topo/Resources/models.json`, the pinned manifest `scripts/model-manifest.sh` writes from the Hugging Face tree API: `FluidInference/parakeet-tdt-0.6b-v2-coreml` at `ee09c569`, `FluidInference/parakeet-ctc-110m-coreml` at `accdafd8`, `FluidInference/pocket-tts-coreml` at `91748676` (the English v2.1 pack, and of it only what the ANE placement loads); each entry is the flattened file list (a `.mlmodelc` is a directory of files on the Hub) with sizes and sha256 digests. Download tasks only, one per file, each verified against its digest and moved into `Application Support/Models/<id>/` with the digest recorded in the directory's ledger (two entries live elsewhere, `ModelStore.homes`, because the library that reads them reads one path and no other: the CTC spotter's is FluidAudio's own `CtcModels.defaultCacheDirectory`, where `VocabularyBoostingSession` reads its tokenizer, and the voice's pack is `Models/pocket-tts/`, where `PocketTtsManager` looks beneath the base directory it is given, with the manifest's paths kept repository-relative so each file lands where the loader looks; a set downloaded under the root before that is renamed into place rather than fetched again); a model is present only when every file is on disk at its size and in the ledger, a partial set carries on from the files it has (resume data where the server gave any), and a bump is a new revision in the script and a re-run. `TopoAppDelegate` (a `UIApplicationDelegateAdaptor`) takes `handleEventsForBackgroundURLSession`, so a transfer that finished while the app was dead is admitted on the relaunch and the handler called. The ear's and the voice's status lines, and the diagnostics `speech` and `voice` rows, say what the session reports: waiting for a network the settings allow, downloading with bytes done of total, verifying, then preparing the model for this phone (the CoreML load, which after an install is the Neural Engine compiling the models afresh) and resident. The store keeps only what the manifest accounts for (`ModelStore.sweep`, `Apps/Client/ModelHousekeeping.swift`, a function over the manifest rather than a step of the download path), run at launch for every model already present and again after each arrival that makes one present. The protected set is each entry's directory as `directory(for:)` resolves it, never its id, since the voice's id is `pocket-tts-coreml` and its home `Models/pocket-tts`: anything under `Models/` that is none of those homes is removed, and inside a home under `Models/` whose model is present, anything that is not a manifest file, the ledger or a file's resume data. A model that is not present is not swept at all, and a home outside `Models/` (the spotter's, FluidAudio's own cache) is a library's and is never entered. Every folder from Application Support down to what the sweep removes or enters, `Models/` included, is judged with `lstat`: a `Models/` reached through a link is not swept at all, a home reached through one is not entered, a link inside a home is removed as a link and never descended, and the link a skipped `Models/` or home is reached through is left where it stands. CoreML's compiled Neural Engine bundles land in `Library/Caches/<bundle id>/com.apple.e5rt.e5bundlecache`, a generation per install that nothing takes away, so that directory, and nothing else in Caches, is removed whole on the first launch of a new install (`CompileCache`; not at all, and nothing recorded, when Caches or the app's folder in it is reached through a link), before the ear and the voice are made (`ModelHousekeeping.launch` in `TopoApp.init`, since a debug build's start loading as they are made). An install is the `LC_UUID` of the image the app's code is linked into (the main executable in a release build, `Topo.debug.dylib` in a debug one) together with the app bundle's path, whose container directory every install makes new, so a byte-identical build installed over itself is a new install too; it is compared with the one last recorded in defaults (`topo.models.compileCacheInstall`), because `CFBundleVersion` is 1 on every development install, and a bundle path that moved on a plain launch would cost one recompile and no file; the key is recorded only once the directory is gone or was never there, so a removal that fails is tried again on the next launch.
- The guest is an arm64 Alpine userland run inside the app's own process by iSH's kernel: `Packages/TopoUserland`, linked into the iOS target alone. Its C side is `TopoIsh.xcframework` (iOS device and arm64 simulator slices, gitignored under `Packages/TopoUserland/Frameworks/`), which `scripts/build-ish.sh` builds from `OpenMinis/ish-arm64` at its pin with meson `guest_arch=arm64`, `kernel=ish`, `engine=asbestos` and exactly the patches in `patches/ish/` — the memory brake's refresh hook (`ish_mem_refresh_hook`, `kernel/mmap.c`: on a sample older than two seconds the kernel asks the app for a fresh one before it fails closed), `pidfd_open` on a child that has exited and not been reaped (`kernel/pidfd.c`: it opens and reads as exited, as on Linux, rather than failing `ESRCH`; Claude Code's runtime opens a pidfd on every child it spawns, and its `ESRCH` path registers fd 0 with its own epoll, so its stdin reader's registration fails and it exits 0 having read nothing), and the `offsets` source meson leaves out of the fork's own executable — linking the fork's libraries, its fakefs importer and `deps/libarchive` (built with no crypto library and no XML reader); `deps/linux` is never fetched and `deps/libapps` never linked. The script refuses a checkout that is not the pin, a patch that does not apply cleanly (`git apply --check`), a populated `deps/linux`, and a meson configuration read back that is not those three options, and skips when the framework's inputs stamp matches the pin, the options, the patches, the glue and the script itself; `scripts/tests/build-ish-test.sh` holds each refusal red, and the PR check builds the framework before any `xcodebuild` and asserts both slices export `ish_mem_refresh_hook`. Building it needs meson, ninja and Homebrew's llvm and lld, since the guest's VDSO is an aarch64 ELF Apple's linker does not make. The glue is `Packages/TopoUserland/Guest/topo_ish.c` behind `topo_ish.h`: import, combining the rootfs and Alpine packages into one archive for it, boot, spawn (stdin from `/dev/null`, or a pipe whose write end the app keeps, `F_SETNOSIGPIPE`, so a write to a program that has gone is `EPIPE` and never a signal), wait, signalling every guest task but init under the pid table's lock, counting what of a list of pids still runs (reaping, as init, those orphaned to it, which init never reaps), a line about one task for a log (its name, thread and parent, whether it is running, exiting or a zombie, the last syscall it entered, a pending `SIGKILL`), a realfs bind mount of a host directory, a link in the fakefs, and the brake's feed, compiled into the framework. A task is started with `SIGUSR1` unblocked on the starting thread: every task thread, and every thread it forks, inherits that thread's mask, a GCD worker blocks `SIGUSR1`, and `SIGUSR1` is how iSH interrupts a task parked in a host call, so with it blocked no signal, `SIGKILL` included, reaches a `sleep` or a blocked read. A second `SIGKILL` to a task that already has one pending wakes its thread again, since iSH queues a pending signal without waking and its one wake is lost if it lands between the syscall's check and a host `nanosleep`. `Guest` boots one kernel per process on a fakefs — init never runs a program, since init exiting halts the process — refuses every boot after the first whatever it answered, names the guest `topo` rather than letting the kernel copy the host's name into its 65-byte field, and runs a program as init's child over host pipes, returning its output and its exit status (128 plus the signal for a signal), in `Guest.environment` unless it is handed another: root's home, the usual path, `SHELL=/bin/bash` (what Claude Code's Bash tool runs in, inherited by the resident and everything it starts) and `DISABLE_AUTOUPDATER=1`. The package suites run with `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1`, which pins that pool to one thread, so anything that blocks one hangs there rather than on a runner. Sign-out takes the folder away — the memory is the person's and lives in their iCloud, and a phone that is signed out keeps no copy — and a sync in flight at that moment is cancelled, writes nothing, and the folder goes once it has stopped, so a half-finished pass cannot put a file back. The diagnostics screen's `memory` row says where the home is, when the folder was last in step and what the last sync did, and names the first few files a pass skipped with the reason it skipped each — a count alone is a device run that has to be repeated to learn anything. `look.json` in the root is a file of the vault like any other, and the one the app reads for itself: after each pass that reached the end of itself, from the folder the home names, through the mirror's own coordinated read (`VaultMirror.contents(at:)`) and never by opening the folder — after the sync and not during it, since a second coordinated access of one folder held from inside the first is two accessors from one process. It is decoded field by field (`Apps/Shared/LookDocument.swift`): a field absent, misspelt, of the wrong kind or outside the range its field is read in falls back to the compiled default for that field alone, every other override stands, and the reason is on the diagnostics `look` row along with the file's state — no file, the count of fields it set, or why nothing could be read from it. Colours are hex pairs, light then dark, as `Theme` writes them (`Theme.colour(light:dark:)`); materials are named; numbers are points, degrees or seconds, each in a range named where it is read, and what has to be pressed or read is bounded below as well as above. The environment is set from it on every sync, so a document the mind wrote is worn from the next one with no relaunch; a sign-out takes it away with the folder. The watch and the television draw the same transcript from the same look and have no composer, badge, sheet or row, so the transcript's and the bubble's fields are all of it that reaches them. An empty file is a note with no text in it, not a file that could not be read: `FileHandle.readToEnd` answers nil at the end of a file, which an empty one is from the start, and every note Obsidian has just made is empty. A debug build launched with `TOPO_DEBUG_LOOP_SECONDS` waits that long between passes instead of five seconds, which is how a device test tells a revision that arrived by push from one the loop would have fetched anyway. The home is the bookmark, one keychain item beside the tokens, because a bookmark is a capability to the person's files and not a setting: no bookmark is the local home, one that resolves is iCloud Drive, one that does not is `lost` and stops every pass until the person picks again or comes back to the phone. The picker's grant is the whole of the permission story — no entitlement of ours reaches iCloud Drive or Obsidian's container — and what it hands over is judged against this device's own ubiquity root, `<user>/Library/Mobile Documents` read off `NSHomeDirectory()`, rather than against a path component of that name: a vault one level under `iCloud~md~obsidian/Documents` is the pick Obsidian opens, iCloud Drive's own root is a vault made at `Obsidian/<the mind's name>` under it, and anything else is refused with the reason and the home unchanged. The bookmark kept is to what was picked, so a root pick keeps root access, and the vault folder under it is derived by the same rule at every launch. Every access is started and stopped on that URL and never on a child of it, and it is held for the whole pass. The move (`Apps/Client/VaultMigration.swift` over `VaultTransfer` in TopoCore) is one coordinated write over both folders with one commit point: every file and the `.topo/mirror.json` baseline are copied and read back by digest, the write of the home to the keychain is the commit, and the source is emptied of what was carried only after it — name by name, then the folders left empty, and the folder itself only when it is this app's own, since a folder in the person's iCloud Drive is theirs. What counts as left behind is a file the move carried and could not take away, never a name it skipped on purpose — `.obsidian` was the person's and is not the memory's to account for, still less to remove. A removal that will not finish is said in the Memory screen and the `memory` row, with a control to try again that runs that same cleanup against the same names, under the grant the stranded folder carries rather than the home's (by then the home is the other folder), and is never a rollback. The screen's controls are read against all three homes: picking while the memory already lives in a picked folder moves it out of that one, picking while the home is lost is refused because there is nothing to carry out of a folder that cannot be reached, and a lost home comes back by dropping the bookmark alone — there is nothing to carry, and the folder fills from the store. A sign-out during a move waits the move out before it clears the bookmark and takes the folder away. A file already in the destination keeps its name and the carried one lands beside it under a conflict copy's name (`ConflictCopy`, the rule `MemoryVault` reads a fork with). An iCloud Drive home has files whose bytes are not on the phone, so each pass asks for what is not downloaded and waits with a bound (`Apps/Client/VaultDownloads.swift`, a regular file whose status is `.notDownloaded` and nothing else: a folder has a downloading status of its own, a file with no status is not a ubiquitous item and asking for one throws, and `.downloaded` is a local copy that is merely out of date); what has not arrived is a file the mirror reports as unreadable and acts on in neither direction. Sign-out drops the bookmark and takes away the folder in this app's container; a vault the person keeps in their own iCloud Drive is theirs and is left where it is. The chat shows one card above the composer offering the move, once, when the vault holds more than a handful and the home is still local; Not now is for good, in defaults.
- **CloudKit is truth, sockets are speed.** State (transcript log, pairing record, primary lease) lives in the private CloudKit database; the push that wakes the primary, direct sockets and the punched tunnel only make live turns fast. With no socket the app still works off the records, just slower.
- The transcript is an append-only log: one record per turn, per-device sequence numbers, never overwrite. The role record (`role/<device>`, `DeviceRole`) is how one device changes another's role, written by the taker in the make-primary control; a device reads its own at launch and on each answering pass. The primary lease is the one mutable record: atomic claim, 10s expiry judged on `mach_continuous_time` (`PrimaryLease.continuousUptime`) as well as the wall clock — not `CLOCK_MONOTONIC`, which on Darwin is time-daemon-disciplined and can follow a backward system-time step, the case the fence exists for — 5s heartbeat the holder runs itself, probe-driven handover, a displaced holder yields rather than reclaims, and only the hub takes the lease from a live holder. A turn written as primary rides in one atomic batch with a heartbeat of the lease (`TurnWriter.append(…, renewing:)`), so a displaced device writes nothing; the phone's reply uses it and the hub's turns will.
- Core logic ships as Swift packages whose tests run against an in-memory database behind the package's own CloudKit protocol; no test needs a signed-in device. `Packages/TopoCore` is the log, the lease, the device directory and the memory (`MemoryStore`, one create-only record per revision; `MemoryVault`, which reads those revisions as files, with the newer head of a forked path the file and every other head a conflict copy under Obsidian Sync's name; and `VaultMirror`, the actor that keeps a directory on disk in step with them both ways): `RecordDatabase` is the protocol over the CloudKit calls used (compare-and-set save, fetch, query, and the whole of a type from the zone's change feed, which is how the log and the device directory are read: a match-all query needs a queryable index on the record name that the development schema never builds), `CloudKitRecordDatabase` is the adapter, and `TopoCoreTesting` holds the in-memory database with CloudKit's conflict semantics. A container nothing has written to answers two more ways, both absorbed by the adapter and both invisible until a fresh account takes its first turn: a query on a record type the development schema has never seen fails `unknownItem` rather than returning nothing (answered `[]`), and an empty string list on a first save makes the server refuse the whole atomic batch with "Syntax error in request" (left off the wire, since a list with no elements has no type the schema can be grown from). `Packages/TopoLink` is the socket layer: the lease probe over TCP (one line each way), the listener that answers it and advertises the device as `_topo._tcp`, and the browse that says who is on the LAN; its tests run on loopback. `swift test` from a package directory runs its suite. `TopoTests` drives the phone's `Harness` itself over the in-memory log, with the Messages API behind a scripted `Transport` (the unsettled line on disk and its relaunch, a failed model call, not-primary and displaced turns, the role-record handover, the answering loop). No automated suite reaches the CloudKit service: `CloudKitMappingTests` covers the adapter's record and error mapping offline, so the account, the schema, partial failures and the zone change feed are exercised only by Womble's manual self-test (`CloudKitSelfTest`) on a signed-in device.

## Working here

The process — who plans, who builds, who reviews, and in what order — is `docs/process.md`. The short form:

- Every change lands as a PR on a `buddy/<topic>` branch from its own worktree, opened as a draft. The description is the contract: what was done, and a **Proof** section as a checklist of what was verified. A test only a physical device can show is an unchecked `- [ ] device: …` box; auto-merge waits until it is ticked.
- Never force push. One concern per PR; a finding on an open PR is fixed on that branch, never in a second PR.
- Prefer what exists: stdlib, then a platform framework, then an already-linked dependency, before new code or a new dependency. Nothing GPL from others ships in a bundle unless its holders waive the App Store conflict, as iSH's do; the fork is the one such piece. Every borrowed piece is attributed in `THIRD-PARTY`.
- Docs describe the present state. When you change behaviour, change the doc to match; do not narrate the change.
- A fix round is scoped: fix the findings you were sent, on the same branch, and say which commit answers which. The re-review is not scoped: it is given the previous verdict and the diff since, answers each earlier finding closed, still open or moot, and reads the whole PR again, so anything you change beyond the list is new surface for it. A new finding in code the fix did not touch blocks only at the blocking bar (a record lost or corrupted, the primary split, a secret leaked, the description untrue at runtime); below it, it is reported non-blocking and deferred. Minor findings are not sent as rounds at all — they are deferred to the sweep before merge.
- An engineer reports to the Topo PM at every task boundary (PR opened, blocked, finished) with `SendMessage`: what, where (branch, commit, PR), what it waits on. It never merges, never reads or answers a review, and never polls with background shells — the PM does all three.

## Where the risk lives

The CI reviewer reads this section before the diff. Keep it current: it names where a serious defect is likely *now*, and it moves as the work does.

- **Audio lifecycle.** The audio session, the engines, the tap, the player and time-pitch nodes and the synthesiser are handles into mediaserverd; a media services reset, an interruption, or a route change invalidates them at once. The rule is that no handle is created, read, started or spoken to until `AudioSession.ensureActive()` has returned since the last reset, that a failure is a refusal, and that the format a tap is installed with is the very object the guard judged. Behind the lock there is a second rule: while a hold stands the session is not reconfigured, because iOS refuses a non-mixable session activated or reconfigured from the background and the refusal leaves it invalid for every path after. A serious defect here is a new audio path that skips `ensureActive`, reads an input format twice, rebuilds anything inside the reset handler, reconfigures the session while a hold stands, or catches a refusal and carries on: each is an uncatchable `NSException`, a crash rather than an error, and none shows in a simulator. The background hold adds three more: one that outlives the reply it was taken for keeps a pocketed phone awake until its battery is the symptom; one dropped at an event that is not the reply's end — the lock screen's own `.began` — suspends the process with the reply unheard, which is the same defect the other way round; and a rebuild on a configuration change or an interruption's end that runs before the session is active again is that same crash on a path nothing in the foreground exercises.
- **The look as a document.** `look.json` lives in the vault's root, which Files, an editor and the mirror all share, so it is read through `VaultMirror.contents(at:)` and never by an uncoordinated open of the folder — a read taken outside the coordination is half a file whenever somebody is halfway through saving one, and a half-read document is a screen drawn from a value nobody wrote. It is read after a sync and not inside one, and from the folder `Memory.home` names rather than from the app's own. Every value it carries is checked where it is read: a serious defect is a value reaching a view unchecked — a number that is not finite, one outside the range its field is read in, a name that is not one of an enum's cases, a length that puts the microphone or the badge out of reach — or a field that is refused taking any other field down with it, since a document is meant to cost what it got wrong and no more.
- **A literal in a view.** Every colour, surface, radius, padding, size and font a view draws with belongs in `Look`, reached from the environment. A number written inline is a value the mind cannot reach, which is the whole point of the type: the interface is meant to be adjustable from the inside. The transcript, the badge, the jewel both it and the microphone are cut from, and the composer are drawn from the look; the rest of the chat is not yet, so the defect is a view being changed or added — the settings sheet's own rows, the offer card — that hard-codes what it draws instead of naming a field, and a difference between two sides of a view written as a branch rather than as two values. A mark drawn on a cabochon rather than pressed into it through `Pressed`, or a cast written as a second picture in the asset catalogue rather than as a colour over the one stone, is the same defect: what the cut is and what colour the stone takes are meant to be values the mind can reach. The pane's presence is the same rule one step out: the surface, its edge and its glow are drawn at a value the composer is handed, so a view that draws the pane without asking it — or a second mechanism for clearing it, a transcript background run under it by hand, a scroll position read inside a view — is that defect rather than a fix.
- **The press path.** Every press is a session with a generation; a late result, a second release, or a press while another surface holds the microphone must reach nothing. Two gates on one input answer twice. The view the gesture is attached to is also the element the two UI suites find, by the three labels and by reporting as an image, so a change to what hosts that gesture is a change to whether the microphone can be pressed by a test at all — and a suite that cannot find the button fails as loudly as one that finds a broken one, which is the only reason that is safe.
- **The outbox and the row.** One nonce per turn, never two for the same words, never a turn lost. The words go on the line under one nonce before any attempt, the row holds them until that nonce is in the log, and the outbox's retry sends the same words under the same nonce — which is what the nonce marker deduplicates. So a serious defect is anything that makes a second nonce for words already on the line: a withdrawal that acts without asking the log, one taken while an attempt may be landing, or a resend that leaves the first entry behind. The row is the person's only sight of all this, so anything that makes it draw something other than the turn it is holding is the same class of defect: a landed turn's words taken into a row over a turn on its way sends one turn and shows another, and a relaunch that comes back to an empty row over an entry still on the line hides a turn that never landed and takes its way back with it. The other way round is as bad: a row that clears while the words are still owed loses them from view with the person unable to see what is still going, and one that stays in flight for a turn already in the log is a person locked out of their own words with no way back. A read that failed is not an answer to either question.
- **The transcript log** is append-only: one record per turn, per-device sequence numbers, create-only saves with a compare-and-set on the change tag. Anything that can overwrite, skip or duplicate a turn.
- **The primary lease**: two devices believing they are primary past the lease duration, a heartbeat that keeps a lost lease alive, a claim that is not atomic.
- **CloudKit is truth, sockets are speed**: a path that only works when a socket is up.
- **The migration.** Moving the folder between its two homes is the one operation that has the person's memory in two places at once. A serious defect is a home written before every file has been copied and verified, a source removed before the home has moved, a bookmark used without starting access on the URL the grant is on, a read of a file iCloud Drive has evicted that returns empty and is taken for the file, a baseline left behind so every file in the new folder re-parents, or a folder the person picked taken away rather than emptied.
- **The mirror.** The folder is shared with Files, with whatever editor has it open, and with the store, so `VaultMirror` is where a person's words are lost quietly. A serious defect is a sync that writes from a partial read, a path outside the vault or reached through a link (the scan and the re-read before an overwrite both refuse one, and both have to), a revision continuing from the store's heads instead of the heads that folder last saw — which swallows a concurrent edit — or a download landing on top of a file saved since the scan, which is why the comparison and the write are one coordinated write and never two. An uncoordinated read or write of that folder is the same class: half a file read as the whole of it becomes a revision saying so. So is a mirror that runs without a login: a signed-out phone that keeps or rebuilds the folder is the memory left on a device its owner signed out of.
- **The resident process.** Claude Code in the guest is a tree of processes that outlives nothing it should: a serious defect is a teardown that answers before the root is reaped, a descendant is gone and both pipes are closed, a background task ended before the teardown answers, or held past its bound, or an end the bound ran out on reported as anything but `NOT confirmed` with what stayed, a pending start or teardown acting on a process of a newer generation, a turn's events or its result reaching the turn after it, or a turn sent a second time — after an abandonment, a failed resume, or a process that exited silently. A blocking call on the cooperative pool is the same class: the stdin write, the stdout read and the wait each have a queue of their own. So is a guest task started from a thread with `SIGUSR1` blocked, which is a task no signal ever reaches while it sleeps.
- **The bridge.** The guest keeps a conversation of its own beside the log, and the ledger is the only thing that says how the two line up. A serious defect is a turn lost or doubled across a crash — an input sent without being recorded first, a received input sent again without the person asking, a reply the guest finished asked for again or written under a second nonce, an owed reply written after new turns rather than before them — the guest missing a turn (coverage advanced before the reply is in the log, or judged by time rather than by the turns themselves, so a late branch or a limb's turn is never told it), a read that failed — of the ledger, a transcript, a folder of them — or a transcript still being written taken as an input never received, coverage counted over turns the guest was never told, a request answered with another's words, the model changing under a turn in flight, a reply, a ledger record or a session id from before a sign-out reaching the log or the disk after it, and any path, not ready included, that answers a turn through something other than the guest.
- **The holes in the guest.** Claude Code in the guest runs with permissions bypassed, so nothing inside it stops a tool: what it can reach is exactly what the app mounts into the guest and what the proxy forwards. A serious defect is a hole wider than meant — a mount of more of the app's container than the home and Claude Code, a proxy route beyond the API, a new host path reachable from the guest — or a launch path in the app other than the resident's launcher setting `IS_SANDBOX` or the bypass flag. What the resident starts — its Bash tool, a nested `claude` — inherits its environment, so `IS_SANDBOX`, by design: the whole guest is the sandbox, and what the mind may do is reviewed at the holes, not inside. The bypass flag is an argument and is not inherited.
- **The guest's token and the proxy.** The guest holds a long-lived credential, and the proxy is the only door between it and the network. A serious defect is the token reaching anywhere but the environment of the process the app starts — a file under the guest's home, an argument, a log line (the proxy logs no header value) — or outliving sign-out in the keychain; a listener reachable on any address but `127.0.0.1`; a request forwarded to any origin but api.anthropic.com, a redirect followed included; a response body collected before it is sent, which Claude Code's streaming turns would feel as a stall; a client that has gone leaving its upstream stream running; and in a debug build a `/v1/messages` body that reaches the upstream unpinned.
- **The test doubles**: `InMemoryRecordDatabase` reproducing weaker semantics than CloudKit's, so the suite passes on behaviour the real store rejects. A test that cannot fail.
- **Licensing**: GPL code from others reaching a bundle, other than the iSH fork under its App Store waiver; a borrowed piece with no entry in `THIRD-PARTY`.
