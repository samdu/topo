# Topo

One always-on mind per person, every Apple device a limb. The design is `docs/design.md`; read it before changing anything.

## Layout

Swift and SwiftUI, except in Womble, which is as old as its devices. Three bundles; the first two are targets of one Xcode project:

- **client**: iOS, iPadOS, watchOS, tvOS. One codebase (`Apps/Client`, with `Apps/Shared` for what the hub shares) in three targets, `Topo`, `TopoWatch`, `TopoTV`; role (primary, viewer, limb) is decided at first launch from the CloudKit records. Only the iOS target can sign in; the watch and TV builds show a viewer screen.
- **hub**: `TopoHub`, the macOS menu-bar app bundling the Claude CLI and the channel servers. The only target that runs resident code. It holds the primary lease, answers probes for it, shows the pairing code (`docs/pairing.md`) and the devices on the Apple ID. An unsigned build has no iCloud entitlement and runs against the in-memory database instead, and says so in its menu.
- **Womble**: the viewer-only bundle for old devices, in its own project (`Womble/`, generated with XcodeGen) because it targets iOS 12 — UIKit, completion handlers, no concurrency and no scenes. It reads the same CloudKit records without depending on TopoCore, whose minimum is iOS 17; no mic, no models, no sign-in.

The logic is in Swift packages under `Packages/`: `TopoCore` (the log, the lease, the device directory, the memory), `TopoLink` (sockets and the lease probe), `TopoAuth` (Sign in with Claude), `TopoTurn` (the phone harness), `TopoUserland` (the guest, iOS target only), `TopoProxy` (the guest's API proxy, iOS target only) and `TopoMascot` (Topo's pixel engine, copied unchanged from samdu/experiments). `Apps/Topo` is the iOS target's own glue; `Tests/` holds the app suites and fixtures; `scripts/` the build, CI and simulator scripts, each with a test under `scripts/tests/`; `patches/ish/` the iSH fork's patches; `Design/` the icon sources.

## Building and testing

- `Topo.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` (edit the yml, run `xcodegen generate`, commit both; a new file under `Apps/`, `Tests/Client` or `Tests/ClientUI` belongs to no target until that runs, and xcodebuild reports success without having compiled it).
- Build check for a PR: `scripts/build-ish.sh`, then `xcodebuild -scheme Topo -destination 'generic/platform=iOS Simulator' build`; every scheme resolves `Packages/TopoUserland`, whose framework the script builds and nothing commits. No entitlements or team are set, so every target builds unsigned for a simulator; `CODE_SIGNING_ALLOWED=NO` for the macOS hub.
- Building `TopoIsh.xcframework` (`scripts/build-ish.sh`) needs meson, ninja and Homebrew's llvm and lld, since the guest's VDSO is an aarch64 ELF Apple's linker does not make.
- `swift test` from a package directory runs that package's suite, offline and against an in-memory database; no test needs a signed-in device.
- Two things in `project.yml` are load-bearing: `EXCLUDED_ARCHS[sdk=iphonesimulator*]: x86_64` on the iOS target, because FluidAudio's NemoTextProcessing xcframework has an arm64 simulator slice and no x86_64 one; and the iOS target's `info:` block, which writes `Apps/Topo/Info.plist` for the keys that have to be in a file. The rest of that plist is generated from the target's `INFOPLIST_KEY_*` settings, which Xcode merges into it, but `UIBackgroundModes` is not a key Xcode generates: an `INFOPLIST_KEY_UIBackgroundModes` setting reaches the project and no built app, and a background mode the product does not declare is a process iOS suspends. The version keys in that file are `$(MARKETING_VERSION)` and `$(CURRENT_PROJECT_VERSION)`, never literals, because a literal beats the build number `scripts/archive-upload.sh` passes on the command line and every TestFlight upload would carry the same one. `scripts/check-built-plist.sh` reads the modes and the build number off the built app in the PR check, because the settings they are declared by are not proof.
- A signed-in simulator run, the microphone press and the talk lane are `docs/simulator.md`; the PR check's jobs are `docs/testing.md`.

## Invariants

- **CloudKit is truth, sockets are speed.** State (transcript log, pairing record, primary lease) lives in the private CloudKit database; the push that wakes the primary, direct sockets and the punched tunnel only make live turns fast. With no socket the app still works off the records, just slower.
- One container, `iCloud.zone.hexagon.topo`, private database, custom zone `Topo`. Every bundle reads and writes that one, so the identifiers are a contract between them and not a per-target setting.
- A debug build only ever talks to Haiku 4.5, because every debug build here is signed into a real subscription: the pin is at the wire (`ClaudeModel.effective`) and in the guest's proxy (`APIProxy.pinnedModel`), never only at the picker (`docs/simulator.md`, *The one rule*).
- Tokens live in the device keychain, never synced; only the primary and the hub ever hold one.
- A block handed to the system from a main-actor context and called back off the main thread (the input tap, on the audio thread) is written `@Sendable`: without it the closure is main-actor-isolated by inference, and Swift 6 opens it with an executor check that traps off the main thread, past any `catch`.

## Working here

The process — who plans, who builds, who reviews, and in what order — is `docs/process.md`. The short form:

- Every change lands as a PR on a `buddy/<topic>` branch from its own worktree, opened as a draft. The description is the contract: what was done, and a **Proof** section as a checklist of what was verified. A test only a physical device can show is an unchecked `- [ ] device: …` box; auto-merge waits until it is ticked.
- Never force push. One concern per PR; a finding on an open PR is fixed on that branch, never in a second PR.
- Prefer what exists: stdlib, then a platform framework, then an already-linked dependency, before new code or a new dependency. Nothing GPL from others ships in a bundle unless its holders waive the App Store conflict, as iSH's do; the fork is the one such piece. Every borrowed piece is attributed in `THIRD-PARTY`.
- Docs describe what **is**, never what was or what is planned. When you change behaviour, change the doc to match; do not narrate the change.
- An engineer reports to the Topo PM at every task boundary (PR opened, blocked, finished) with `SendMessage`: what, where (branch, commit, PR), what it waits on. It never merges, never reads or answers a review, and never polls with background shells — the PM does all three.

## Where the risk lives

The CI reviewer reads this section before the diff. Keep it current: it names where a serious defect is likely *now*, and it moves as the work does.

- **Audio lifecycle.** The audio session, the engines, the tap, the player and time-pitch nodes and the synthesiser are handles into mediaserverd; a media services reset, an interruption, or a route change invalidates them at once. The rule is that no handle is created, read, started or spoken to until `AudioSession.ensureActive()` has returned since the last reset, that a failure is a refusal, and that the format a tap is installed with is the very object the guard judged. Behind the lock there is a second rule: while a hold stands the session is not reconfigured, because iOS refuses a non-mixable session activated or reconfigured from the background and the refusal leaves it invalid for every path after. A serious defect here is a new audio path that skips `ensureActive`, reads an input format twice, rebuilds anything inside the reset handler, reconfigures the session while a hold stands, or catches a refusal and carries on: each is an uncatchable `NSException`, a crash rather than an error, and none shows in a simulator. The background hold adds three more: one that outlives the reply it was taken for keeps a pocketed phone awake until its battery is the symptom; one dropped at an event that is not the reply's end — the lock screen's own `.began` — suspends the process with the reply unheard, which is the same defect the other way round; and a rebuild on a configuration change or an interruption's end that runs before the session is active again is that same crash on a path nothing in the foreground exercises.
- **The look as a document.** `look.json` lives in the vault's root, which Files, an editor and the mirror all share, so it is read through `VaultMirror.contents(at:)` and never by an uncoordinated open of the folder — a read taken outside the coordination is half a file whenever somebody is halfway through saving one, and a half-read document is a screen drawn from a value nobody wrote. It is read after a sync and not inside one, and from the folder `Memory.home` names rather than from the app's own. Every value it carries is checked where it is read: a serious defect is a value reaching a view unchecked — a number that is not finite, one outside the range its field is read in, a name that is not one of an enum's cases, a length that puts the microphone or the badge out of reach — or a field that is refused taking any other field down with it, since a document is meant to cost what it got wrong and no more.
- **A literal in a view.** Every colour, surface, radius, padding, size and font a view draws with belongs in `Look`, reached from the environment. A number written inline is a value the mind cannot reach, which is the whole point of the type: the interface is meant to be adjustable from the inside. The transcript, the badge, the jewel both it and the microphone are cut from, and the composer are drawn from the look; the rest of the chat is not yet, so the defect is a view being changed or added — the settings sheet's own rows, the offer card — that hard-codes what it draws instead of naming a field, and a difference between two sides of a view written as a branch rather than as two values. A mark drawn on a cabochon rather than pressed into it through `Pressed`, or a cast written as a second picture in the asset catalogue rather than as a colour over the one stone, is the same defect: what the cut is and what colour the stone takes are meant to be values the mind can reach. The pane's presence is the same rule one step out: the surface, its edge and its glow are drawn at a value the composer is handed, so a view that draws the pane without asking it — or a second mechanism for clearing it, a transcript background run under it by hand, a scroll position read inside a view — is that defect rather than a fix.
- **The press path.** Every press is a session with a generation; a late result, a second release, or a press while another surface holds the microphone must reach nothing. Two gates on one input answer twice. The view the gesture is attached to is also the element the two UI suites find, by the three labels and by reporting as an image, so a change to what hosts that gesture is a change to whether the microphone can be pressed by a test at all — and a suite that cannot find the button fails as loudly as one that finds a broken one, which is the only reason that is safe.
- **The outbox and the row.** One nonce per turn, never two for the same words, never a turn lost. The words go on the line under one nonce before any attempt, the row holds them until that nonce is in the log, and the outbox's retry sends the same words under the same nonce — which is what the nonce marker deduplicates. So a serious defect is anything that makes a second nonce for words already on the line: a withdrawal that acts without asking the log, one taken while an attempt may be landing, or a resend that leaves the first entry behind. The row is the person's only sight of all this, so anything that makes it draw something other than the turn it is holding is the same class of defect: a landed turn's words taken into a row over a turn on its way sends one turn and shows another, and a relaunch that comes back to an empty row over an entry still on the line hides a turn that never landed and takes its way back with it. The other way round is as bad: a row that clears while the words are still owed loses them from view with the person unable to see what is still going, and one that stays in flight for a turn already in the log is a person locked out of their own words with no way back. A read that failed is not an answer to either question.
- **Topo standing nowhere.** Obscuring a line is better than disappearing: a roaming Topo with no place clear of the words stands over the least of them. A serious defect is a roam that undraws him for lack of a clear spot, or one whose fallback puts his reach on the pane, the well, the keyboard or past the screen's edge. He stands nowhere only while the transcript is unread, with no pane or transcript to be placed on, or where his reach cannot fit the room at all.
- **The transcript log** is append-only: one record per turn, per-device sequence numbers, create-only saves with a compare-and-set on the change tag. Anything that can overwrite, skip or duplicate a turn.
- **The primary lease**: two devices believing they are primary past the lease duration, a heartbeat that keeps a lost lease alive, a claim that is not atomic.
- **CloudKit is truth, sockets are speed**: a path that only works when a socket is up.
- **The migration.** Moving the folder between its two homes is the one operation that has the person's memory in two places at once. A serious defect is a home written before every file has been copied and verified, a source removed before the home has moved, a bookmark used without starting access on the URL the grant is on, a read of a file iCloud Drive has evicted that returns empty and is taken for the file, a baseline left behind so every file in the new folder re-parents, or a folder the person picked taken away rather than emptied.
- **The mirror.** The folder is shared with Files, with whatever editor has it open, and with the store, so `VaultMirror` is where a person's words are lost quietly. A serious defect is a sync that writes from a partial read, a path outside the vault or reached through a link (the scan and the re-read before an overwrite both refuse one, and both have to), a revision continuing from the store's heads instead of the heads that folder last saw — which swallows a concurrent edit — or a download landing on top of a file saved since the scan, which is why the comparison and the write are one coordinated write and never two. An uncoordinated read or write of that folder is the same class: half a file read as the whole of it becomes a revision saying so. So is a mirror that runs without a login: a signed-out phone that keeps or rebuilds the folder is the memory left on a device its owner signed out of.
- **The resident process.** Claude Code in the guest is a tree of processes that outlives nothing it should: a serious defect is a teardown that answers before the root is reaped, a descendant is gone and both pipes are closed, a background task ended before the teardown answers, or held past its bound, or an end the bound ran out on reported as anything but `NOT confirmed` with what stayed, a pending start or teardown acting on a process of a newer generation, a turn's events or its result reaching the turn after it, or a turn sent a second time — after an abandonment, a failed resume, or a process that exited silently. A blocking call on the cooperative pool is the same class: the stdin write, the stdout read and the wait each have a queue of their own. So is a guest task started from a thread with `SIGUSR1` blocked, which is a task no signal ever reaches while it sleeps.
- **The bridge.** The guest keeps a conversation of its own beside the log, and the ledger is the only thing that says how the two line up. A serious defect is a turn lost or doubled across a crash — an input sent without being recorded first, a received input sent again without the person asking, a reply the guest finished asked for again or written under a second nonce, an owed reply written after new turns rather than before them — the guest missing a turn (coverage advanced before the reply is in the log, or judged by time rather than by the turns themselves, so a late branch or a limb's turn is never told it), a read that failed — of the ledger, a transcript, a folder of them — or a transcript still being written taken as an input never received, coverage counted over turns the guest was never told, a request answered with another's words, the model changing under a turn in flight, a reply, a ledger record or a session id from before a sign-out reaching the log or the disk after it, and any path, not ready included, that answers a turn through something other than the guest.
- **The holes in the guest.** Claude Code in the guest runs with permissions bypassed, so nothing inside it stops a tool: what it can reach is exactly what the app mounts into the guest and what the proxy forwards. A serious defect is a hole wider than meant — a mount of more of the app's container than the home and Claude Code, a proxy route beyond the API, a new host path reachable from the guest — or a launch path in the app other than the resident's launcher setting `IS_SANDBOX` or the bypass flag. What the resident starts — its Bash tool, a nested `claude` — inherits its environment, so `IS_SANDBOX`, by design: the whole guest is the sandbox, and what the mind may do is reviewed at the holes, not inside. The bypass flag is an argument and is not inherited.
- **The guest's token and the proxy.** The guest holds a long-lived credential, and the proxy is the only door between it and the network. A serious defect is the token reaching anywhere but the environment of the process the app starts — a file under the guest's home, an argument, a log line (the proxy logs no header value) — or outliving sign-out in the keychain; a listener reachable on any address but `127.0.0.1`; a request forwarded to any origin but api.anthropic.com, a redirect followed included; a response body collected before it is sent, which Claude Code's streaming turns would feel as a stall; a client that has gone leaving its upstream stream running; and in a debug build a `/v1/messages` body that reaches the upstream unpinned.
- **The test doubles**: `InMemoryRecordDatabase` reproducing weaker semantics than CloudKit's, so the suite passes on behaviour the real store rejects. A test that cannot fail.
- **Licensing**: GPL code from others reaching a bundle, other than the iSH fork under its App Store waiver; a borrowed piece with no entry in `THIRD-PARTY`.
