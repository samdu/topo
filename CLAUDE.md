# Topo

One always-on mind per person, every Apple device a limb. The design is `docs/design.md`; read it before changing anything, and keep it and this file describing what **is**, never what was or what is planned.

## Stack

- Swift and SwiftUI, except in Womble, which is as old as its devices. Three bundles; the first two are targets of one Xcode project, `Topo.xcodeproj`, generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` (edit the yml, run `xcodegen generate`, commit both):
  - **client**: iOS, iPadOS, watchOS, tvOS. One codebase (`Apps/Client`, with `Apps/Shared` for what the hub shares) in three targets, `Topo`, `TopoWatch`, `TopoTV`; role (primary, viewer, limb) is decided at first launch from the CloudKit records. Only the iOS target can sign in; the watch and TV builds show a viewer screen.
  - **hub**: `TopoHub`, the macOS menu-bar app bundling the Claude CLI and the channel servers. The only target that runs resident code.
  - **Womble**: the viewer-only bundle for old devices, in its own project (`Womble/`, generated with XcodeGen) because it targets iOS 12 — UIKit, completion handlers, no concurrency and no scenes. It reads the same CloudKit records without depending on TopoCore, whose minimum is iOS 17; no mic, no models, no sign-in.
- Build check for a PR: `xcodebuild -scheme Topo -destination 'generic/platform=iOS Simulator' build`. No entitlements or team are set, so every target builds unsigned for a simulator; `CODE_SIGNING_ALLOWED=NO` for the macOS hub.
- Sign in with Claude is `Packages/TopoAuth`: the Claude Code CLI's OAuth client (authorization code with PKCE against `claude.com/cai/oauth/authorize`, exchange and refresh at `platform.claude.com/v1/oauth/token`, the CLI's client id and scopes). The browser redirects to a loopback listener in the app; if that cannot bind, to the hosted callback page, whose `code#state` the user pastes. Tokens live in the device keychain, never synced; only the primary and the hub ever hold one.
- The phone harness is `Packages/TopoTurn`: `MessagesAPI` (one non-streaming `POST /v1/messages` with the OAuth bearer token, the `oauth-2025-04-20` beta and the Claude Code CLI's identity line as the first system block, which is what a subscription token is accepted for; `Transport` is the seam the tests mock), `TurnRunner` (take the primary lease, append the person's turn, call the model with the last 40 turns, append the reply as its child once a heartbeat confirms the lease is still held; a failed call leaves the person's turn in the log, a lost lease leaves the reply out), and `LocalRecordDatabase` (a `RecordDatabase` in one JSON file with CloudKit's conflict semantics). The model is a setting: Sonnet 5 by default, Opus 5 or Fable 5.1 from the chat menu.
- The iOS client keeps its log in a `LocalRecordDatabase` under Application Support; it carries no iCloud entitlement yet, so `RecordDatabase` is where CloudKit plugs in. With no socket, its lease probe answers no to every holder. Sign-out deletes the local log and the first-run answer along with the tokens.
- **CloudKit is truth, sockets are speed.** State (transcript log, pairing record, primary lease) lives in the private CloudKit database; direct sockets and the punched tunnel only make live turns fast. With no socket the app still works off the records, just slower.
- The transcript is an append-only log: one record per turn, per-device sequence numbers, never overwrite. The primary lease is the one mutable record: atomic claim, 10s expiry, 5s heartbeat the holder runs itself, probe-driven handover, a displaced holder yields rather than reclaims.
- Core logic ships as Swift packages whose tests run against an in-memory database behind the package's own CloudKit protocol; no test needs a signed-in device. `Packages/TopoCore` is the log and the lease: `RecordDatabase` is the protocol over the CloudKit calls used (compare-and-set save, fetch, query), `CloudKitRecordDatabase` is the adapter, and `TopoCoreTesting` holds the in-memory database with CloudKit's conflict semantics. `swift test` from the package directory runs everything.

## Working here

- Every change lands as a PR on a branch named `<role>/<topic>`: `lead/…`, `senior/…`, `junior/…`. The status pane assigns PRs to engineers by that prefix, so a branch without it belongs to nobody.
- Never force push.
- Prefer what exists: stdlib, then a platform framework, then an already-linked dependency, before new code or a new dependency. Nothing GPL from others ships in a bundle (App Store distribution); every borrowed piece is attributed in `THIRD-PARTY`.
- Docs describe the present state. When you change behaviour, change the doc to match; do not narrate the change.
