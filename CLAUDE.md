# Topo

One always-on mind per person, every Apple device a limb. The design is `docs/design.md`; read it before changing anything, and keep it and this file describing what **is**, never what was or what is planned.

## Stack

- Swift and SwiftUI, except in Womble, which is as old as its devices. Three bundles; the first two are targets of one Xcode project, `Topo.xcodeproj`, generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` (edit the yml, run `xcodegen generate`, commit both; a new file under `Apps/`, `Tests/Client` or `Tests/ClientUI` belongs to no target until that runs, and xcodebuild reports success without having compiled it):
  - **client**: iOS, iPadOS, watchOS, tvOS. One codebase (`Apps/Client`, with `Apps/Shared` for what the hub shares) in three targets, `Topo`, `TopoWatch`, `TopoTV`; role (primary, viewer, limb) is decided at first launch from the CloudKit records. Only the iOS target can sign in; the watch and TV builds show a viewer screen.
  - **hub**: `TopoHub`, the macOS menu-bar app bundling the Claude CLI and the channel servers. The only target that runs resident code. It holds the primary lease, answers probes for it, shows the pairing code (`docs/pairing.md`) and the devices on the Apple ID. An unsigned build has no iCloud entitlement and runs against the in-memory database instead, and says so in its menu.
  - **Womble**: the viewer-only bundle for old devices, in its own project (`Womble/`, generated with XcodeGen) because it targets iOS 12 — UIKit, completion handlers, no concurrency and no scenes. It reads the same CloudKit records without depending on TopoCore, whose minimum is iOS 17; no mic, no models, no sign-in.
- Build check for a PR: `xcodebuild -scheme Topo -destination 'generic/platform=iOS Simulator' build`. No entitlements or team are set, so every target builds unsigned for a simulator; `CODE_SIGNING_ALLOWED=NO` for the macOS hub.
- Sign in with Claude is `Packages/TopoAuth`: the Claude Code CLI's OAuth client (authorization code with PKCE against `claude.com/cai/oauth/authorize`, exchange and refresh at `platform.claude.com/v1/oauth/token`, the CLI's client id and scopes). The browser redirects to a loopback listener in the app; if that cannot bind, to the hosted callback page, whose `code#state` the user pastes. Tokens live in the device keychain, never synced; only the primary and the hub ever hold one.
- One container, `iCloud.zone.hexagon.topo`, private database, custom zone `Topo`. Every bundle reads and writes that one, so the identifiers are a contract between them and not a per-target setting.
- The phone harness is `Packages/TopoTurn`: `MessagesAPI` (one non-streaming `POST /v1/messages` with the OAuth bearer token, the `oauth-2025-04-20` beta and the Claude Code CLI's identity line as the first system block, which is what a subscription token is accepted for; `Transport` is the seam the tests mock), `TurnRunner` (take the primary lease, append the person's turn under a nonce the caller keeps until the turn is known to be in the log, call the model with the last 40 turns, append the reply as its child in one atomic batch with a lease heartbeat; a failed call leaves the person's turn in the log, a lost lease leaves the reply out). A reply's nonce is a hash of the turns it answers, so a retry or a second brain finds the one reply. The row at the end of the transcript is drawn against that contract: it holds the words under the nonce `willSend` gave them until `Harness.said(nonce)` is true, which is what the outbox's own retry is keyed to, so a turn that never settled stays in flight and one whose reply failed clears, its turn standing in the log. `Harness.withdraw(nonce)` is the way back from the first: it takes the entry off the line so the words can be said again as one turn under one nonce, and it asks the log before it does — a turn already there cannot be taken back, and neither can one whose log could not be read, since a read that failed is not an answer. It is refused while an attempt is running, which is a write that may be landing as it is asked. The row is `NextTurn` (`Apps/Client/NextTurn.swift`) rather than the chat screen's own state, because what it holds outlives the screen: the line is on disk, so a chat appearing over an unsettled line takes the oldest words on it whose turn the read did not find in the log back up as the turn on its way (`resume(from:)`), which is where the way back from a turn that never landed is and where it is most needed. The oldest still owed and not the head, since the head can be a turn that reached the log and lost its acknowledgement, with a turn said behind it still owed; words already in the log belong to the transcript and not to the row, whichever entry they are. It resumes nothing over a row already in use. It refuses a landed turn's words while a turn is on its way (`edit(_:in:)`), since the row draws the words being sent until they land or are taken back. `answerPending` is the log's own path for a limb's words: the primary answers any person turn at the log's head, whoever wrote it, one reply continuing every head; the phone runs it every five seconds while the chat is open, which is also how a reply that failed is retried. A phone that is not primary writes the person's turn as a limb and the primary answers it there. The model is a setting: Sonnet 5 by default, Opus 5 or Fable 5.1 from the settings sheet — except in a debug build, which is pinned to Haiku 4.5 (`ClaudeModel.pinned`, applied in `MessagesAPI.complete` so every caller obeys it, not only the picker), because every debug build here is signed into a real subscription and a stray turn spends it.
- Voice on the phone is push to talk (`Apps/Client/VoiceInput.swift`): hold the microphone to talk and release to send, or tap to open it until the next press; the first-run answer is hold-to-talk only. The first press asks for the microphone, which is the only permission a press asks for, and nothing is asked before it. Recognition is on the device, and it is the phone's one ear: Parakeet-tdt-0.6b-v2 through FluidAudio (`Apps/Client/Ear.swift`, the iOS target only), the audio so far decoded bare every second for the caption and the whole utterance decoded and rescored at the release against the person's own vocabulary (`Apps/Client/Vocabulary.swift`: empty until they add to it, since none of anyone else's words are theirs; edited from the settings sheet; kept in this device's defaults rather than the vault, because a vocabulary is this device's ear and not the person's memory). An edit rebuilds the spotter's session live, so a word works from the next press; the gate is constant (no aliases, similarity 0.65, three characters minimum: Daphne's measured config, and the reason additions are safe). The session is a layer over Parakeet, not a condition of the ear: an empty list builds none, and one that cannot be built leaves Parakeet recognising bare, with the reason in the diagnostics `speech` row. The models are not in the bundle: about 540 MB of CoreML that `ModelDownloads` (`Apps/Client/ModelDownloads.swift`) fetches from the first foreground on (`VoiceInput.prepare`) into the app's Application Support, where FluidAudio loads them from, told to touch no network of its own (`ModelHub.offlineMode`). Until they are resident, or if they fail to load, a press is refused with the ear's own status line and nothing touches the audio session or the engine; both surfaces' microphone buttons, the chat's and the first run's, are dimmed whenever a press would not open one (`VoiceInput.canListen`, the microphone denied or the ear not resident, read from the state as it is, so the load finishing undims them with no press in between); the first run's copy about allowing it in Settings stays tied to `denied` alone, since an ear that is still downloading is a wait rather than something to go and allow; a decode that throws at the release sends the caption the glances left, and nothing when there is none, with the error in the debug `Capture`. The diagnostics screen's `speech` row says which state the ear is in. A spoken turn's reply is read aloud (`Speaker`; a setting in the settings sheet), a typed one's is not; holding any of Topo's turns in the transcript opens a menu that says it again, which is how a typed turn's reply is heard (`Replay` in `Apps/Client/TranscriptView.swift`, threaded from the chat screen, so the watch, the television and a viewer offer nothing). The item reads Stop while the speaker is speaking, and is gone while the voice is not resident. The voice is on the device, and it is the phone's one voice: Kyutai's Pocket TTS through FluidAudio (`Apps/Client/Voice.swift`, the iOS target only), speaking its stock `eponine`: each person names their own mind, so the default voice is a neutral stock one rather than anyone's blend. Every stage is placed off the GPU — the conditioner, the flow-LM and the fused flow decoder at `.cpuAndNeuralEngine` on the rank-4 `.ane` variants, Mimi at `.cpuOnly`, where the port found it fastest and where its fp16 state feedback does not beep; `.all` is never used, because it lets a stage fall to the GPU. A reply is cut into sentences on sentence-final punctuation, each synthesised behind the one before as a stream of 80 ms frames pushed to one player node as they decode, so the wait is the first frame. Pocket has no pace of its own, so the pacing is the play queue's `AVAudioUnitTimePitch` at `Voice.tempo`, 1.20 with the pitch untouched: a per-speaker constant, explained in the doc comment, and the only thing between the voice's frames and the speaker. `Speaker` reads the clock through an injected `now` (the continuous clock in production), so the debug report's two measurements are arithmetic a unit test drives rather than a race it has to wait out. The model is not in the bundle either: about 351 MB (the four CoreML bundles the ANE placement loads, the constants and the tokenizer beside them, and the one speaker) that `ModelDownloads` fetches on the same cue (`Speaker.prepare`) and FluidAudio loads from the store, told to touch no network of its own. A reply is not read aloud at all when the model is not resident or fails to load — there is nothing to fall back to — and the diagnostics screen's `voice` row says which state the model is in; a debug build launched with `TOPO_DEBUG_VOICE=loading` (`DebugRun.voice`) holds the voice unloaded, and one launched with a directory loads Pocket from there instead of downloading it, which is what the talk lane does. One `VoiceInput` for the app and one gate on its microphone, enforced: a surface pressing while another holds it is refused, since two gates on one input answer the same utterance twice; the two surfaces are never mounted together and each cancels its session on disappearing. Every press is a session with a generation, so a release during the permission prompts starts nothing, a late recogniser result or a second release belongs to no session, and what one session heard cannot become the next one's turn. The audio session, the idle timer and the background hold are process-wide, so `AudioSession` counts claims on them rather than assigning them; the record configuration is warmed on the foreground so the press does not pay for the route change. A block handed to the system from a main-actor context and called back off the main thread (the input tap, on the audio thread) is written `@Sendable`: without it the closure is main-actor-isolated by inference, and Swift 6 opens it with an executor check that traps off the main thread, past any `catch`. A spoken turn's reply is heard behind the lock, in a pocket, or in front of another app: the iOS target holds the `audio` background mode (`Apps/Topo/Info.plist`), and under it iOS runs the process only while an engine of its own is running, so the play queue keeps a second player node at no volume looping a fifth of a second of zeroes (the keeper) for as long as a hold stands. The process is held by the running engine and the keeper is only what it renders, so with no hold nothing runs: the last hold going stops the keeper and the engine with it, its nodes left attached, and the next hold or frame starts it again through the same refusal path as any other. An engine left running under a stopped keeper is a phone that never suspends. The hold is counted like the other two, with two kinds of owner: `.awaitingReply(nonce)`, one claim per spoken turn outstanding — the chat lets a second press append while the first turn is in flight, and each turn holds for itself — taken at the release and dropped when that turn's reply is handed to `speak`, when the harness says that turn failed (`Harness.onTurnFailed`, named as the turn ends, since the screen's error line cannot say whose turn stopped), when a press, a Stop, a sign-out or a reset ends things, and at its own ceiling of 120 s; and `.speaking`, taken in `speak` after `ensureActive` and dropped when every sentence is made **and** the queue is drained, since a queue that empties between two sentences is not the reply's end. Nothing is held for a turn whose reply could not be heard anyway — Read replies aloud off, or the voice not resident at the release — and a typed turn asks for none, so the app suspends behind the lock as it always did. Both owners are bounded by the same 120 s ceiling, `.awaitingReply` from the release and `.speaking` from the last frame scheduled or played back, so a hold outlives a dead reply by the ceiling at most; the ceiling's line says which way the wait ended, a reply that never landed or one that landed and was refused, with the count, because the two end the same wait and only that tells a run's log them apart. An `AVAudioSession` interruption is not the end of either: iOS posts a `.began` at the lock screen with no call and no Siri in it, so `.began` stops the player, keeps the buffers nobody has heard and leaves the hold standing — and a frame arriving while the engine is dead is added to what is owed rather than played, since restarting a dead engine throws and the voice reads that throw as the sentence's end (the notification's type, reason, `wasSuspended` and options are logged), and `.ended` — or the `AVAudioEngineConfigurationChange` a real interruption's end posts — rebuilds through the same path as the lock's category flip, whenever anything is owed or the queue is dead, building an engine from nothing if an earlier refusal left none. Every way the recovery path can fail ends in one refusal: the engine is dropped, the owed frames and the dead mark are kept, the session is invalidated, and the next end, change or reply tries the whole thing again — an activation refused, an engine that will not start, a frame that could not be played, a keeper that could not be started. A reply arriving on a dead queue rebuilds it first and is refused when that rebuild is, and one whose hold cannot be honoured — the keeper's own engine refusing to start — is refused the same way, since a reply taken on an engine that will not start would clear its turn's mark and end its wait for a reading that never happens. The hold's count tells the speaker about every claim taken or dropped, not only about the answer changing, so a claim arriving while another already stands is the chance to start a keeper an earlier refusal left down. Nothing is reported as playing, or as held, that is not. The format survives a refusal, because it is the voice's rate and not the engine's and a frame arriving while there is no engine at all is still made against it and owed; only a media services reset drops it. A reply cut by a short call carries on after it; a reply the speaker refuses (`speak` answers whether it took it) is still owed, so its turn stays marked spoken, its wait stands to its ceiling, and the next pass offers the reply again. The decision to read a reply aloud is `Harness.onReply`, which the chat installs beside `PushWake`: it fires for a reply this phone wrote and for one a pass read that another primary wrote, once per turn, because behind the lock nothing is drawn and whether a view's observer runs is SwiftUI's to decide. A reply is recorded as offered only when a handler took it — one that was not there, and one that could not act, both leave it to be offered again — and installing a handler replays what arrived unheard, since the screen reads the log and sends what an earlier launch left owed before it installs. Of more than one owed reply the newest is read and the older are cleared unread: a person coming back is owed the answer to the last thing they said rather than a backlog read at them, and each reply spoken cuts off the one before it anyway. The handler reads the mark and not the setting, since the setting governs what the next release decides and not what a turn already released is owed. Whether a turn is spoken is the wait's own answer — `Speaker.awaitReply` answers both `spoken` (the reply will be read aloud when it lands, which is what marks the turn, and is true in the foreground whatever the audio is doing) and `held` (the keeper is actually rendering for it); the chat records the mark from `spoken` and states no condition of its own, so no later launch turning the setting on reads an old reply aloud, and a keeper that would not start is reported as the refusal it is rather than as a hold. The mark is the harness's, and on disk (`topo.harness.spoken`, the twenty most recent nonces owed a reply, cleared per turn as its reply is read and by a sign-out): the words said before the app went away survive the relaunch in the outbox, so what makes them a spoken turn has to survive with them. Signing out, and the far end of a takeover, stop the speaker: the reply in the ear goes with the login. While any hold stands the session is not reconfigured: a claim change — the warm record claim dropped at the lock, or any other — is remembered, so the session that was active at the release stays active and untouched, whatever category it was in, until the reply has been heard. What is remembered is applied when the last hold goes and the app is in front; behind the lock, where the last hold going is as likely a reply ending as the app coming back, the session is marked as needing configuring instead and the claims are left for the next path that wants audio — the next `ensureActive`, or the foreground's own warm claim, which applies them as it changes. Activating or reconfiguring a non-mixable session from the background is refused (`cannotInterruptOthers`), and a session left invalid by that refusal is one every later `ensureActive` tries the same refused call on, which is a reply spoken only on unlock; an already-active session goes on rendering behind the lock under the `audio` mode, so `ensureActive` at `speak` is free there and nothing sets a category or activates a session from the background. A claim's configure failing is logged with its error rather than thrown, since a claim is not an audio path and the path that is meets it at `ensureActive`. What can still change under a hold is an interruption, whose end is exactly when iOS allows the session back: the queue rebuilds for its own engine on an `.ended` or an `AVAudioEngineConfigurationChange` — `ensureActive` first, then a fresh engine at the same format, every buffer not yet played back scheduled again in order under a new epoch so the discarded completions move nothing, and the keeper back if a hold stands. Resuming a reply after an interruption ends is not built. Nothing that is a handle into mediaserverd — an `AVAudioEngine`, its input node, a tap, an `AVAudioPlayerNode` — is created, read, started or spoken to until `AudioSession` has configured **and** activated the session since the last reset; a failure to activate is a refusal, never a fall-through. `AudioSession.ensureActive()` is the call every audio path makes first, and costs nothing on a session that is already valid, so a press still does not pay for the route change the foreground paid for. When iOS resets the media server (`AVAudioSession.mediaServicesWereResetNotification`) the session is marked invalid and re-applied if it had ever been configured, a failure there being remembered rather than swallowed; `VoiceInput` cancels any press, dropping its words as an interruption does, and drops its engine; and `Speaker` stops the reply, drops both holds and drops the play queue's engine, players and time-pitch unit, which an interruption deliberately does not. Nothing is rebuilt in a handler: the press and `speak` each reactivate and build what they need, so recovery does not depend on which of the two comes first, and Say it again after a reset works with no press before it. A press reads the input node's client and hardware formats and refuses (`no audio input`) when either has no sample rate or no channel or the two rates differ — both are ways `installTap` raises an exception no `catch` sees — and a refusal, like an activation that threw, drops the engine and invalidates the session so the next press rebuilds rather than reading the same dead node. - On-device model weights are downloaded by Topo, never by the libraries: one background `URLSession` (`ModelDownloads`, identifier `zone.hexagon.topo.models`; expensive and constrained network access off, waits for connectivity, not discretionary) so iOS applies the person's data settings and finishes the transfer with the app suspended or gone, with no prompt, toggle or gate of ours. What it fetches is `Apps/Topo/Resources/models.json`, the pinned manifest `scripts/model-manifest.sh` writes from the Hugging Face tree API: `FluidInference/parakeet-tdt-0.6b-v2-coreml` at `ee09c569`, `FluidInference/parakeet-ctc-110m-coreml` at `accdafd8`, `FluidInference/pocket-tts-coreml` at `91748676` (the English v2.1 pack, and of it only what the ANE placement loads); each entry is the flattened file list (a `.mlmodelc` is a directory of files on the Hub) with sizes and sha256 digests. Download tasks only, one per file, each verified against its digest and moved into `Application Support/Models/<id>/` with the digest recorded in the directory's ledger (two entries live elsewhere, `ModelStore.homes`, because the library that reads them reads one path and no other: the CTC spotter's is FluidAudio's own `CtcModels.defaultCacheDirectory`, where `VocabularyBoostingSession` reads its tokenizer, and the voice's pack is `Models/pocket-tts/`, where `PocketTtsManager` looks beneath the base directory it is given, with the manifest's paths kept repository-relative so each file lands where the loader looks; a set downloaded under the root before that is renamed into place rather than fetched again); a model is present only when every file is on disk at its size and in the ledger, a partial set carries on from the files it has (resume data where the server gave any), and a bump is a new revision in the script and a re-run. `TopoAppDelegate` (a `UIApplicationDelegateAdaptor`) takes `handleEventsForBackgroundURLSession`, so a transfer that finished while the app was dead is admitted on the relaunch and the handler called. The ear's and the voice's status lines, and the diagnostics `speech` and `voice` rows, say what the session reports: waiting for a network the settings allow, downloading with bytes done of total, verifying, then loading and resident.
- A simulator is signed in from its launch environment, not by hand: `Apps/Client/DebugRun.swift` (all of it behind `#if DEBUG`) takes a Claude Code setup token from `TOPO_CLAUDE_SETUP_TOKEN` and writes it to the store as a finished sign-in, puts a turn on the harness's line from `TOPO_DEBUG_OUTBOX` (empty clears it) so a launch can be the relaunch that finds one owed, and takes one turn from `TOPO_DEBUG_SEND` through the ordinary harness, printing each step prefixed `[topo-debug]`. `scripts/simulator-run.sh` builds, boots, launches and asserts on those lines, passing only a finished turn with no error whose reply `DebugRun.answer` tied to the sent turn's nonce and that carries the script's run id (`TOPO_DEBUG_RUN`); `scripts/tests/simulator-run-test.sh` holds every failure red against a fake `xcrun`, in the PR check; `docs/simulator.md` is the runbook, and says what the token is and what it is not written to. The microphone is pressed by `TopoUITests` (`Tests/ClientUI`, an XCUITest in the `Topo` scheme's test action, so the PR check and `scripts/simulator-run.sh --press-mic` run it): a tap, a hold and a release on the chat screen, holding that the app is still running after each, that each press reached `VoiceInput`, and what reached the input tap and the sample sink (the button's debug-only accessibility value, a JSON `VoiceInput.Report`; `TapMeter` counts inside the tap block). Three tests, chosen by `TOPO_DEBUG_EAR` (`DebugRun.ear`): `stub` (an ear resident without a model), `loading` (one never resident, so every press is refused with its reason, which needs no audio input and so passes on every host), and a models directory (the real Parakeet, which does run in a simulator on the CPU), in which the lane loops `Tests/Fixtures/purple-elephants.wav` into the microphone and the test asserts Parakeet heard its words. A host with no audio input refuses the press at the input guard, and that test ends in a `missing coverage` skip, never a pass; `scripts/ci-require-tests.sh` allows no skip at all. The first press in each test also answers the permission prompts it raises, against a running total across the class's tests: on a lane that cleared the app's grants first (`xcrun simctl privacy <udid> reset all zone.hexagon.topo`, declared as `TEST_RUNNER_TOPO_UITEST_PRIVACY_RESET=1`) the total has to be exactly one, so a reset that did not happen fails as loudly as a permission Topo should not ask for; elsewhere it is held at no more than one, and every prompt's text is the microphone usage description. The PR check is the input-capable lane: BlackHole as the runner's default input and output with the fixture looping into it from one long-lived feeder that listens to BlackHole itself and restarts on silence, and a lane check before and after the suite that fails by name unless a separate meter hears the fixture (`scripts/ci-audio-lane.sh`), the models from a cache, declared to the runner as `TEST_RUNNER_TOPO_UITEST_AUDIO_INPUT` and `TEST_RUNNER_TOPO_UITEST_EAR_MODELS` (`docs/simulator.md`). The whole voice path on a real account is `SpokenTurnTests` (`Tests/ClientTalk`, the `TopoTalkTests` target in its own `TopoTalk` scheme, never the `Topo` scheme's test action, since it needs a real token, the simulator's iCloud account and a loopback lane, which only buddybox has): `scripts/simulator-run.sh --talk` loops `Tests/Fixtures/capital-of-france.wav` into the microphone through `scripts/ci-audio-lane.sh` (stopped, with the Mac's defaults restored, on every exit; the lane's tools need a one-time microphone consent in buddy's GUI session), reboots the simulator so its audio binds to the coreaudiod that has BlackHole (one booted before the lane restarted coreaudiod has no input), hands the token and both model directories to the test runner as `TEST_RUNNER_TOPO_TALK_SETUP_TOKEN`, `TEST_RUNNER_TOPO_UITEST_EAR_MODELS` and `TEST_RUNNER_TOPO_UITEST_VOICE_MODELS`, and passes only when `scripts/ci-require-tests.sh` finds the test passed. The test holds, from two debug-only accessibility values, that Parakeet heard the question, that the spoken turn with that text is in the log, that a reply naming it among its parents contains "Paris", and that `Speaker` started and finished that reply on Pocket, with the reply's own two measurements made rather than defaulted — seconds from `speak` to its first frame being scheduled, written once and absent when no frame ever was, and the time spent synthesising over the audio that made (the badge's `DebugRun.ChatReport`, carrying `Speaker.Report` and the voice's state, which the test waits on before it presses: Pocket runs in a simulator on the CPU, and the lane gives it the pack in `TEST_RUNNER_TOPO_UITEST_VOICE_MODELS` rather than letting it download one).
- Two things in `project.yml` are load-bearing: `EXCLUDED_ARCHS[sdk=iphonesimulator*]: x86_64` on the iOS target, because FluidAudio's NemoTextProcessing xcframework has an arm64 simulator slice and no x86_64 one; and the iOS target's `info:` block, which writes `Apps/Topo/Info.plist` for the keys that have to be in a file. The rest of that plist is generated from the target's `INFOPLIST_KEY_*` settings, which Xcode merges into it, but `UIBackgroundModes` is not a key Xcode generates: an `INFOPLIST_KEY_UIBackgroundModes` setting reaches the project and no built app, and a background mode the product does not declare is a process iOS suspends. The version keys in that file are `$(MARKETING_VERSION)` and `$(CURRENT_PROJECT_VERSION)`, never literals, because a literal beats the build number `scripts/archive-upload.sh` passes on the command line and every TestFlight upload would carry the same one. `scripts/check-built-plist.sh` reads the modes and the build number off the built app in the PR check, because the settings they are declared by are not proof.
- The transcript is `Apps/Client/TranscriptView.swift`, one view drawn by the phone, the watch and the television. Which side a turn is on and whether it is enclosed is what says who said it: the person's turns sit on the right in a bubble outlined in the theme's primary colour, Topo's on the left as plain text, and the time is under the words on the turn's own side. Primary is the mind's own colour on both ends of the conversation; `Theme.secondary` is reserved for a turn a process puts into the transcript — a reminder firing, a schedule, a limb's sensor — which nothing writes yet, so there is no role for one and no enclosure to draw it in. Holding a turn offers saying it again, or stopping (`Replay`, Topo's turns alone), Copy on any turn, and Edit on one of the person's own, which puts its words back into the row at the end of the transcript and raises the keyboard (`TurnActions.edit`, wired in `ChatView`); the log is append-only, so Edit changes what is said next and never the turn that was said. It is offered only while the row is free to take the words — a row holding a turn on its way is drawing the words being sent — and `NextTurn.edit` refuses them over such a turn whether or not the item is there. Every value the transcript draws with — colour, surface, corner radius, padding, spacing, type — is a field of `Look` (`Apps/Shared/Look.swift`), read from the environment as `@Environment(\.look)`, its defaults chosen per platform and its palette `Theme`; a surface is one of an enum (`glass`, `material`, `flat`) rather than a branch inside a view, and Topo's unenclosed side is a look value of the same type as the bubble (`plain`, set to nothing) rather than a branch either, so the row picks a side and draws no number of its own. The look itself is a document the mind can write: `look.json` in the vault's root, decoded field by field onto the compiled `Look` by `Apps/Shared/LookDocument.swift` and handed to the environment by `TopoApp`, so every screen of the app is drawn by it. `Apps/Client/ChatPreviews.swift` is fixture turns, one `#Preview` per platform and `ChatCanvas` — the chat as one view, which the canvas shows and the render suites photograph — all `#if DEBUG`, so the transcript is reviewable with no account behind it and nothing of it ships. Holding a turn offers what `TurnMenu.items(for:)` says it offers, which is a list of values rather than a block of buttons: a context menu is a gesture no test can press, so which items each role gets is read there and drawn in the row.
- The person's next turn is written at the end of the transcript rather than in the glass: `Draft` and `DraftRow` in the same file, drawn on the phone alone since it is the only screen handed one. `Draft` is the whole of what the row shows — the words and whether the keyboard is up, both bound to the chat; whether the turn is on its way; what sends it; and what takes it back, nil where there is nothing to take back — and its `state` is one of `hidden`, `writing` and `inFlight`, so each of the row's states is a value a test can make. The row is the bubble the turn is about to become: `look.bubble` and `look.transcript.bodyFont`, with a field laid over a `Text` that is not drawn and is what sizes it, since a field asked for its own width takes every point on offer while a `Text` takes what the words need; so the row hugs its words, wraps rather than scrolling inside itself, and holds `look.draft.minimumWidth` when it is empty. - A limb's turn wakes the answering loop by a silent CloudKit push rather than waiting out the five seconds. `TurnPush` (`Apps/Topo/TurnPush.swift`) is a `CKQuerySubscription` on `Turn` creation in the `Topo` zone, content-available only, with the predicate `sequence > 0` (every turn; a match-all would need the record-name index the development schema never builds, and `sequence` is queryable because `TurnLog.read(device:after:)` filters on it), saved once per Apple ID under a fixed id; the chat registers it beside its answering loop and ignores a failure. `TopoAppDelegate` (`Apps/Topo/TopoAppDelegate.swift`) registers for remote notifications and hands a push that is the subscription's to `PushWake.handler`, which the chat installs immediately around `Harness.answering(every:)` and removes when it returns, so a push after sign-out or a takeover reaches nothing. The push carries nothing, so it needs no authentication, and the loop is the backstop for every push Apple drops. The iOS target alone has the `remote-notification` background mode (`Apps/Topo/Info.plist`) and `aps-environment` (`Apps/TopoiOS.entitlements`); the watch and TV keep `Apps/Topo.entitlements`, iCloud only. It runs only while this device holds a login, the condition the harness answers under: a cue reaching a signed-out phone — a foreground after a sign-out, a launch as a viewer — takes away any folder it finds rather than filling one, so a sign-out the app did not live to finish settles at the next cue. It syncs on every foreground (`TopoApp`, where the models are prepared), at the top of every pass of the answering loop before it looks for a turn to answer and again once a reply is in the log, whoever's turn it answered — a limb's, or one typed here (`Harness.onPass`, installed by the chat) — and on a silent push saying a revision was created (`NotePush`, `TurnPush`'s twin under the id `note-created`, routed by `TopoAppDelegate` to `MemoryWake.handler` by the subscription id it carries; the handler follows the login rather than the chat screen, put up and taken down by `TopoApp` as the login comes and goes, so a signed-in phone that never reached the chat still answers a push). The loop is what makes the folder current with no push and no turn, so a dropped push costs latency and not currency. A failed sync is recorded, retried on the next cue, and touches no disk: the mirror refuses to act on a partial read. Nothing in the folder is read or written uncoordinated, the mirror's own `.topo/mirror.json` baseline included, and that baseline is written last and only by a pass that got to the end of itself. Every fact about the folder is read where it is acted on, inside the same coordinated write: what is at a name, whether it is a file or a folder, whether a folder is still empty (`rmdir`, which refuses one that is not), and what text a file holds. All of it goes through a descriptor for the folder the file sits in, opened from the vault root with `O_NOFOLLOW_ANY` so no link anywhere on the way down is followed and nothing is resolved again between the look and the write, and the way down is made one name at a time through that descriptor rather than by a path. So an editor's save landing in that window is found and made a revision of rather than flattened, and a file this pass cannot read is neither written over nor read as a deletion. A path only counts as shown the store's heads when its text reached the disk, since a push names as its parent what this folder was actually given. Cancellation is checked before every mutation, the folder's own making included, which is what makes a sign-out mid-sync safe, and it is carried into the coordination by hand because none of it runs on a cooperative thread: `NSFileCoordinator` blocks until every other accessor lets go, and the threads tasks run on are a handful the process shares, so the wait is spent on a queue of the mirror's own with the actor suspended. The package suites run with `LIBDISPATCH_COOPERATIVE_POOL_STRICT=1`, which pins that pool to one thread, so anything that blocks one hangs there rather than on a runner. Sign-out takes the folder away — the memory is the person's and lives in their iCloud, and a phone that is signed out keeps no copy — and a sync in flight at that moment is cancelled, writes nothing, and the folder goes once it has stopped, so a half-finished pass cannot put a file back. The diagnostics screen's `memory` row says where the home is, when the folder was last in step and what the last sync did, and names the first few files a pass skipped with the reason it skipped each — a count alone is a device run that has to be repeated to learn anything. `look.json` in the root is a file of the vault like any other, and the one the app reads for itself: after each pass that reached the end of itself, from the folder the home names, through the mirror's own coordinated read (`VaultMirror.contents(at:)`) and never by opening the folder — after the sync and not during it, since a second coordinated access of one folder held from inside the first is two accessors from one process. It is decoded field by field (`Apps/Shared/LookDocument.swift`): a field absent, misspelt, of the wrong kind or outside the range its field is read in falls back to the compiled default for that field alone, every other override stands, and the reason is on the diagnostics `look` row along with the file's state — no file, the count of fields it set, or why nothing could be read from it. Colours are hex pairs, light then dark, as `Theme` writes them (`Theme.colour(light:dark:)`); materials are named; numbers are points, degrees or seconds, each in a range named where it is read, and what has to be pressed or read is bounded below as well as above. The environment is set from it on every sync, so a document the mind wrote is worn from the next one with no relaunch; a sign-out takes it away with the folder. The watch and the television draw the same transcript from the same look and have no composer, badge, sheet or row, so the transcript's and the bubble's fields are all of it that reaches them. An empty file is a note with no text in it, not a file that could not be read: `FileHandle.readToEnd` answers nil at the end of a file, which an empty one is from the start, and every note Obsidian has just made is empty. A debug build launched with `TOPO_DEBUG_LOOP_SECONDS` waits that long between passes instead of five seconds, which is how a device test tells a revision that arrived by push from one the loop would have fetched anyway. The home is the bookmark, one keychain item beside the tokens, because a bookmark is a capability to the person's files and not a setting: no bookmark is the local home, one that resolves is iCloud Drive, one that does not is `lost` and stops every pass until the person picks again or comes back to the phone. The picker's grant is the whole of the permission story — no entitlement of ours reaches iCloud Drive or Obsidian's container — and what it hands over is judged against this device's own ubiquity root, `<user>/Library/Mobile Documents` read off `NSHomeDirectory()`, rather than against a path component of that name: a vault one level under `iCloud~md~obsidian/Documents` is the pick Obsidian opens, iCloud Drive's own root is a vault made at `Obsidian/<the mind's name>` under it, and anything else is refused with the reason and the home unchanged. The bookmark kept is to what was picked, so a root pick keeps root access, and the vault folder under it is derived by the same rule at every launch. Every access is started and stopped on that URL and never on a child of it, and it is held for the whole pass. The move (`Apps/Client/VaultMigration.swift` over `VaultTransfer` in TopoCore) is one coordinated write over both folders with one commit point: every file and the `.topo/mirror.json` baseline are copied and read back by digest, the write of the home to the keychain is the commit, and the source is emptied of what was carried only after it — name by name, then the folders left empty, and the folder itself only when it is this app's own, since a folder in the person's iCloud Drive is theirs. What counts as left behind is a file the move carried and could not take away, never a name it skipped on purpose — `.obsidian` was the person's and is not the memory's to account for, still less to remove. A file already in the destination keeps its name and the carried one lands beside it under a conflict copy's name (`ConflictCopy`, the rule `MemoryVault` reads a fork with). An iCloud Drive home has files whose bytes are not on the phone, so each pass asks for what is not downloaded and waits with a bound (`Apps/Client/VaultDownloads.swift`, a regular file whose status is `.notDownloaded` and nothing else: a folder has a downloading status of its own, a file with no status is not a ubiquitous item and asking for one throws, and `.downloaded` is a local copy that is merely out of date); what has not arrived is a file the mirror reports as unreadable and acts on in neither direction. Sign-out drops the bookmark and takes away the folder in this app's container; a vault the person keeps in their own iCloud Drive is theirs and is left where it is. The chat shows one card above the composer offering the move, once, when the vault holds more than a handful and the home is still local; Not now is for good, in defaults.
- **CloudKit is truth, sockets are speed.** State (transcript log, pairing record, primary lease) lives in the private CloudKit database; the push that wakes the primary, direct sockets and the punched tunnel only make live turns fast. With no socket the app still works off the records, just slower.
- The transcript is an append-only log: one record per turn, per-device sequence numbers, never overwrite. The role record (`role/<device>`, `DeviceRole`) is how one device changes another's role, written by the taker in the make-primary control; a device reads its own at launch and on each answering pass. The primary lease is the one mutable record: atomic claim, 10s expiry judged on `mach_continuous_time` (`PrimaryLease.continuousUptime`) as well as the wall clock — not `CLOCK_MONOTONIC`, which on Darwin is time-daemon-disciplined and can follow a backward system-time step, the case the fence exists for — 5s heartbeat the holder runs itself, probe-driven handover, a displaced holder yields rather than reclaims, and only the hub takes the lease from a live holder. A turn written as primary rides in one atomic batch with a heartbeat of the lease (`TurnWriter.append(…, renewing:)`), so a displaced device writes nothing; the phone's reply uses it and the hub's turns will.
- Core logic ships as Swift packages whose tests run against an in-memory database behind the package's own CloudKit protocol; no test needs a signed-in device. `Packages/TopoCore` is the log, the lease, the device directory and the memory (`MemoryStore`, one create-only record per revision; `MemoryVault`, which reads those revisions as files, with the newer head of a forked path the file and every other head a conflict copy under Obsidian Sync's name; and `VaultMirror`, the actor that keeps a directory on disk in step with them both ways): `RecordDatabase` is the protocol over the CloudKit calls used (compare-and-set save, fetch, query, and the whole of a type from the zone's change feed, which is how the log and the device directory are read: a match-all query needs a queryable index on the record name that the development schema never builds), `CloudKitRecordDatabase` is the adapter, and `TopoCoreTesting` holds the in-memory database with CloudKit's conflict semantics. A container nothing has written to answers two more ways, both absorbed by the adapter and both invisible until a fresh account takes its first turn: a query on a record type the development schema has never seen fails `unknownItem` rather than returning nothing (answered `[]`), and an empty string list on a first save makes the server refuse the whole atomic batch with "Syntax error in request" (left off the wire, since a list with no elements has no type the schema can be grown from). `Packages/TopoLink` is the socket layer: the lease probe over TCP (one line each way), the listener that answers it and advertises the device as `_topo._tcp`, and the browse that says who is on the LAN; its tests run on loopback. `swift test` from a package directory runs its suite. `TopoTests` drives the phone's `Harness` itself over the in-memory log, with the Messages API behind a scripted `Transport` (the unsettled line on disk and its relaunch, a failed model call, not-primary and displaced turns, the role-record handover, the answering loop). No automated suite reaches the CloudKit service: `CloudKitMappingTests` covers the adapter's record and error mapping offline, so the account, the schema, partial failures and the zone change feed are exercised only by Womble's manual self-test (`CloudKitSelfTest`) on a signed-in device.

## Working here

The process — who plans, who builds, who reviews, and in what order — is `docs/process.md`. The short form:

- Every change lands as a PR on a `buddy/<topic>` branch from its own worktree, opened as a draft. The description is the contract: what was done, and a **Proof** section as a checklist of what was verified. A test only a physical device can show is an unchecked `- [ ] device: …` box; auto-merge waits until it is ticked.
- Never force push. One concern per PR; a finding on an open PR is fixed on that branch, never in a second PR.
- Prefer what exists: stdlib, then a platform framework, then an already-linked dependency, before new code or a new dependency. Nothing GPL from others ships in a bundle (App Store distribution); every borrowed piece is attributed in `THIRD-PARTY`.
- Docs describe the present state. When you change behaviour, change the doc to match; do not narrate the change.
- An engineer reports to the Topo PM at every task boundary (PR opened, blocked, finished) with `SendMessage`: what, where (branch, commit, PR), what it waits on. It never merges, never reads or answers a review, and never polls with background shells — the PM does all three.

## Where the risk lives

The CI reviewer reads this section before the diff. Keep it current: it names where a serious defect is likely *now*, and it moves as the work does.

- **Audio lifecycle.** The audio session, the engines, the tap, the player and time-pitch nodes and the synthesiser are handles into mediaserverd; a media services reset, an interruption, or a route change invalidates them at once. The rule is that no handle is created, read, started or spoken to until `AudioSession.ensureActive()` has returned since the last reset, that a failure is a refusal, and that the format a tap is installed with is the very object the guard judged. Behind the lock there is a second rule: while a hold stands the session is not reconfigured, because iOS refuses a non-mixable session activated or reconfigured from the background and the refusal leaves it invalid for every path after. A serious defect here is a new audio path that skips `ensureActive`, reads an input format twice, rebuilds anything inside the reset handler, reconfigures the session while a hold stands, or catches a refusal and carries on: each is an uncatchable `NSException`, a crash rather than an error, and none shows in a simulator. The background hold adds three more: one that outlives the reply it was taken for keeps a pocketed phone awake until its battery is the symptom; one dropped at an event that is not the reply's end — the lock screen's own `.began` — suspends the process with the reply unheard, which is the same defect the other way round; and a rebuild on a configuration change or an interruption's end that runs before the session is active again is that same crash on a path nothing in the foreground exercises.
- **The look as a document.** `look.json` lives in the vault's root, which Files, an editor and the mirror all share, so it is read through `VaultMirror.contents(at:)` and never by an uncoordinated open of the folder — a read taken outside the coordination is half a file whenever somebody is halfway through saving one, and a half-read document is a screen drawn from a value nobody wrote. It is read after a sync and not inside one, and from the folder `Memory.home` names rather than from the app's own. Every value it carries is checked where it is read: a serious defect is a value reaching a view unchecked — a number that is not finite, one outside the range its field is read in, a name that is not one of an enum's cases, a length that puts the microphone or the badge out of reach — or a field that is refused taking any other field down with it, since a document is meant to cost what it got wrong and no more.
- **A literal in a view.** Every colour, surface, radius, padding, size and font a view draws with belongs in `Look`, reached from the environment. A number written inline is a value the mind cannot reach, which is the whole point of the type: the interface is meant to be adjustable from the inside. The transcript, the badge, the jewel both it and the microphone are cut from, and the composer are drawn from the look; the rest of the chat is not yet, so the defect is a view being changed or added — the settings sheet's own rows, the offer card — that hard-codes what it draws instead of naming a field, and a difference between two sides of a view written as a branch rather than as two values. A mark drawn on a cabochon rather than pressed into it through `Pressed`, or a cast written as a second picture in the asset catalogue rather than as a colour over the one stone, is the same defect: what the cut is and what colour the stone takes are meant to be values the mind can reach. The pane's presence is the same rule one step out: the surface, its edge and its glow are drawn at a value the composer is handed, so a view that draws the pane without asking it — or a second mechanism for clearing it, a transcript background run under it by hand, a scroll position read inside a view — is that defect rather than a fix.
- **The press path.** Every press is a session with a generation; a late result, a second release, or a press while another surface holds the microphone must reach nothing. Two gates on one input answer twice. The view the gesture is attached to is also the element the two UI suites find, by the three labels and by reporting as an image, so a change to what hosts that gesture is a change to whether the microphone can be pressed by a test at all — and a suite that cannot find the button fails as loudly as one that finds a broken one, which is the only reason that is safe.
- **The outbox and the row.** One nonce per turn, never two for the same words, never a turn lost. The words go on the line under one nonce before any attempt, the row holds them until that nonce is in the log, and the outbox's retry sends the same words under the same nonce — which is what the nonce marker deduplicates. So a serious defect is anything that makes a second nonce for words already on the line: a withdrawal that acts without asking the log, one taken while an attempt may be landing, or a resend that leaves the first entry behind. The row is the person's only sight of all this, so anything that makes it draw something other than the turn it is holding is the same class of defect: a landed turn's words taken into a row over a turn on its way sends one turn and shows another, and a relaunch that comes back to an empty row over an entry still on the line hides a turn that never landed and takes its way back with it. The other way round is as bad: a row that clears while the words are still owed loses them from view with the person unable to see what is still going, and one that stays in flight for a turn already in the log is a person locked out of their own words with no way back. A read that failed is not an answer to either question.
- **The transcript log** is append-only: one record per turn, per-device sequence numbers, create-only saves with a compare-and-set on the change tag. Anything that can overwrite, skip or duplicate a turn.
- **The primary lease**: two devices believing they are primary past the lease duration, a heartbeat that keeps a lost lease alive, a claim that is not atomic.
- **CloudKit is truth, sockets are speed**: a path that only works when a socket is up.
- **The migration.** Moving the folder between its two homes is the one operation that has the person's memory in two places at once. A serious defect is a home written before every file has been copied and verified, a source removed before the home has moved, a bookmark used without starting access on the URL the grant is on, a read of a file iCloud Drive has evicted that returns empty and is taken for the file, a baseline left behind so every file in the new folder re-parents, or a folder the person picked taken away rather than emptied.
- **The mirror.** The folder is shared with Files, with whatever editor has it open, and with the store, so `VaultMirror` is where a person's words are lost quietly. A serious defect is a sync that writes from a partial read, a path outside the vault or reached through a link (the scan and the re-read before an overwrite both refuse one, and both have to), a revision continuing from the store's heads instead of the heads that folder last saw — which swallows a concurrent edit — or a download landing on top of a file saved since the scan, which is why the comparison and the write are one coordinated write and never two. An uncoordinated read or write of that folder is the same class: half a file read as the whole of it becomes a revision saying so. So is a mirror that runs without a login: a signed-out phone that keeps or rebuilds the folder is the memory left on a device its owner signed out of.
- **The test doubles**: `InMemoryRecordDatabase` reproducing weaker semantics than CloudKit's, so the suite passes on behaviour the real store rejects. A test that cannot fail.
- **Licensing**: GPL code from others reaching a bundle; a borrowed piece with no entry in `THIRD-PARTY`.
